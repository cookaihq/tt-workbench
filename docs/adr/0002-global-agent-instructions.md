# 在 tannt 维护跨项目使用的全局 Agent 指令

2026-10-28 修订：用户纠正迁仓范围，个人全局源继续由 tannt 知识库维护，工作台公开仓库仅维护工具。详见 [ADR 0005](0005-independent-workbench-repository.md)。本文中的 `docs/global-agent-instructions/` 相对于该知识库；其中的说明与场景正文不随工作台软件分发。本机加载、跨项目范围与具体授权边界保持。

本人已确认：tannt 作为全局 Agent 主指令及其引用的全局场景指令的正式维护位置，Agent 实际读取这里的文件。各项目自己的场景指令由各项目维护，不集中到 tannt。

## 决定与边界

1. 全局正文放在 `docs/global-agent-instructions/`，主文件为 `AGENTS.md`，按需读取的场景正文放在 `scenarios-agent-instructions/`。Agent 的用户级主入口读取主文件，主文件明确各场景的触发操作及读取路径。
2. Codex 的 `~/.codex/AGENTS.md` 与 Claude Code 的 `~/.claude/CLAUDE.md` 分别直接链接到本机库内的正式主文件；`~/.agents/scenarios-agent-instructions` 直接链接到正式场景目录。两个工具共用一份源，场景引用使用固定的用户目录路径；不再通过用户目录下的 `global-instructions` 中间层。
3. tannt 根目录 `AGENTS.md` 和 `docs/agents/` 继续维护 tannt 的项目指令；其他项目的指令仍在其他项目。这与 ADR 0001 对 tannt 业务规则的集中维护范围分别成立。
4. 2026-10-22 首次源目录迁移保留了当时的全局规则正文，仅更新来源说明并增加全局指令维护场景；该历史操作不规定其他设备已有规则的接入策略。不迁移 Skill、工具配置、执行权限或凭证。
5. 规则源可以随库保存；用户级链接由每台设备建立并验证。移动源库、更换设备或增加其他 Agent 宿主时，分别检查加载链，不以本机文件存在证明其他环境已经使用。
6. 其他设备已有全局指令时，先逐条评估，提出符合主指令／按需场景／项目规则边界的具体迁移方案，经本人允许后应用；共享正式源仍然唯一。共享正文修改的跨设备影响、旧条款退出及未决冲突须在方案中明确，操作流程统一见所选规则源的 `README.md`。
7. 2026-10-25 本人确认：共享规则正文在一处获准修改后，随 FNS 到达供各设备的新会话或后续按需读取使用，无需逐台再次批准正文。保留直连正式源的简易结构；安装、链接、登录及本机生成配置等主动调整仍须对应设备的具体授权。已打开会话是否刷新与后续读取分别核验。

## 验收

检查两个工具的入口解析到同一源文件；从 tannt 之外核对主文件加载，以及场景路径不依赖当前项目。验收区分实际宿主加载与文件系统检查；未完成的宿主或设备验收明确记录。

维护方法见所选规则源的 `README.md`，本次实施和证据见[功能记录](../../.scratch/global-agent-instructions/spec.md)。

用户确认取消 `~/.agents/global-instructions` 中间层，将场景源目录和用户侧入口命名为 `scenarios-agent-instructions`。本轮先实施路径和加载入口调整；面向 macOS、Windows 的本库项目级安装与修复 Skill 仅登记需求，随后另行实施。原迁移与精简重建的验收保留为历史证据，当前路径以本文决定和全局指令说明为准。
