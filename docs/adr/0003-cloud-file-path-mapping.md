# 网盘路径保留库内目录层级

本次网盘托管设计已选择 `<指定父目录>/tannt/<库内相对路径>`，并在原文件位置保存同名 YAML 替代记录。此前讨论过将文件平铺到同一网盘目录，随后改为保留库内层级；这一选择让不同本地目录中的同名文件仍有各自的位置。

本地移动或改名时，网盘路径也随之调整。这意味着目录整理需要协调远端文件、替代记录、存在的本地原文件及引用；部分成功必须保留恢复依据，不能将本地文件移动视为全部完成。具体规则维护在[网盘托管规则](../rules/cloud-files.md)，本 ADR 只记录路径方案的选择和代价。

决定来源为本次会话中用户对保留层级方案及移动联动推荐的确认。取用入口及核验策略的后续复核见[功能规格](../../.scratch/cloud-managed-files/spec.md)，不由本 ADR 预先决定。

## 2026-10-25 早期分发方案（已被下节取代）

本人确认采用默认上传账号加按次指定，各账号分别拥有父目录；已有文件仍由替代记录标识原账号和远端位置，不随默认值切换或父目录修改而改变归属。

非敏感目标唯一维护于库根 `.env`，直接通过 FNS 同步；凭据各设备单独准备。本人在并发方案冲突后明确选择 A，此决定取代曾由另一会话提出并记录的共享 JSON、各设备生成 `.env` 方案。保留一个配置源，同时承担 FNS 2.4.0 独立文件扫描支持的逐设备安装和升级复核成本；具体字段与维护流程只维护在[网盘托管规则](../rules/cloud-files.md)。历史版本与验证保留，不能作为当前方案的验收。

## 2026-10-25 将网盘目标迁入 config

用户确认将根目录 `.env` 中的配置迁到 `config/`，并要求具体用途的文件名。唯一目标源改为 `config/cloud-storage-targets.json`；现有默认账号及各账号父目录原样迁移，脚本直接读取 JSON，不生成第二份环境文件。

该普通文件通过 FNS 原生的笔记和附件同步传输，退出独立隐藏文件的单文件补丁方案，避免逐设备维护插件改动。登录秘密仍留在库外本机档案。具体字段与维护流程继续以[网盘托管规则](../rules/cloud-files.md)为准；本机迁移与另一设备接收分别验证。

## 2026-10-25 为自有配置增加注释

用户希望项目中的 JSON 配置可写注释。网盘目标后续改为 `config/cloud-storage-targets.jsonc`，与 Skill 清单共用 JSONC 解析入口，原账号、目录及普通文件同步方式不变。上节 JSON 路径保留迁移历史；当前格式约束见[写入与变更](../rules/writing-and-changes.md#项目配置格式)，实施与本机验证见[本轮记录](../../.scratch/jsonc-config/spec.md)。
