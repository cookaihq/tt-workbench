# 将工作台拆为独立维护、独立安装的 Obsidian 插件

工作台源码迁至 `D:\zhao\tt-workbench`，该目录作为工作台的独立仓库。工作台继续采用 Obsidian 插件形态，将源码仓库、分发的安装包和使用插件的目标知识库分开；本轮迁移包含独立打包、测试和指定知识库安装能力。GitHub 远端与线上发布由后续步骤配置。

工作台可以安装到任意名称、任意位置的 Obsidian 库，首版沿用现有五目录和项目／任务格式。工作台与 Agent 共用的文件读写、FNS 等程序一并迁入新仓统一维护，tannt 使用安装后的工具；已有 Skill 在 Obsidian 关闭时仍须可用。新仓从当前代码开始新的 Git 历史，过去的修改记录留在 tannt 仓库回查。

原来将源码放在 tannt 内，安装器、独立命令和软件更新都可以利用知识库所在路径及其 Git 仓库，但也把软件安装绑定到了特定知识库。用户希望工作台能单独安装，因此选择独立仓库，并承担明确共享程序归属、工具安装入口、运行记录位置与软件更新来源的维护成本。

用户另明确当前项目的 Skill 源码也归工作台仓库，并要求在工作台 UI 中提供这些 Skill 的安装入口。Skill 源码及维持现有使用所必需的安装脚本、发现入口调整纳入迁仓清单；新增 UI 的需求梳理、原型制作和用户确认安排在代码迁至新目录之后，记录于[后续需求](../../.scratch/workbench-skill-installation/spec.md)。当前迁仓不提前设计或实现该 UI。

本决定延续 [ADR 0001](0001-shared-rules-and-scenario-skills.md) 的规则优先原则及 Agent 无需 Obsidian 运行即可操作知识库的要求。Skill 区分软件资源与目标库的适用约定；软件共同规则与模板随迁，个人全局指令、知识库业务文件与运行记录归实例。

用户在迁仓后修正个人规则归属：全局主指令与五个场景的正式源仍由 `D:/zhao/tannt_vault/tannt/docs/global-agent-instructions/` 管理，已从工作台软件仓库迁回。此前将这些个人正文随软件分发的方案撤销；ADR 0002 的个人正式源归属继续有效。工作台仅提供浏览、整理 Skill 与显式来源的接入工具，打包和安装不读取或复制个人正文。共同软件规则、可复用模板与开发材料继续由本仓维护。

插件安装只放入插件及内置资源；初始化、配置、Skill 注册和全局规则接入在安装后的页面中显式操作。现有入口因迁仓所需的接续作为单独维护步骤，不变成每次安装的隐式行为。新仓以后公开，软件更新由 GitHub 发布版本提示，用户点击后下载并安装；真实地址及首次发布后续配置。

迁仓实施证据见[实施记录](../../.scratch/workbench-repository-extraction/spec.md)，个人正文归属以本决定上述修订为准。迁仓后用户已确认 Skill 安装采用 A「列表＋详情」，正式页面实施与验收见[功能记录](../../.scratch/workbench-skill-installation/spec.md)。
