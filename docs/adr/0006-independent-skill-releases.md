# Skill 独立版本，使用完整清单的批次发布

Skill 的行为版本独立于工作台，源码仍归本仓，由工作台统一管理正式安装副本。一次批次 Release 可发布一个或多个 Skill，完整清单继承未变化项的固定包来源；版本决定是否更新，兼容要求决定可安装性，内容校验决定包一致性。标签不含单个 Skill 名称。

2026-10-31 用户确认：工作台和 Skill 同次更新时共用工作台 Tag 与一个 Release，使用户能从一次发布取得配套交付；仅 Skill 更新才使用独立批次 Tag，并避免占用工作台 Latest。共用发布归属不改变 Skill 的独立行为版本。两种 Tag 共用清单序号与上一清单摘要，避免用不可比较的标签格式或发布时间判断清单先后。发布 Agent 的选择规则见 [发布范围与 Tag 选择](../agents/git-access-commit-and-release.md#发布范围与-tag-选择)。

每项 Skill 携带其版本所需的工具与文档，安装后工作台升级核验并保留该独立包。相比依赖工作台实时共享资源，这会重复分发部分文件，但能避免工作台升级隐式改变 Skill 行为，且继续支持 Agent 脱离 Obsidian 使用。稳定发现入口继续指向受管理安装目录，两个宿主共用磁盘版本，已有会话是否重新加载另行验证。

本决定细化 ADR 0005 的安装管理职责：插件安装仍不隐式注册 Skill、改变用户配置或导入规则；Skill 更新成为明确的正式分发操作。发布与安装契约见 [Skill 发布说明](../workbench/skill-releases.md)。
