## 已有依据与边界

## Q41 已确认：项目之外的内容目录

在当前库中使用以下位置。它们承担不同的记录职责，不要求本人在每次输入时先选分类，也不新增 Obsidian 仓库。

| 已确认位置 | 内容如何组织 | 具体例子 |
| --- | --- | --- |
| `资料/` | 围绕一门课程、一份外部资料或一个已参加的社群保存上下文，包含来源内容及随来源产生的学习记录 | 课程介绍、目录、课时摘要、学习思考及源文件位置；准备反复查阅的文章／视频资料；AI 破局俱乐部值得保留的讨论及出处 |
| `知识/` | 围绕一个问题、观点、方法或长期专题持续积累，按需引用多个来源和实践记录；可以包含未成熟的判断和待验证问题 | 多 Agent 会话切换的认识、企业培训方法、个人成长或心理学专题 |
| `领域/内容创作/<创作方向>/选题/` | 保存本人认为值得继续考虑、但尚未决定启动制作的创作选题 | 将会话切换的研究写成一篇文章的候选选题，关联研究笔记及来源 |

按 Q49 的补充，选题与 Project 在所属创作方向下并列，使用 `领域/内容创作/<创作方向>/选题/` 和同级 `项目/`。本人决定开始制作后，再在该方向创建内容 Project 并关联原选题；不把“出现了一个选题”当作已经启动项目。

## 一次输入如何进入这些位置

1. 一条没有确定归属的阅读摘录先进入 Inbox，保存原输入。
2. 本人整理时可以决定按原样保留，直接标为已整理，流程到此结束。
3. 如果需要把它纳入持续维护的来源资料，可在 `资料/` 的相应资料说明中链接原记录，不强制复制一份正文。
4. 如果从多份资料形成了需要反复使用或继续修正的认识，按需在 `知识/` 建立独立笔记，并链接原始资料或研究 Task。
5. 如果形成了候选选题并明确所属创作方向，在 `领域/内容创作/<创作方向>/选题/` 记录创作想法及关联材料；只有明确决定投入制作，才建立同方向的内容 Project／Task。尚未明确归属的输入仍可先留在 Inbox。

上述步骤不是必须依次经过的流程。已经知道属于某门课程的内容直接保存在课程资料里；已经明确属于企业、Project 或 Task 的材料继续就地保存，通过链接供其他记录引用。

## 需要保持的区别

- `资料/` 不接管所有企业和项目文件，只组织尚无这些具体归属的来源资料。
- 课程摘要及学习笔记可以一直随课保留，不要求全部拆进 `知识/`。
- 长期专题不是必须产出文章的选题，个人兴趣也不必进入 `领域/内容创作/<创作方向>/选题/`。
- 已参加社群的讨论可以作为来源资料；本人经营社群的活动准备、任务与成果仍属于社群运营领域。
- 视频 Task 的完整转写和实际选用截图继续随 Task 保存；其他区域通过链接引用。大文件仍按库外存放规则处理。
- 源文件位置可以列出多个设备或网盘入口，继续视为同一套内容，不增加版本或完整度管理。

## 选择依据

围绕来源查找时可以进入 `资料/`；围绕问题和认识查找时可以进入 `知识/`；准备创作时查看 `领域/内容创作/<创作方向>/选题/`。同一份学习积累可以支持多个作品和培训项目，无须重复保存，也不必先决定它最终用于哪个项目。

与把资料和知识分别放入各领域相比，采用这些位置可以让一份 AI 课程或一套个人方法被内容、培训和社群工作共同引用，无须先选一个主要使用领域。已明确属于某领域、企业、Project 或 Task 的资料继续按既有归属保存。

Q41—Q44 确定位置、职责与基本组织；下文已按 Q48—Q51 更新为本人自定知识分类、创作方向分组、培训内容复用及功能目录约定。Q54 已确定第一版通过目录浏览、搜索和正文预览访问业务笔记，HTML 原型已加入示例；通用模板与真实读写接口仍需设计，专用管理页面按需增加。课程的具体模板和整理流程按实际需要再决定。不据此自动创建业务目录或迁移既有文件。

### Q42 已确认：资料按来源类型组织

按本人已有使用场景，采用：

```text
资料/
├── 课程/
│   └── <课程名>/
├── 文章与视频/
└── 社群/
    └── <已参加社群名>/
```

- 一门课程使用一个目录，保留介绍、目录、随课笔记和源文件位置记录；延续此前“先随课保存，需要复用时再提炼”的约定。课程按需整理，具体文件与课时笔记结构、AI 处理流程等实际需要时再决定。
- 文章与视频用于保存需要持续查阅的来源材料。一份材料可以先用一份 Markdown 保存说明和链接；仅保留在 Inbox 中的输入不要求另建一份资料副本。
- 已参加的社群按具体社群建立目录，集中回查其讨论、问题、案例与出处。本人经营社群的活动与项目继续放在社群运营领域。
- 各类内容只在实际使用时创建目录；遇到书籍、论文等新来源时再扩展，不预先创建一批空分类。
- 大文件继续保存在库外，来源位置按已确认规则记录。

同一门课程或一份资料可能覆盖多个主题，因此已选择按来源类型组织，再通过知识笔记和专题链接跨来源使用。

### Q43、Q48 已确认：知识按本人偏好分类，专题通过链接组织

采用：

```text
知识/
├── 笔记/
│   └── <自定分类>/
│       └── <知识笔记名>.md
└── 专题/
    └── <专题名>.md
```

`知识/笔记/<自定分类>/` 保存围绕具体问题、观点、方法或案例的独立笔记，可以包含尚未成熟的判断、疑问和修订记录。分类依据与名称由本人按自己的偏好决定，不要求严格按学科、领域或创作方向划分，不将 AI、哲学等示例变成固定分类清单。每篇笔记选择一个主要存放位置。

`知识/专题/` 中每个专题用一份索引笔记说明关注范围、当前认识和待研究问题，并跨分类链接相关知识笔记、来源及研究任务。

同一份知识笔记可以被多个专题引用，不需要搬进某个专题文件夹或复制。相关笔记较少时，直接写独立笔记即可，不要求先建专题；专题的作用是在实际需要时组织已有积累。

本人选择目录中的知识分类用于按个人偏好浏览，专题索引用于关联已有内容。同一笔记可涉及多个主题，其主题关系不要求由一个分类文件夹全部表达；这不会要求日常输入时先完成分类。

### Q44、Q49 已确认：按创作方向组织，候选选题先用一份 Markdown

采用：

```text
领域/内容创作/
├── 账号/<具体账号>.md
└── <创作方向>/
    ├── 方向说明.md
    ├── 选题/<候选选题>.md
    └── 项目/<已决定启动的内容项目>/
```

一条候选选题先使用一份笔记，按需记录想表达什么、面向谁、已有想法和关联资料；这些不是随手记录时的必填表单。不要求每条选题预先创建文件夹，也不要求先补齐完整创作方案。

本人决定开始制作后，在同一创作方向下创建内容 Project 并关联原选题。一条选题及其项目只归属一个方向，发布范围保持在该方向内。一个项目可包含公众号文章、小红书图文、视频等实际需要的制作结果；研究、稿件与任务进展在 Project／Task 中维护，按需使用 `稿件/`、`发布记录.md` 和 `任务/`。选题原记录保留用于回查，具体状态字段和筛选方式仍需设计，不另设与项目进度重复维护的选题进度。

`方向说明.md` 记录定位、受众和关联账号；账号资料集中在 `领域/内容创作/账号/`。稿件和发布记录关联具体账号，同一视频发布到多个账号时可共用脚本、分别记录发布情况。一个账号能否服务多个方向尚未确定，不预设一对一限制。不同方向可引用同一份资料或知识，需要制作时分别建立各自的选题与项目。

候选阶段以想法和链接为主，已选择先用单文件。只有本人另行提出需要时再讨论其他组织方式；这不改变 Task 固定使用文件夹的约定。

```text

├── 培训内容/<培训内容名称>/
```

## Q52 已确认：Project 状态独立维护

Project 与 Task 使用“待开始、进行中、暂停、已完成、已取消”五种状态，但分别维护。Project 状态保存在 `项目说明.md` 的 YAML 属性中，Task 状态、文字进度和下一步保存在 `任务说明.md` 的 YAML 属性中。本人、工作台与明确获授权的 Agent 读写同一份说明笔记，不另建可编辑 JSON 保存另一份状态。
