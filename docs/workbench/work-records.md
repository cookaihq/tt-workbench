# 工作台项目与任务实现

目录、说明字段、状态和归属的正文见 [项目与任务规则](../rules/projects-and-tasks.md)。

`work-items.js` 的表单创建和状态更新使用 `lib/vault/work.js` 中的路径、名称与状态定义。新项目集中于 `1.项目/<项目名>/`，每个任务位于所属项目的 `任务/<任务名>/`；领域、企业和创作方向通过可选关联表达。名称输入拒绝路径字符、点前缀、保留目录名或超过 80 个字。

状态与进度更新调用独立 `note-editor.js` 文件能力，读回后刷新展示。Project 与 Task 不自动联动。

源码 `0.17.0` 将活跃、暂停、已结束未存档、已存档工作分开筛选；`test_fixture` 验收样例默认隐藏、可显式显示。项目、任务和普通笔记可使用局部用途表单维护 `output_uses`，格式与限制见[文件操作说明](../agents/vault-file-operations.md#可选的局部用途记录)；它不是统一成果模型，正文用途记录仍然有效。

归档和恢复是独立于状态更新的整包操作；已归档项目与内部任务保留原状态、来源及恢复位置，任务不单独脱离项目归档。Inbox 按实际目标可分流到项目、任务、领域或资源，不能只隐藏记录。文件入口、工具支持边界及恢复方式见[文件操作说明](../agents/vault-file-operations.md)；本轮代码、安装与实际入口验证以[实施记录](../../.scratch/information-architecture-workflow/spec.md)为准。

Inbox 的“新建任务并迁入资料”先创建任务，再由 `work-links.js` 调用共用 `TaskTransfer`；“迁入已有任务”直接调用同一迁移操作。文件核验成功后打开任务，任务说明链接迁入的来源笔记，“相关笔记”列出任务目录内的 Markdown。未保存的 Inbox 补充会阻止迁移，需先保存或放弃。

任务创建成功而迁移失败时，表单保留已建任务路径，再次提交继续同一任务。已经开始的迁移可从本机恢复记录继续；关闭表单后可重新打开尚存的源记录，选择原任务迁入。源记录已经移走但清理未完成时，按错误中给出的恢复路径使用[文件命令](../agents/vault-file-operations.md#从收件箱迁入任务)继续。

共享资料的“仅添加引用”仍由 `work-links.js` 更新来源的 `related_work`，任务页面据此回查来源；原位置与整理状态保持不变。该操作与迁移使用不同按钮。

此前任务资料迁移的实际表单、重试与重载证据见[任务资料集中保存](../../.scratch/task-materials-together/spec.md)，只证明当时范围。五目录与扩展分流、归档须依据本轮入口验证；独立的项目与任务创建 Skill 仍属于后续场景，文件命令存在不等于新的创建 Skill 已完成。
