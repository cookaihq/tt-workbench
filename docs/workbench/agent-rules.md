# Agent 规则页面

工作台左侧的 **系统** 分组下选择 **Agent 规则**，或在 Obsidian 命令面板执行 **tannt 工作台：打开 Agent 规则**。页面采用已确认的 A「状态总览」布局，上方显示本机入口状态，下方只读浏览规则并按需显示 Skill 提示词。

`0.20.1` 恢复页面在工作台中的导航、命令和样式接入，与 FNS 配置同步并列于「系统」分组；独立窗口保留当前规则页及所选 Agent。提示词按下述两种接入情况分别生成。

## 浏览与检查

- 先输入包含 `AGENTS.md` 与 `scenarios-agent-instructions/` 的正式规则目录绝对路径，点击「读取并选择」。选择只保存本插件的来源设置，不修改规则或宿主入口；未选择时不回落到软件目录或当前库。
- 可切换 Codex、Claude Code；显示当前用户的主规则入口、共用场景入口、实际链接目标和所选正式源。
- 按工作台进程的 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 解析自定义绝对目录，未设置时使用用户默认目录。其他会话单独设置的目录无法从工作台推断；相对目录显示无法判断。
- 只有入口为直接指向所选规则正式源的符号链接，才计为已接入。普通文件、普通目录、其他目标、中间链接、断链、缺失和读取错误分别显示。
- Codex 的非空 `AGENTS.override.md` 单独显示，并可只读浏览。主规则、场景入口都正常且没有已发现的覆盖／读取问题时显示已接入，并隐藏接入提示词。
- 正文来自本项目正式主规则和场景文件；本机入口尚未接入时，可另行浏览它的原文。正文与文件来源分别标明，不展示文件差异。
- 点击 **重新检查** 才重新读取文件系统事实；浏览正文、切换页面或复制提示词不代表执行了 Skill，也不代表任何现有 Agent 会话已加载规则。重新进入页面同样会更新状态。

正式源与入口布局依据所选规则目录中的 `README.md`。个人正文由用户选择的知识库或规则仓库维护，工作台软件包不包含个人正文。页面只读浏览，不修改正文或宿主入口。

## Skill 提示词

未完整接入或无法判断时，页面直接显示可复制的 `tannt-organize-agent-rules` 调用提示词，包含当前项目、所选 Agent、实际入口和检查结果。在以当前项目为工作目录的 Agent 会话中使用，按两种情况生成任务：

- **主文件未接入**：梳理已有规则及歧义，提出主规则、场景规则和入口的整理方案，确认后接入。
- **主文件已接入、场景入口未接入**：保留已正确接入的主文件，核查场景入口及必要旧内容，确认后补齐或修复场景目录链接，并验证主规则中的按需读取路径。

主文件链接和场景目录链接相互独立，因此第二种状态可能出现。页面只根据文件事实选择提示词；内容判断与操作确认由 Skill 在 Agent 会话中完成。入口无法判断时先请求核查；两项链接已正确但存在覆盖或读取问题时，提示核查相应问题。

独立 Skill 已纳入[活动清单与项目发现](agent-skill-setup.md)，流程及各环境验收见[实施记录](../../local-evidence/.scratch/agent-rules-workflow/verification/skill-implementation.md)。页面会检查所选 Agent 的项目发现入口是否可读并提示缺项，不把按钮或复制成功称为 Skill 可用。Skill 在会话中重新核查页面观察，按授权完成整理与接入；页面不读取过程记录，不保存分析或审批状态。即使发现文件，宿主是否实际发现 Skill 仍需在会话核验。

## 读取范围与验证

`apps/workbench/agent-rules.js` 是独立只读模块，不扩大业务笔记读取与编辑范围。只读取显式所选目录下的主文件与场景文件、固定宿主入口及已知环境变量；源路径与场景内部链接不递归读取，单文件上限 1 MiB，场景浏览最多 6 层、128 份文件。超限或读取失败直接显示原因。新选择存为插件设置 `rulesSource`（规则目录）；已有显式 `rulesRoot`（所属仓库根）兼容解析其 `docs/global-agent-instructions/`，新选择优先。

正文按文本显示标题和段落，链接、HTML、复选框、代码块及嵌入不执行，不加载外部资源。页面没有写入 API。实现与实机验收见[本轮记录](../../local-evidence/.scratch/agent-rules-workflow/verification/implementation.md)。
