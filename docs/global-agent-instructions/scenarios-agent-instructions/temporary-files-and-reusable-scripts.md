# 临时文件与复用脚本的存放

适用条件：准备创建临时文件（含一次性脚本）、新增复用脚本，或迁移这两类文件。直接写入和通过命令生成这些文件都适用，须在操作前读取本场景。

先核对当前项目的文件存放规则；项目已有专门约定时遵守该约定，否则按以下默认位置执行。

## 按用途选择位置

- 临时文件：仅供本次执行、完成后无需保留的草稿、中间数据、输出缓存和一次性脚本，放在 `tmp/<业务>/`。
- 复用脚本：需要重复使用的部署、安装、验证和维护脚本，放在 `scripts/<业务>/`，作为正式项目文件维护并随项目纳入版本管理。
- 正式文档、代码、测试和需要长期保留的记录，按项目规则放在正式位置；持久化运行数据按项目配置或专门规则确定位置，不因执行过程中产生就归为临时文件。
- 按实际用途判断，不能仅凭 `.scratch/`、`draft/`、`test/` 等目录名认定文件是临时材料。

在项目或 worktree 中操作时，上述路径相对于该项目或 worktree 根目录；没有所属项目时，临时文件相对于当前任务工作目录。业务子目录名称直接说明用途，不把文件散放在 `tmp/` 或 `scripts/` 根目录。同一业务的多次执行需要隔离时，在业务子目录内继续建立执行子目录。

## 临时文件

- 使用者是用户还是 Agent，不改变临时文件的存放规则。
- 不将 Agent 创建的临时文件放入 `/tmp`、`/var/folders/.../T/` 或宿主会话临时目录。调用 `tempfile.mkdtemp()`、`tempfile.TemporaryDirectory()`、`mktemp` 等时，显式指定本次任务的临时目录，不使用系统默认目录。
- 所需业务子目录不存在时可以直接创建，无需逐项确认名称。
- 当前项目使用 Git 时，写入前用 `git check-ignore -v tmp/<业务>/` 核对实际目标目录的忽略规则；未忽略时告知用户并确认是否加入 `.gitignore`。无 Git 项目跳过此项，不因此初始化 Git。

## 复用脚本与迁移

- 创建复用脚本前，先检查所属项目中已有的同类脚本，避免重复实现。
- 复用脚本使用全小写的 `scripts/` 目录，不放在 `tmp/` 或系统临时目录。
- 迁移已有脚本时，同时检查并更新调用方、文档和配置中的路径引用，不只移动文件。
