# Agent 指令与项目规则的维护

适用条件：准备新增、修改、拆分或迁移全局 Agent 指令、项目 Agent 指令或项目规则（含规范、约定），或安装、修复、调整其读取与加载入口。无论这些操作是用户直接要求，还是完成已授权任务所需，都须在操作前读取本场景。

“项目 Agent 指令文件”指当前任务所属项目实际使用的 `AGENTS.md`、`CLAUDE.md` 等入口文件。项目专属规则正文及其读取入口保存在该项目内。

## 1. 确定预期行为和适用范围

- 明确修改后，Agent 应在什么条件下执行什么动作。以用户明确要求或已确认的行为为准；尚未确认的行为变更单独列为建议。
- 跨项目共同要求归入全局指令，仅对某个项目有效的要求留在该项目。文件物理位置不决定规则适用范围。范围未明确且不同理解会改变修改位置时，先说明判断和影响，再确认范围。

## 2. 查找已有正文与入口

- **全局指令**：解析本机 `~/.codex/AGENTS.md` 或 `~/.claude/CLAUDE.md` 的实际源文件，以其所在目录为全局源目录；两个入口均存在时，核对它们读取同一份正文。读取源目录的 `README.md`、`AGENTS.md` 及相关场景；修改源库前，读取源库的项目指令和本次操作触发的规则。链接失效时报告实际断点，不猜测或创建同名副本。
- **项目指令与规则**：读取项目实际使用的 Agent 指令文件，查找相关条款及其引用。无论入口中是否已有说明，都要搜索当前项目的 `docs/agents/` 和现有入口指向的规则文档，按内容判断是否属于同一主题。

读取相关规则的完整原文后再确定修改位置。上述搜索只用于规则维护，不要求日常任务读取全部规则文件。

## 3. 选择位置、准确命名并编写规则

- 全局与项目规则均按是否需要在所有会话中加载来决定位置；项目规则的“所有会话”指该项目内的所有会话。主文件保留常驻要求和简短场景入口。简短且无需独立流程的项目规则，在需要项目内所有会话加载的前提下，可以直接写入项目 Agent 指令文件。
- 不需要在所有会话中加载的规则，应放入独立场景文件，并在对应主文件中建立按需读取入口。即使规则简短或无需独立流程，也应遵守这一结构。
- 已有适用文档时优先更新原文档。没有时，全局场景建在全局源目录的 `scenarios-agent-instructions/<主题>.md`；项目场景优先使用项目已有的正式规则目录，推荐使用 `docs/agents/<主题>.md`，但不强制。无论正文位于哪个目录，都须建立明确的按需读取入口。
- 选择复用项目已有正式规则目录或适用文档时，须在修改前向用户说明具体目录和文件、采用该位置的项目约定及适用理由、读取入口和触发条件，以及入口是新增、调整还是沿用。说明现有目录时，用括号注明“推荐使用 `docs/agents/`，但不强制”。已有明确授权且无冲突时，说明后继续执行。
- 新建场景指令文件时，按正文实际约束的对象和用途命名，必要时写明适用范围。名称应能区分相邻主题，范围与正文一致。例如，仅规定临时文件与复用脚本存放的场景，使用 `temporary-files-and-reusable-scripts.md`，避免使用涵盖所有文件位置的泛称。
- 修改场景正文后，核对文件名是否仍准确反映主题和适用范围；不匹配时，在本次修改中同步重命名。名称仍准确时沿用原名。
- 每条要求写清具体条件、动作和结果。保留已确认的规则含义；拆分或迁移本身不授权改写行为。
- 同一规则正文只维护一处，其他位置使用必要摘要和引用。检查重复、冲突和被取代内容，列出具体位置与处理建议；已有明确处理要求时按要求执行，处理方式尚未确定时请用户决定保留、更新或删除。

## 4. 建立或更新按需读取入口

- 新增独立规则文档时，同时建立读取入口。默认在对应的全局或项目主文件中，先写具体使用条件和读取时机，再引用文件并要求读取、遵守。条件须覆盖正文的适用场景，也不能扩大到无关操作；只在被引用正文中写条件，不能代替入口中的条件。
- 全局场景入口使用 `~/.agents/scenarios-agent-instructions/<主题>.md`；项目场景引用使用该项目可解析的路径，并明确路径基准。
- 已有入口完整覆盖新文档及适用场景时，复用入口。允许通过已有必读文档继续要求读取新文档，但须逐级核对触发条件和明确的读取要求；普通 Markdown 链接不代表宿主自动加载，也不等于要求 Agent 读取。覆盖不足时补充或调整入口。
- 修改正文路径（含重命名）、适用范围或执行要求时，同步检查并更新受影响的入口与引用。重命名或迁移时，搜索旧文件名与路径，更新主文件、其他规则文档、README 及配置、脚本中仍在使用的引用。仅创建文件、提及目录或罗列链接不算完成接入。

## 5. 编辑实际源文件

- 全局指令编辑解析后的源文件，保留 `~/.codex/AGENTS.md`、`~/.claude/CLAUDE.md` 等用户级加载链接。安装范围和命令以全局源目录的 `README.md` 为准。
- 项目规则编辑已确认的项目正文；全局源库自己的项目指令仍只服务该源库，不能并入跨项目主文件。
- 更换入口前，核对旧文件、引用和恢复依据。发现并发修改或目标不明时，先核对差异与目标，不覆盖未知内容。

## 6. 验证并说明结果

- 读回修改结果，核对文件名与正文范围一致；从实际指令入口逐级核对触发条件覆盖适用任务、各级路径可解析且目标存在、读取后的执行要求明确。如有重命名，检查生效引用中没有遗留旧路径。项目规则从该项目实际使用的 Agent 指令入口开始检查。
- 全局加载入口或场景引用变化时，从源库之外，通过目标宿主的新会话或加载诊断验证主文件加载和场景路径；确认各使用方仍读取同一份正式源，源库自身的项目指令没有进入其他项目。记录实际宿主、版本、工作目录及未验证范围，不将结果自动推广到其他设备或已打开会话。
- 完成后说明修改文件、作用范围，以及 Agent 在什么条件下通过哪个入口读取规则。区分文本与路径检查、实际加载验证和行为验证，不以文件存在声称行为已经生效。
