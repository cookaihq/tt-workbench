# 发布时同步仓库设计文档

适用条件：准备工作台新版本或 Skill 发布批次（调整发布版本号、整理发布说明或执行发布检查）、执行发布及发布收尾。先读取并遵守 [发布范围与 Tag 选择](git-access-commit-and-release.md#发布范围与-tag-选择)，按本次唯一 Tag 组织记录。每个版本和批次都核对对使用规范、Skill、工作台功能和相关设计的影响，包括修复、改名、移除及兼容性变化。涉及 Skill 更新时还须读取并遵守[Skill 发布说明](../workbench/skill-releases.md)。

2026-10-31 用户要求：在 tannt 创建「仓库设计」项目，分类记录和讨论使用规范、已开发 Skill、工作台功能及尚未采用的设计或灵感；工作台发布新版本时更新其中相应文档。本场景是发布 Agent 的必做工作，沿用这项文档维护授权。软件提交、推送和发布本身仍遵守[Git 与发布规则](git-access-commit-and-release.md)。

## 1. 定位两个项目

本场景路径分别以工作台源码根和 tannt 知识库根为基准。通过本机已确认的项目登记（如 Orca）或用户明确提供的位置解析各根目录；Windows、macOS 及新增设备的绝对根可以不同，不要求两个项目相邻。

- 工作台：读取实际 `AGENTS.md`、[变更联动](workbench-change-coordination.md)及本次发布涉及的正式文档。
- tannt：按[目标库规则读取](package-layout.md#目标库规则读取)读取该库实际 Agent 入口及适用业务规则，再读取 `1.项目/仓库设计/项目说明.md`、`版本记录/版本索引.md` 和上次相关版本记录。后两项版本记录路径以「仓库设计」项目目录为基准。

确认目标库身份与已有项目可读写后继续。目录改名或迁移时核对原项目身份，并同步调整本场景及项目入口；不能因原路径不可达就重建同名项目或回落到源码仓库。目标不可达或出现并发内容冲突时，保留待更新清单与当前依据，停止依赖该结果的发布步骤，恢复后核对续做。

## 2. 将版本变化对应到分类文档

固定本次拟发布版本及源码依据，与上一个实际发布版本比较；首次发布采用完整能力清单。核对实际差异、活动 Skill 清单、使用说明、实现与已有验收证据，不只依据提交标题、版本号或历史计划判断。

Skill 发布分别记录发布 Tag 与逐项行为版本，比较本批 `changed` 项及其原版本；未变化项注明继承此前正式包。记录统一使用「仓库设计」内 `版本记录/<本次Tag>.md`：联合发布将工作台和 Skill 变化合写在 `v<版本>.md`，只有 Skill 发布才建立 `skills-YYYYMMDD.N.md`；版本索引只登记实际选定的发布。此前尚未发布的拆分计划被合并时，更新其状态和索引指向，保留必要历史依据。一个候选批次或未选定的开发改动不能写成全部 Skill 已升级。

按下表检查受影响主题。表中路径相对于 tannt 的 `1.项目/仓库设计/`；内容拆分后沿该项目导航找到实际主题文件，并更新对应索引。

| 变化 | 需核对的项目文档 |
| --- | --- |
| 使用步骤、适用条件、业务规则或跨设备要求改变 | `使用规范/现行规范.md` 及对应正式规则 |
| Skill 新增、调整、改名或退役 | `Skill/内置Skill.md` 及已有单项说明 |
| 日常工作功能新增、修复、改动或移除 | `工作台功能/日常工作.md` 及已有主题说明 |
| 安装、规则、配置、同步、运行数据或版本更新功能变化 | `工作台功能/系统与集成.md` 及已有主题说明 |
| 已记录设计得到实现、改变或放弃 | `设计与灵感/讨论索引.md` 及实际相关讨论记录 |
| 本次版本及文档更新结果 | `版本记录/v<版本>.md` 与 `版本记录/版本索引.md`；导航变化时更新 `项目说明.md` |

每项影响用户使用的变化都须有对应文档更新。只有内部实现变化、现有说明仍准确时，在当次版本记录写明无使用文档变更及依据，不为凑改动重写无关页面。规则或共同概念确需改变时执行变更联动，项目使用摘要不能替代双方正式源的修改。

## 3. 发布前更新并核验

先读目标原文，按 tannt 的保存与更新流程局部修改，保留身份、创建时间、本人判断及无关内容。使用说明写清实际入口、步骤、条件、结果和限制；新增、变更、退役功能分别对应其现状，相关设计记录保留原问题、取舍和结论依据。

分别记录已开发、已发布、设备已安装和已经实际使用。源码完成或发布成功不能自动证明 tannt 已采用；未安装或采用情况未知时如实标明。既有历史记录按当时版本保留，当前说明关联新版本。

本次版本记录至少包含：前后版本与源码依据、变化到文档的对应清单、更新的项目相对路径、设计结论变化、核验结果与剩余限制。发布前使用「准备发布」等明确表述，候选能力注明拟发布版本，不提前写成正式发布或实际使用。

读回受影响文档，检查内容与版本差异一致、分类和双向关联正确、链接指向实际文件。完成条件是每项使用变化有准确说明或有依据的无影响结论，项目记录可以回查本次变更；发布说明中一句“文档已同步”不能代替实际文件。

文档核对未完成时保留待发布状态及接续清单。验证后源码或版本范围又变化时，复查新增差异及相关文档，再继续发布。

## 4. 发布后完成记录

回读实际 Release、标签／提交及附件结果后，在同一版本记录补齐实际版本、发布日期、发布链接和验证依据。只有本次另有安装或采用证据时才更新相应设备或使用状态；发布中断则保留准备状态、实际完成步骤和失败原因。

最终报告发布结果与项目文档更新结果，列出文档路径、覆盖的变化和未验证范围；其他设备的文件到达、安装、Agent 加载及实际使用分别核验。目标文档尚未保存或核对失败时，明确该项未完成，不能宣布整次交付完成。

## 正文归属与同步

本场景只维护发布 Agent 的文档联动流程，适用于维护者指定的 tannt 项目；其他使用者的知识库保留自己的规则和资料。发布 Agent 按授权写入该项目，安装器和更新器继续只负责软件资源。知识库笔记不复制进公开源码或发布包；本次文档更新也不自动授权业务材料迁移、设备配置变更或安装升级。

工作台中保持 `AGENTS.md` → `docs/agents/release-knowledge-docs.md` 的读取关系，发布说明也须要求读取本场景。tannt 中保持 `1.项目/仓库设计/` 及其分类导航的相对关系。其他设备须保持这些各自根下的相对路径与入口关系；两个仓库各自同步，不能以本机已保存证明其他设备已到达。
