# FNS 隐藏项检查 Harness

本流程仅在本 Agent 实际新建隐藏文件或目录时自动触发。触发后核对新增项的 FNS 配置，先向用户确认同步意图，再调整对应路径的配置，并在该次回复中统计其他未纳入的隐藏项。入口为 `AGENTS.md`，检查脚本为 `scripts/fns-hidden-audit.mjs`。

## 触发条件

- 本 Agent 的文件操作实际新建了名称以 `.` 开头的文件或目录，包括写文件时一并新建的隐藏父目录。
- 普通对话、查询、读取文件、修改已有隐藏项，以及在已有隐藏目录中新建普通名称的文件，均跳过本流程：不运行基线或扫描命令，回复中也不附 FNS 检查或统计。
- 其他进程或同步产生的隐藏项不单独触发本流程；本流程因 Agent 新建隐藏项触发后，再把它们计入其他既存项的统计。用户明确要求检查 FNS 时，按其请求执行。

## 执行流程

1. **仅为创建隐藏项留基线。** 已确定要新建隐藏文件或目录时，在操作前运行 `node "<软件根>/scripts/fns-hidden-audit.mjs" --vault "<库绝对路径>" snapshot`，保存输出的基线文件路径。本次创建后的检查复用这个路径。基线保存在系统临时目录，每次独立创建，适用于并行会话。实际未产生新隐藏项时，到此结束流程。
2. **创建后扫描一次。** 确认本 Agent 实际新建隐藏项后，运行 `node "<软件根>/scripts/fns-hidden-audit.mjs" --vault "<库绝对路径>" check --baseline "<本次基线路径>" --json`；同次批量创建合并检查。已创建但没有基线时，运行 `node "<软件根>/scripts/fns-hidden-audit.mjs" --vault "<库绝对路径>" check --json`，用文件操作记录确认具体新增路径。仅缺少基线或接手已有任务不会触发扫描。
3. **核对新增项。** 将本 Agent 实际新建的路径与扫描结果核对；有基线时用 `prompts` 辅助识别。对新增且尚未覆盖的隐藏项，按实际路径询问用户是否用 FNS 同步。同一目录下的文件可以合并询问，但须说明拟加入的目录范围和文件数。已经覆盖的新增项说明其覆盖来源即可；用户已明确决定的路径沿用其决定。
4. **仅在本次触发的回复中附统计。** 若存在未加入、仅部分覆盖、排除、同步关闭或未知项，列出路径、类型、状态和文件数，以及未加入范围的目录数、独立隐藏文件数。将本次新增项与其他既存项区分；既存项只做统计，除非用户要求处理。数量较多时先给总数和前 10 项，并说明剩余项数。扫描报错须标为检查不完整，不能报告为“全部已同步”。后续没有新建隐藏项的对话不重复检查或提醒既存项。
5. **落实用户选择。** 用户同意具体路径后，再修改对应设备的 FNS 设置，并重跑检查。未回答时保留原配置，完成其余已授权工作。不能把单一路径的授权扩大为所有隐藏项。

可用异步提问工具时，在检查结果已明确后发起问题并继续不依赖回答的工作；否则在最终回复中附具体问题。因本流程发问时，说明来自用户要求的项目规则，并链接本文件。建议措辞：

> 本次新增 `.example/`，含 2 个文件，目前未纳入 FNS。是否将 `.example/` 加入同步？另有 1 个既存隐藏目录尚未加入：……。

## 检查范围与结果含义

- “隐藏”指名称以 `.` 开头，包含普通目录深处的隐藏文件和目录。Windows 的 Hidden 属性本身不属于此触发条件。
- 统计按最外层隐藏目录归组，其内部所有普通文件计入文件数；独立隐藏文件单独计数，避免父子目录重复计算。基线仍记录嵌套隐藏项，能发现既有隐藏目录中新建的点号项。
- `.obsidian/` 走 FNS 的核心配置规则，不能把整个目录当作递归同步目录。其内部其他点号项仍检查。使用非默认配置目录时，两次命令均加 `--config-dir <实际目录>`。
- 区分额外目录登记、路径排除、白名单、插件启用、配置同步开关和只读模式。配置范围已覆盖，只表示按本机规则可以纳入，不表示服务端或其他设备已经收到。空目录没有文件可传输。
- 脚本依据本机 FNS **2.4.0** 扫描逻辑核验；插件升级后会标为未知，先复核新版本的规则再更新兼容版本。检查不读取笔记正文、不输出密钥、不发送同步请求；只读 FNS 配置。`snapshot` 仅额外写系统临时目录中的路径基线。
- 不跟随符号链接或目录联接，相关项标为待核验，避免把库外内容或循环链接纳入扫描。

## 同意同步后的处理

### 隐藏目录

在 Fast Note Sync 的 **配置同步-增加目录同步** 中添加用户同意的库内目录路径，对应 `configSyncOtherDirs`。保留已有条目，避免用父目录扩大用户批准的范围。如果已有路径排除或配置同步关闭，将具体阻碍一并呈现，按用户授权处理。

可以通过应用设置保存；若编辑 `data.json`，先读取并遵守[FNS 按设备配置](fns-device-config.md)，确认插件目录中是本机普通配置，再更新相应字段；旧链接先获准迁回，并让插件重新加载设置后复查，避免应用缓存覆盖。FNS 的自身 `data.json` 默认不参加配置同步；发布时生成完整 Git 快照，每台仍须核对自己的普通配置和设置，不能声称其他设备自动完成了设置。

### 单个隐藏文件

原生 FNS 2.4.0 的额外同步扫描器读取的是目录；仅把文件路径填入目录列表无法覆盖完整扫描。网盘目标已迁至普通路径 `config/cloud-storage-targets.jsonc`，按[网盘目标配置同步维护](fns-cloud-targets-sync.md)使用原生普通文件同步；不再安装独立 `.env` 补丁。检查器仍能识别其他设备残留的旧补丁，用于准确报告其当前能力，不由配置字符串推断扫描能力。

- 文件已位于获准的额外同步目录内：按目录规则检查覆盖情况。
- 文件位于未纳入的隐藏目录内：询问是否添加明确的所属目录，说明会包含哪些其他文件。
- 其他文件独立位于库根或普通目录中：先询问同步意图；需要同步时评估当前版本的文件支持或提出目录、命名方案。已迁移的 `.env` 不构成其他隐藏文件的同步授权；移动、重命名可能影响使用方，不能仅为让检查通过而自行更改位置。

## 运行与验证

脚本适用于安装 **Node.js 18 或更新版本** 的 Windows、macOS、Linux Agent 环境，无第三方依赖。手机和平板上不预设 Node.js 可用；在那里由有文件访问能力的 Agent 按同一规则人工核对当前设备设置和目录，报告检查范围及遗漏，不能把当前 Windows 的结果当作其他设备的结果。

```text
node "<软件根>/scripts/fns-hidden-audit.mjs" --vault "<库绝对路径>" check
node "<软件根>/scripts/fns-hidden-audit.mjs" --vault "<库绝对路径>" check --json
node --test scripts/fns-hidden-audit.test.mjs
```

`--vault <路径>` 可指定别的笔记库。退出码 `0` 表示检查完成，可能仍有待用户决定的路径；`2` 表示无法完整检查。脚本输出供 Agent 判断和组织提问，本流程通过项目指令接入，不依赖某一种 Agent 应用的文件系统钩子。
