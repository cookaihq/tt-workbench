# Agent 配置清单的使用约定

个人或团队的实际目标保存在目标知识库 `config/agent-config-checklist.md`，由用户决定管理哪些集成。本文件只定义清单的结构和检查标准；安装插件不创建清单，也不代表用户选择了下表中的任何可选功能。

每次运行 `tannt-sync-agent-config`，读取该实例清单以及[执行流程](agent-config-sync.md)，核对当前宿主与设备。有差异时提出具体动作，在既有授权内应用并复查。清单修改不是对所有设备的修改许可；已经明确覆盖当前动作的授权持续有效。

## 可用结构

每项包含编号、适用条件、期望设置、检查依据、获准后的处理和完成证据。保存“应该是什么”，不要填写某台设备完成状态，不保存凭据。删除条目仅停止管理，不自动卸载。

| 条目 | 用户需要确定的目标 | 验证依据 |
| --- | --- | --- |
| 当前 Agent 与知识库 | 宿主及真实目标库；每次只管理选定宿主 | 实际会话、绝对路径和运行环境 |
| 项目 Skill | 选择的软件版本和活动清单 | `.agents/skills/` 或 `.claude/skills/` 的来源，以及宿主新会话实际发现 |
| Node.js | 能运行已启用工具的受支持版本 | 当前软件的 `package.json` 引擎要求及实际命令能力 |
| 工作台 | 期望插件版本及启用状态 | 已安装 `release.json`、文件校验、实际加载版本和适用功能 |
| FNS（可选） | 是否使用及具体同步范围 | 本机普通配置、运行加载、必要的双机到达证据 |
| 飞书（可选） | 目标库、profile 和身份 | 实例同步配置及实际只读接口 |
| 网盘（可选） | 账号别名、目标父目录和默认账号 | 实例 `config/cloud-storage-targets.jsonc`、本机授权与实际账号身份 |
| 浏览器剪藏（可选） | 浏览器、入口和目标库 | 该设备上的实际剪藏结果 |

未定义的模型、权限、用户 Skill／Plugin 或 MCP 不由本流程统一管理。Agent 全局规则由独立整理流程处理，本清单不隐式转交。产品文件的取得方式与实例配置的 FNS 同步分别核验，不能把源码移出知识库后的缺失路径当作同步故障。
