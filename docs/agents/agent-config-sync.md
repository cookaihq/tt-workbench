# Agent 配置检查与同步

在目标知识库使用 `tannt-sync-agent-config`，执行者读取该库 `config/agent-config-checklist.md`，核对当前 Agent 的实际设置；尚无清单时按[清单约定](agent-config-checklist.md)确定目标，不采用其他实例的选值。有差异时呈现具体方案，在用户授权范围内应用并复查。FNS 按[专门流程](fns-device-config.md)检查本机普通文件。

## 共享目标与本机结果

检查清单是目标配置的统一阅读入口，供用户和 Agent 阅读；配置说明、活动 Skill 清单和网盘目标值继续引用各自唯一正式源，不在清单中重复维护账号及目录。配置检查结果属于本次环境，在回复中报告，不把共享目标表改成某台电脑的完成状态。执行者正常读取并遵守适用规则；Agent 规则检查、分析、迁移、入口修复和加载验证不属于本流程，也不在检查后自动转交或调用规则整理 Skill。

用户在一台电脑修改目标清单，经 FNS 把清单和受影响的共享源传到另一台电脑后，在后者重新运行本 Skill。执行者按本机实际路径和当前宿主应用同一目标，不复制旧机用户目录、会话、运行锁或其他登录凭证。FNS 发布允许包含来源完整配置快照，但每台运行配置仍留在自己的插件目录，只应用四组共享规则，不使用另一台的 Token。文件已在本机不证明远端最新版本已到达；同步不完整时列明缺项。

共享规则正文在一处获准修改后，已正确接入的设备会在新会话或后续按需读取时使用收到的内容，无需每台再次批准正文；本 Skill 不提供按设备锁定规则版本的机制。安装、链接、登录、启用及同步设置仍先检查、列方案、按本机授权应用。非敏感网盘目标唯一维护于`config/cloud-storage-targets.jsonc`，通过 FNS 普通文件同步；涉及其同步配置或新设备接入时，先读取并遵守[网盘目标配置同步维护](fns-cloud-targets-sync.md)。

现阶段宿主为 Codex、Claude Code，环境为 macOS、Windows 原生；Hermes 另行接入。判断“当前 Agent”依据实际执行会话，不能用 PATH 中同时存在两个可执行文件推断要一起配置。WSL 有独立用户目录和运行环境，不能替代 Windows 原生的检查结果。

## 首次也只发送名称

Codex 和 Claude Code 读取目标库各自的项目入口。当前技能清单已包含名称时使用标准入口；尚未包含时，从已安装软件的 `skills/manifest.jsonc` 核对名称，再读取其 `skills/tannt-sync-agent-config/SKILL.md`。软件和实例路径按[路径约定](package-layout.md)分别解析。

按名称读取源码不要求先注册，也不计为标准发现通过。未得到修改许可前，不为让 Skill 出现在菜单中先运行安装器。源码或清单尚未到达时说明具体缺失路径，不要求用户记另一条安装命令，也不从库外取得同名 Skill 代替。

## 检查

采用简易文件检查：以本机已收到的清单及自身配置工作所需资料为依据，核对可读性、必要引用、已发现的冲突和内容指纹。A07 不扩展为对项目或全局规则正文、入口或加载的管理。发现缺失、不可读、冲突副本或内容矛盾时，停止依赖这些文件的修改，继续无依赖的检查；说明具体问题及恢复检查所需条件。本流程不建立整批发布、版本锁定或远端最新版本证明，文件齐全也不等于已经收到同一批更新。

1. 确认实际库、当前宿主、系统、shell、用户目录、可执行文件及宿主配置目录。库名仍受现有工作台安装器的 `tannt` 末级目录约束；上级路径可以不同。
2. 完整读取目标清单，记录内容指纹及相关规则／清单的版本。按清单明确的管理范围检查，已纳入的飞书、网盘等配置不因本次仅检查而跳过；暂不纳入的项目保留现状。不扫描凭证正文或擅自扩大到其他库。Node 缺失时继续能完成的文件检查，把无法运行的检查列出来。
3. 检查 B02 时必须先读取并执行[FNS 按设备配置](fns-device-config.md)：运行 `node "<软件根>/scripts/fns/device-config.mjs" --vault "<库绝对路径>" --check`，普通配置保持原位，旧链接报告待迁回；缺配置提示安装 FNS，断链或目标冲突保留现场。随后独立执行其余只读检查。单项失败不阻塞无依赖的其他项；只能证明文件存在时，不报告功能已可用。当前会话未刷新 Skill 清单时单独说明。
4. 按条目编号向用户展示“目标、实际结果、符合／不符合／无法验证／不适用、证据”。不符合项附拟执行动作和影响，包括项目 Skill 发现入口、启用 FNS 配置同步可能带入的其他配置、已有文件冲突等。

缺少工具时，提出当前系统适用的安装来源和方式；模型、权限、用户级 Skill、Plugin、MCP 等未写入清单的配置不由本机库存推导。清单的值、来源或适用条件不足以判断时，只确认该具体缺项，不把它算作通过。

## 用户允许后应用

单独发送名称、同步了新清单或清单标明某项启用，都不构成 Agent 主动调整本机设置的许可；共享规则正文按上文约定随同步读取。没有相应许可时，先完成差异与具体方案，再请求用户允许全部或选定条目；说明这是用户要求的“先检查、允许后设置”流程。已有明确覆盖当前环境和具体动作的授权继续有效，不重复请求。

应用前重读清单和本次用到的共享源，并确认拟修改文件仍与检查时一致。发现缺失、冲突或内容变化时停止对应项的写入，重新核对差异；新增或扩大范围的动作需要对应许可，原授权内未受影响的部分可继续。不得把原方案的许可套用于新收到的不同清单。

按批准范围分项执行。自定义宿主配置目录、无法确认的配置来源等按实际能力报告；保留未知内容和实际环境变量，不用默认目录的检查冒充成功。重复执行只处理仍不符合目标的配置。

## 现有配置工具

将下面的 `<当前宿主>` 替换为本次识别的 `codex` 或 `claude`；检查、应用与复查保持一致。不省略该参数回到兼容旧用法的 `all` 默认范围。

| 对象 | 只读检查 | 获准后的应用 |
| --- | --- | --- |
| 项目 Skill | `node "<软件根>/scripts/agent-skills/install.mjs" --vault "<库绝对路径>" --agent <当前宿主> --check` | 同命令去掉 `--check`；只建立当前宿主的活动入口，清理同一宿主已知来源的退役链接 |
| 工作台 | 根据安装器列出的文件只读比较源码、安装副本与启用设置 | `node "<软件根>/scripts/workbench/install.mjs" --vault "<库绝对路径>"`，随后启用或重载；该脚本没有检查模式，传 `--check`／`--help` 也会写入 |
| FNS 配置文件位置 | 必须先读[FNS 按设备配置](fns-device-config.md)，运行 `node "<软件根>/scripts/fns/device-config.mjs" --vault "<库绝对路径>" --check` | 获准迁回旧链接后，实际停用 FNS，运行同命令的 `--apply`，恢复原启用状态；普通文件不搬动，缺文件不借用其他设备配置 |
| FNS 同步范围 | 按[隐藏项机制](fns-hidden-item-check.md)核对范围，需要时运行 `node "<软件根>/scripts/fns-hidden-audit.mjs" --vault "<库绝对路径>" check --json` | 按获准的具体路径调整本机设置，确认是本机插件目录的普通文件后写入；旧链接先按获准范围迁回，保留无关配置，检查插件重载后的实际值 |
| 网盘共享目标与本机授权 | `node "<软件根>/scripts/cloud-files/config.mjs" --vault "<库绝对路径>" --check` 只读检查`config/cloud-storage-targets.jsonc`；身份和授权另按[网盘规则](../rules/cloud-files.md)检查 | 按已确认值维护共享目标 JSONC，按[网盘目标配置同步维护](fns-cloud-targets-sync.md)配置本机 FNS；凭据在库外单独准备，未提供真实账号时不写示例值 |

项目 Skill 安装器保留不加 `--agent` 时处理两个宿主的旧命令，但本 Skill 使用显式当前宿主。另一个宿主的冲突不应阻塞本次。原 `tannt-setup-device` 为退役名称，清单负责清理其已知来源链接。

项目 Skill 入口在 Windows 使用本机目录符号链接；FNS 运行配置使用普通文件，无建链权限要求。实际权限错误须报告对应失败和已完成步骤，给出适用于该机器的开发者模式或管理员权限操作；获得权限后重新执行原范围。不能用 WSL、硬链接或复制文件改变既定目标。Mac 专用的 `ps`、`pgrep`、应用标识和工具路径不能证明 Windows 的运行状态。

实际新建点号名称项时执行隐藏项创建检查；仅在已有 `.agents/skills/`、`.claude/skills/` 中创建普通名称链接不触发。FNS 检查的退出码 0 不代表范围全部覆盖，更不证明已传到另一台；按报告阅读缺项、排除和未知项。

FNS 修改方案须说明具体纳入与排除路径。`.scratch/` 含临时材料、测试夹具或链接时，不能仅提出开启开关并加入父目录；先列出保留的正式记录与配套排除规则，并说明开启配置同步会纳入哪些其他 Obsidian 设置，再取得对应范围的许可。

## 复查与交付

对应用过的条目重新检查，分别报告文件配置、项目 Skill 实际发现与适用功能结果。登录、重载、新会话或无法完成的权限操作给出明确下一步。没有修改的正确项保持原样；用户未允许或未通过的项保留在结果中。

清单目标全部适用项都有证据时，才报告当前环境符合该版本目标。Windows 或双电脑的现场验证尚未完成时明确范围；其他设备按相同清单自行运行。需要保存本机执行记录时，遵循[运行记录约定](../rules/writing-and-changes.md)，不要把机器检查结果写回共享目标清单。

工作台、FNS 往返与冲突的跨设备验收仍见[第二台电脑](../workbench/second-computer.md)。本功能演进与验证保留在[原设备接入记录](../../.scratch/device-setup/spec.md)。
