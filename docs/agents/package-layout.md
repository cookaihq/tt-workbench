# 软件位置与目标知识库

`<软件根>` 是本次执行工具的确定资源根：工作台源码仓库根、完整插件安装根（通常为 `<库>/<配置目录>/plugins/tt-workbench`），或独立 Skill 自带的 `runtime/`。通过发现链接读取 Skill 时，先解析其真实目录；同目录存在 `skill-package.json` 就使用其中的 `runtime/`，仅旧安装与源码开发从 `skills/<名称>/` 向上两级回到根。所选根中的 `lib/`、`scripts/`、`docs/`、`templates/` 属于同一版本，不用工作台当前工具替换独立包内工具。

管理 Skill 的安装与更新使用完整插件根的 `scripts/agent-skills/install.mjs`；活动页面清单来自该插件的 `skills/manifest.jsonc`。各 Skill 的实际版本来自其自身 `SKILL.md` 的 `metadata.version`。独立包更新、正式清单与管理边界见[Skill 版本与发布](../workbench/skill-releases.md)。

`<库>` 是用户明确操作的知识库绝对路径，名称不限。软件文档中的相对链接以该文档所在目录为基准，`<软件根>/scripts/`、`lib/`、`skills/`、`templates/` 是工具资源；业务路径、实例 `config/`、`.agents/`、`.claude/`、Obsidian 配置和本机运行位置配置相对于目标库。两边均可有 `docs/`、`AGENTS.md` 和 `GLOSSARY.md`，不能按同名互换来源；目标库文档按其自己声明的基准解析。

命令从任意工作目录运行，使用软件的绝对路径并显式传 `--vault "<库>"`。自定义 Obsidian 配置目录另传 `--config-dir "<库内相对目录>"`。缺少目标库就停止该命令，不回落到源码库。

目标库的个性化配置清单为 `config/agent-config-checklist.md`；产品提供流程和模板，不替所有用户决定启用 FNS、飞书、网盘等集成。未建立清单时仅报告缺项，用户确定期望后再保存。

个人全局规则由用户明确选择的知识库或规则仓库维护，工作台公开仓库及安装包不包含个人正文。`<规则源>` 指已确认、包含 `AGENTS.md`、`README.md` 和 `scenarios-agent-instructions/` 的绝对目录；其选择独立于软件根和当前目标库。规则页面显式选择该目录，接入工具必须传 `--source "<规则源>"`。采用、合并及本机入口替换沿用具体授权边界。已确认的 tannt 个人正式源位于 tannt 项目根的 `docs/global-agent-instructions/`；这不是其他使用者的默认源。

功能历史和 `.scratch/` 属于开发仓库。历史验证文件迁入本机 `local-evidence/`，不在分发包中；文档中的历史链接不能视为安装缺失或已在当前设备验证。凭据与 FNS 运行配置不包含在公开源码及安装包中。

## 目标库规则读取

使用任何工作台 Skill 或工具处理目标库前，执行以下步骤。此流程由 Agent 执行；CLI 和插件不会解释 Markdown 规则或自动切换业务模型。

1. 从用户明确的目标确定库根，从 Skill 的真实路径确定软件根，分别记录。遵守当前宿主实际生效的项目入口（如 `AGENTS.md`、`CLAUDE.md` 及其导入、覆盖和适用的下级入口）；启动目录不在目标库时也须读取目标库入口。不能将软件开发 `AGENTS.md` 当作该库入口。
2. 根据本次操作，从该入口逐级读取其要求的业务／场景正文及所需概念。Markdown 链接相对解析后的源文件目录；文字路径采用文档明确的基准。入口可能指向本库 `docs/rules/`、`docs/agents/` 或其他已明确位置，沿实际引用读取，不按固定文件名猜测；普通链接存在不等于宿主已自动加载。
3. Skill 步骤列出的范围、内容来源、收件箱、项目任务、附件、网盘、飞书、写入等是待匹配主题。使用目标库选定的正文，不再隐式读取软件的同名规则。软件 `docs/rules/`、模板及操作说明用于核对产品模型、格式、工具参数和限制；目标库明确采用某项软件默认规则时才把该项作为其业务依据。
4. 入口、必要规则或引用缺失、来源不明，或规则之间有冲突时，列出具体断点／双方出处和对本次动作的影响，停止依赖它的写入，继续独立的只读核查。目标库要求与工具能力不符时，说明不支持的字段、目录或行为，选择符合规则且已获授权的其他方式或协调实现；不能静默用软件默认覆盖，也不能声称改了规则就改变了代码。
5. 执行前确认本次必需主题均有依据及适用工具；完成后核对实际文件和引用，报告所用目标库入口、规则位置、软件能力与未完成项。文件读回、安装校验、宿主实际发现／加载和其他设备同步分别验证。

### 新目标库采用默认规则

安装只交付插件资源。沿用安装后的显式初始化／配置流程：先由用户明确采用的模型和主题，再在该库自己的入口中记录选择；需要独立维护时在该库建立所需正文并让入口指向它，每个项目内部保持一处。已有入口及规则保留并比较，不能覆盖。完整初始化不是当前安装 CLI 的能力，也没有自动规则导入命令；Agent 在明确初始化授权内维护文件，不新增规则位置配置或从空库推断默认采用。

只引用软件默认正文的库须明确引用版本及升级后的核对方式；软件更新本身不授权改业务规则或笔记。已由目标库独立维护的正文继续以其入口为准。跨项目共同含义变化按[变更联动](workbench-change-coordination.md)处理，保留各自独立使用的内容。

## 运行目录迁移

运行目录默认是 `<实例根>/.system/.workbench-runtime/`，固定位置配置为 `<实例根>/.system/workbench/runtime.jsonc`。工作台、CLI 和 Skill 共用解析器；自定义位置相对于所属实例根目录，不能使用库外路径或链接。笔记、FNS、Skill 与连接记录属于目标知识库；Issue 属于实际 developmentRoot。FNS 回执继续核对设备与 configDir。规则正文见[本机运行记录](../rules/writing-and-changes.md#本机运行记录)。

工作台顶部「运行数据位置」可选择知识库或开发实例，查看实际设置、预览迁移、恢复默认。填写库外独立备份目录后「迁移并保存」；本库入口暂停连接服务与 FNS，完成后恢复并报告加载结果。先结束其他 CLI、旧版插件及开发实例的写入程序。界面提示的相对路径始终以上方选定的实例根为准。

独立入口同样支持 Obsidian 未运行时操作：

1. 用 `node "<软件根>/scripts/workbench/runtime-storage.mjs" --vault "<实例绝对路径>" --check` 取得实际位置、源目标、清单与指纹。修改位置时加 `--directory "<实例内相对目录>"`，恢复默认加 `--reset`；自定义配置目录加 `--config-dir`。检查不创建目录，不输出记录正文。
2. 完整安装新包；安装只更新插件目录。实际停止旧版工作台、相关 CLI 和 FNS；核对旧锁、连接记录与 PID。异常退出的记录按所属模块核对恢复，迁移不自动删除。多个旧目录、未知内容、链接或目标冲突均保留现场。
3. 排除实际新旧运行目录与 `.system/workbench/` 的 Git/FNS 同步。用 `--configure-isolation` 明确补齐本机必要排除，保存原设置到迁移备份；只追加必要 Git 忽略与 FNS 目录规则，白名单冲突停止。保留其他字段，不排除整个 `.system/`。旧 apps 退役时，`retiringParents` 列出将退出且须排除的空父目录，含其他应用的父目录不移除。
4. 使用相同 directory/reset 参数加 `--apply --expected "<指纹>" --backup "<库外独立备份目录>" --writers-stopped`。程序取得固定协调锁及源目标迁移锁，复查租约；备份并核验 SHA-256，再复制、读回、清理源，最后保存位置配置。只移除已空的目录。
5. 备份的 `manifest.json` 记录实例、版本、源目标、配置前后原文、哈希和阶段，`files/` 保存原始记录；`isolation-*.json` 可能含完整本机设置，不能输出或公开。失败时保留固定协调记录，阻止继续写入。中断后用同一备份 `--resume --backup "<原目录>" --writers-stopped`；恢复用 `--restore`。进程退出遗留锁需验证原进程已结束，仍活跃或归属不符就停止。
6. 恢复拒绝覆盖后续记录或配置，只清理本次创建且仍与原版本一致的文件，恢复原位置设置；安全排除继续保留。历史 JSON 保持字节，已知恢复路径通过本实例位置历史读取。恢复到旧版布局后，新版再次写入仍须显式迁移。
7. 恢复运行服务，分别验证实际加载、CLI、历史重试、Git/FNS 排除和旧目录不再出现。实际笔记不是测试夹具；合成写入放开发仓库忽略的 tmp 独立库。新建隐藏项时按目标库的隐藏项检查规则执行，已经明确的运行数据排除意图无需重复询问。

本流程不是跨文件事务。清单、备份、协调状态支持中断续做与保守恢复；不约束忽略锁的外部程序。不同设备分别核验，不从本机结果推断跨设备传输。0.24.0 的旧迁移清单保留用于回查；本版续做/恢复使用本版生成的 schema 2 清单，旧清单按原版本工具和现场核对。
