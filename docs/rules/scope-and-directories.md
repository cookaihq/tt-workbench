# 范围与目录

这是工作台支持的默认业务模型；目标库的实际采用范围按[规则读取流程](../agents/package-layout.md#目标库规则读取)确认。个人使用范围、分类和集成选择由目标库维护。

目标知识库供使用者学习、研究、思考、创作及开展工作使用，可按自身主题设置方向，也容纳其他兴趣、未成熟判断、失败尝试及零散想法。记录不以对外发表为前提。关注信息、课程学习、社群研究、长期专题、内容创作、企业培训等工作可共享资料与积累，不因此另建多个库。

## 库与访问边界

- 当前库与私人库独立。Agent 不主动读取、关联、同步或转存私人库；它不是敏感内容的默认保存位置。
- 疑似私密内容只提醒。会话中的内容先不保存；已有文件不擅自移动、复制、删除或改写。本人明确对象和动作后才执行。普通整理指令不授权跨库操作。
- 其他库外来源仅限本次明确提供或已授权的位置。一个路径或链接不证明文件已取得、可达或已同步。
- 本库的成果可以按另行授权在网站、飞书等平台交付；保存笔记不授权发布或发送。

## 业务目录

本库采用适配 PARA 的五个业务根目录，卡片盒写作与 MOC 在这些目录之间连接认识和来源。项目可长期推进，领域维护持续责任，资源保存知识和材料；决定见[ADR 0004](../adr/0004-project-centered-information-architecture.md)。数字与点号是实际目录名，使用下表的精确名称。

| 根目录 | 内容与内部组织 |
| --- | --- |
| `0.收件箱/` | 尚待澄清处理方式的输入，结构见[收件箱规则](inbox.md) |
| `1.项目/<项目名>/` | 已决定投入且范围明确的工作，集中保存项目、所属任务及专属过程与成果；具体路径见[项目与任务](projects-and-tasks.md) |
| `2.领域/<领域名>/` | 持续责任、标准、运行记录与跨项目投入取舍；通过链接关联项目与资源，不把它们作为领域子目录 |
| `3.资源/` | 供理解和复用的知识、来源、对象信息和工作内容；不要求已有用途或已经被多个项目使用 |
| `4.存档/` | 通过明确归档动作移入的项目、领域记录或资源，连同专属材料保留上下文与恢复依据 |

`3.资源/` 按需使用 `知识/`（含实践经验）、`来源/`（课程、文章与视频、社群等）、`对象/`、`可复用内容/`、`专题/`。知识分类按实际积累确定，不预建学科树。`飞书知识库/` 保留整个同步单元，适用[飞书同步规则](lark-wiki-sync.md)，不能按普通来源材料拆散。

导航使用库根首页和按需 MOC，不设独立导航、待考虑或任务根目录。每个任务必须属于项目；暂未找到具体业务归属的已承诺工作由专门项目承接，尚未决定投入的想法可以保存为资源。领域不是项目的必填归属，长期主题也不自动成为责任领域。

旧 `01`—`06` 目录只作为历史路径与迁移输入，不继续新建旧根目录。已有业务内容按获授权清单迁移，不能对旧领域或经验整根同名替换；真实业务与验收样例分别核对。路径变化、引用、网盘和飞书关系须同步维护，历史说明见[编号与迁移说明](../workbench/numbered-directories.md)。当前实现与迁移的完成范围以[本轮实施记录](../../.scratch/information-architecture-workflow/spec.md)为准，规则生效不等于所有设备和入口已经验收。

明确属于课程、企业、领域、Project 或 Task 的材料就地保存，其他内容通过链接复用；不要求先经过 Inbox。一篇笔记选一个主要位置。明确归入任务的 Inbox 原记录和专属附件一起迁入任务，规则见[项目与任务](projects-and-tasks.md#任务资料归属)。目录按实际需要创建，验收样例不代表本人的分类、方向、企业或账号。

## 内容创作与培训

- 内容创作的持续责任与方向管理按需在 `2.领域/内容创作/` 维护；候选选题等未承诺制作的内容可作为资源保存。本人决定制作后，简单工作作为项目内 Task，需要独立管理多项任务时建立 Project，关联并保留原选题。长期运营可作为 Project，独立交付项目与其平级关联，不新增子项目层。
- 创作方向不再限制一个内容项目只能归属一个方向；不同方向的工作通常分别建立项目，也允许按实际需求在同一项目关联多个方向或账号。稿件、脚本和各次发布/使用分别关联实际方向与账号，不因解除限制而强行合并现有项目。方向关联按需填写，不作为建立项目的前提；当前字段与操作见[文件操作说明](../agents/vault-file-operations.md)，入口验收见[本轮实施记录](../../.scratch/information-architecture-workflow/spec.md)。
- 具体账号事实信息在 `3.资源/对象/`，持续运营责任在领域中维护，已决定执行的工作在项目中推进；稿件与发布记录关联实际账号，不用平台名替代账号身份，不预设方向与账号一对一。
- 企业培训的责任与标准按需在 `2.领域/企业培训/` 维护；企业事实信息在 `3.资源/对象/`，通用培训内容在 `3.资源/可复用内容/`，各次开发与交付项目在 `1.项目/`。一家企业可有多个项目，一套内容可被多个项目引用，一个项目也可组合多套内容。本人学习的来源课程使用 `3.资源/来源/课程/`。

课程学习、课程开发和具体授课是可以组织为 Project 的工作；课程来源与长期维护的教学内容是被这些工作使用的内容。收藏或购买课程不自动建立项目，项目结束也不自动结束其内容的复用。

## 存档与恢复

归档是明确的整理操作，完成、取消或暂停工作都不自动搬动文件。按已获授权的对象范围，将项目、领域记录或资源及其专属材料整包移入 `4.存档/`，保留原对象身份、实际状态、来源和上下文；项目内任务随项目保留归属。仍在独立复用的资源不因引用它的项目结束而归档。归档不是删除，也不据此改变本人是否已完成工作。

操作前记录源/目标清单、原版本和恢复位置，核对外部引用及目标冲突；核验目标与链接后再移除源文件。恢复时按记录返回原位置或明确指定的新位置，先检查重名与并发修改，不覆盖现有不同内容。跨文件操作遵守[写入规则](writing-and-changes.md)，托管附件执行[网盘路径联动](cloud-files.md)，飞书同步单元执行[同步规则](lark-wiki-sync.md)。普通移动工具不能代替这些联动和恢复核验；实际工具支持范围见[文件操作说明](../agents/vault-file-operations.md)。

## 源码与非业务内容

以下源码目录均位于独立工作台仓库或安装包，具体位置见[路径约定](../agents/package-layout.md)。目标库保留业务内容、自己维护的规则／场景／概念及实例配置与运行记录。

`apps/workbench/` 为工作台源码，`lib/vault/` 为共用文件模块，`skills/` 为场景 Skill 源码，`scripts/<用途>/` 为复用脚本，`templates/` 为模板，`docs/` 为规则与说明。功能规格和任务使用 `.scratch/<功能名>/`，是长期正式记录，不是临时缓存。

个人全局 Agent 规则由所选规则源所属仓库维护，源目录独立于工作台软件，见[路径约定](../agents/package-layout.md)。各项目自己的场景指令仍保存在各项目；各目标库的项目指令保存在各自根目录；工作台开发入口属于工作台仓库。

这些目录、隐藏项、依赖和运行数据不进入工作台业务笔记列表。根目录普通 Markdown 可被业务浏览读取；规则入口、README 和术语表使用各自的阅读入口。
