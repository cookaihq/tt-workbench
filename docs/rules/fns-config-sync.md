# FNS 共享规则的发布与应用

本文中的 `<运行目录>` 按[本机运行记录](writing-and-changes.md#本机运行记录)解析，默认 `.system/.workbench-runtime/`；自定义位置从所属实例的 `.system/workbench/runtime.jsonc` 读取。

适用于当前 tannt 库的 FNS 配置同步功能。设备完整配置的位置、身份、凭据和旧链接迁回继续遵守[设备配置规则](../agents/fns-device-config.md)；本文件规定不同设备之间如何选定并采用共享规则。

## 范围与归属

共享范围固定为额外目录、排除目录、排除文件类型和排除白名单四组，分别对应 `configSyncOtherDirs`、`syncExcludeFolders`、`syncExcludeExtensions`、`syncExcludeWhitelist`。每次整体发布和应用，包含新增、修改、删除及清空；不能以集合求并复活已删除规则。

每台设备保留并使用自己的完整配置。A 发布本机规则，不代写 B 的设备文件；B 只将这四组规则应用到自己的真实配置目标。账号、Token、连接、开关、只读模式及其他字段继续属于本机。完整设备配置允许进入 Git 的既有决定继续有效，界面与日志不输出凭据。

本机运行配置保留在插件目录的普通文件中。发布时读取完整原文并生成固定 Git 快照，接收从同一提交的快照读取规则；不要求配置外移或建立符号链接。规则值来自发布来源的设备配置快照。权威元数据记录来源、发布身份、前序、版本、时间、字段范围、内容指纹及逐条规则的设置说明，不形成另一份可独立编辑的规则正文。

## 规则设置说明

每条规则可填写设置目的、原因或适用条件，按字段组、规则模式和大小写选项对应。说明是供人阅读的纯文本，不写入 FNS 设备配置，不改变同步规则的含义或规则指纹；未填写时明确显示暂无说明，不推断本人的设置理由。

工作台提供说明编辑入口，先保存为当前设备的说明草稿；Agent 也可通过独立程序维护同一份草稿。保存草稿不发布、不改写已接收版本。发布时预览说明变化，将与本机规则对应的说明一起固定到新的权威版本；只修改说明也可以发布新版本。删除规则后不把旧说明附到其他规则，旧版本仍保留原说明。

接收设备展示该权威版本中的说明，不依赖是否已经应用规则。说明草稿基于明确的已接收版本；编辑后来源版本发生变化时，保留草稿并要求比较后重新保存，再发布。保存和发布均核对编辑时的本机规则、接收版本及草稿，拒绝陈旧覆盖；推送失败重试沿用已经生成的说明与发布身份。

已发布说明保存在专用传输分支的 `config/fns-config/authority.jsonc`；未发布草稿保存在本机 `<运行目录>/fns-sync/state.json`，沿用运行数据的 Git 忽略与 FNS 排除。旧发布没有说明时正常读取；更新说明通过新版本传递，不回写旧提交。

## 发布、接收与争用

修改 FNS 设置不等于发布。发布前先核对本机内容及当前远端版本，展示差异；本人确认后生成发布记录并通过 Git 传递。普通工作分支、暂存区、无关文件和其他待推送提交不属于本操作范围。

发布使用独立的 FNS 传输引用，提交只包含来源设备完整配置和权威记录，历史从独立根开始。更新基于已核对的前序，不强推，不用较大版本号或较晚时间自动覆盖另一设备的发布。

本机生成、远端接受、另一设备接收与另一设备应用分别记录。推送失败保留同一发布身份供重试；结果不明时先核验远端是否已接受。远端已经推进时重新比较，不覆盖新的发布。明确放弃待推送记录保留本机规则及回查依据。

接收只取得并核验发布对象，不自动应用。来源配置、字段范围和指纹须对应同一发布；不一致时停止使用并提示重新发布。远端历史删除或改写时保留最近核验的记录。离线时只能展示最近收到的版本，不能证明它是当前最新。

## 本机应用与恢复

应用固定到用户看到的版本和本机原文。预览后任一依据发生变化，停止陈旧操作并重新比较。本机已有未发布修改时，明确选择保留本机、稍后处理或用权威版本替换；不静默合并或自动发布。

写入前保存恢复材料，实际暂停 FNS，再更新本机插件目录中的普通配置文件，仅改四组字段。读回并核对文件类型、恢复原启用状态、核验实际加载。旧链接须先明确迁回；应用不自动迁移配置。写入、加载和文件实际同步分别判断；配置同步关闭、只读模式或连接问题不通过隐式修改设备设置解决。

发布快照路径及旧设备配置目录 `config/fns-config/` 与本机运行数据 `<运行目录>/` 必须继续被 FNS 排除，白名单不能覆盖。来源不符合时拒绝发布或应用，不能悄悄补规则后宣称与来源一致。

FNS 自身的内部排除项、字符串规范化与共享规则分开处理。不同文本但相同规则含义不制造假差异，非法或无法识别的内容不能被丢弃后当作有效版本。

恢复只针对本机明确选定的上次操作，先核对恢复材料和当前配置；后续外部修改存在时保留现场。各阶段可能部分成功，不宣称跨文件、跨进程或跨设备事务。明确恢复时，程序只在核对原持锁进程已经退出、锁与恢复记录仍匹配后接续；活进程、权限不足或无法识别的锁须保留现场，不自动抢占。

应用回执绑定本机设备、发布身份和规则指纹。重开页面重新核验；仅内容相同而无回执时显示内容一致，不虚构应用历史。没有远程回执机制时不报告其他设备已应用。

## 接入与能力边界

### 工作台代码由 Git 传递

源码、共享模块和脚本在独立工作台仓库维护，安装包通过本地安装或 GitHub Release 更新。每台知识库设备排除 `<运行目录>/` 以及实际配置目录下的 `plugins/tt-workbench/`、`plugins/tt-workbench-recovery/`；白名单不能覆盖。运行数据继续排除 Git。软件来源与知识库自己的 FNS 配置传输仓库分别管理。

本机调整不代改其他设备。沿用本规则的发布、接收和明确应用流程传递排除，或在每台设备分别设置。已排除的工作台代码目录不得因应用旧权威版本而重新进入 FNS；先更新并发布规则，再应用。安装、版本检查与首次接入见[工作台版本说明](../workbench/updates.md)。

设备检查、旧链接迁回与版本处理由程序实现，不以 Skill 为运行前提。缺少 FNS 或本机配置时引导先安装并配置，不自动借用其他设备身份。工作台不能运行时，独立程序可执行检查；无法确认 FNS 已暂停时不得写入。

当前实现与支持版本见[工作台使用说明](../workbench/fns-config-sync.md)，实际验收见[功能记录](../../.scratch/fns-config-sync/spec.md)。`tt-sync-agent-config` 暂时保留，其整体去留另行讨论。
