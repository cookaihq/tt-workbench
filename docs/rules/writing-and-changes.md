# 写入与规则变更

本文维护工作台写入协议及开发维护要求。处理目标库业务文件时，先按[目标库规则读取](../agents/package-layout.md#目标库规则读取)取得该库的适用正文，再核对本软件契约；两边规则各自在所属项目维护。

## Agent 独立运行

Agent 在本库读取、新建、追加、修改属性及保存附件，不要求 Obsidian 启动、打开当前库或启用工作台。通过明确目标库路径、实际文件访问能力和本次授权确定操作范围。工具可选择直接文件操作或符合相同规则的接口；工作台连接信息不作为唯一库定位方式。

文件写入后直接读回核验。工作台之后打开时读取同一份文件；工作台的显示与重载验收不成为每次 Agent 保存的前置条件。新建、已有内容更新均遵守这一要求。

编辑或移动 `3.资源/飞书知识库/` 下的非配置内容，或将其中改动回传飞书前，Agent 必须先读取并执行[飞书知识库编辑与同步](lark-wiki-sync.md)；迁移期间旧位置同样适用。配置例外、拉取、冲突与回传确认的具体要求以该文档为准。

## 新建、更新与重试

- 新建不得覆盖已存在的不同内容。原文件复制核对字节或内容哈希，返回实际位置；目录与文件分步完成时，不声称全体原子写入。
- 更新前读取完整原文，只实施本人授权的正文或属性变化。保留无关属性、注释和正文，普通更新不重算创建时间、不重生成身份、不擅自改类型。
- 本机参与共用写入约定的多个 Agent 与工作台按文件协调写入。更新时核对原文；检测到变化就保留拟写内容并报告冲突，不替换成新快照强制重试。
- 原生编辑器、FNS 和其他未参与约定的写入方不受本机协调锁控制。应验证实际冲突场景并明确保护范围，不宣称文件哈希检查或原子替换能够提供全局并发保证。
- 成功必须由实际文件读回确认。失败、部分成功、保存后内容又变化或验证未完成分别报告，指出已保存文件和未完成步骤。不得把冲突副本当成原笔记已更新。
- 同一操作重试沿用请求标识并核对实际结果；输入变化使用新请求。已写结果变化或中断状态不明时先检查，不重复追加、不自动覆盖。
- 冲突内容作为辅助记录保留，可回查原笔记，不计作新 Inbox 记录。无法保留副本时明确告知并保留可恢复的输入。

跨文件迁移必须保存源/目标清单与恢复记录，核对源版本，先核验目标和引用再移除源文件。迁移不是多文件原子事务；中断或外部编辑时停止并报告具体步骤，只有核对结果后才能重试。明确的迁移可以改变原记录位置与类型，仍保留其身份、创建时间和原始正文。

这些要求适用于各写入工具，复用脚本是实现方式，不是唯一许可入口。

## 本机运行记录

工作台、独立 CLI 和 Skill 配套工具默认使用显式目标实例根目录下的 `.system/.workbench-runtime/`。工作台可查看、修改位置或恢复默认；自定义位置是相对于所属实例根的普通目录，不能越出实例、经过链接或包含工作台的位置配置目录。业务笔记的锁、回执和恢复材料在运行目录的 `vault-io/`；开发 Issue 使用实际 `developmentRoot` 的设置，不能写进另一个业务知识库或将多个库记录汇入软件仓库。路径由 `lib/runtime/storage.cjs` 统一解析，与 Obsidian 配置目录和插件安装位置无关；没有 Obsidian 进程也读取同一设置。

位置配置固定保存在所属实例的 `.system/workbench/runtime.jsonc`，不随运行目录移动，不写入插件 `data.json`。该目录也保存迁移协调状态。位置配置和运行记录都是本机状态，分别明确排除 Git 与 FNS；不得因此排除整个 `.system/` 或改变其余隐藏项的同步策略。更新 JSONC 保留无关字段与注释；无配置时使用默认，配置损坏时停止，不悄悄回落。

操作完成后释放本次创建的锁、删除已经成功提交的暂存内容；紧凑请求回执保留用于重试，失败恢复材料保留用于核对。中断遗留锁不自动抢占，先核对持有者与恢复记录。此目录不纳入源码版本管理，须保持 Git 忽略；初始化或接入 Git 时先核验忽略规则。每台设备使用前核验其 FNS 排除配置，不能声称本机成功代表另一台同步成功。

跨文件迁移的清单及修改前后版本在完成后仍保留，用于追溯与核对重试；业务阅读与后续补充使用任务内资料，不使用这些本机恢复记录。

从旧 `.workbench-runtime/`、`apps/workbench/data/` 升级或修改位置时，先读取并遵守[运行目录迁移流程](../agents/package-layout.md#运行目录迁移)。安装和只读检查不自动迁移。新写入发现待迁旧目录或迁移协调状态即停止，避免丢失旧请求回执后重复操作；迁移前停止相关 CLI，工作台入口暂停自身连接服务与 FNS，旧版本须实际停用。当前程序用固定协调锁、运行目录内的 `writers/` 租约与各模块锁协调迁移，异常遗留的租约和锁先核对进程与恢复材料，不能直接抢占。先备份、复制并核验目标，再清理源和提交位置设置；中断保留可恢复状态，设置失败不能启用空目录。历史回执原文不改写，已知恢复路径通过本实例的旧位置映射读取。

整个新运行目录必须排除 Git 和 FNS，保留旧目录排除以防未升级写入方重建。发现新旧目录冲突、链接、未知内容或并发变化时保留现场；不能覆盖新记录或用删除历史代替迁移。

## 项目配置格式

自行维护、供人编辑且读取方可控的 JSON 配置使用 `.jsonc`，支持 `//` 行注释与 `/* … */` 块注释。软件维护 `skills/manifest.jsonc`，各目标库维护自己的 `config/cloud-storage-targets.jsonc`；保留 JSON 的双引号与值类型，不使用尾随逗号或 JSON5 的单引号、无引号键等扩展。同一对象中的键只定义一次。

读取方使用 `lib/config/jsonc.cjs`，遇到语法错误或重复键拒绝读取，不执行配置内容。更新配置须局部修改、保留无关注释和字段，不用 `JSON.stringify` 覆盖整份带注释文件。迁移时同步修改读取方、路径引用和适用的同步检查。

Obsidian、FNS、第三方软件规定的配置及包元数据继续使用其要求的格式；接口请求与响应、程序生成的回执、缓存、依赖来源记录和历史验收证据继续使用标准 JSON。已有业务附件、库外授权档案和第三方依赖源码不因本约定批量改写。

## 变更共同规则

用户或获授权维护者确认变更后，在所属项目更新对应正文；本项目内部保持一处正式正文，其他位置维护必要摘要和引用。工作台与目标库各自保存需要且可独立使用的规则与概念；共同含义变化时，先读取并遵守[工作台变更联动](../agents/workbench-change-coordination.md)，检查两边对应规则、场景、术语、格式、Skill、模板和实现，不以跨项目去重撤掉目标库正文。

实现有冲突时提供具体依据并讨论规则，不能静默改含义。受影响实现、安装和实际入口验收都是同一交付的一部分；存在缺口时记入功能任务，不宣布整项完成。历史证据保留当时时间与范围，不能替代新版本验收。

修改按实际影响选择测试；记录基准、目标文件哈希或版本、安装副本、执行结果与跳过原因。仅说明文字修改不重跑应用测试。已有笔记是否迁移需单独明确，不因规则或程序重写自动移动或改写业务内容。
