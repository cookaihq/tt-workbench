# 飞书知识库编辑与同步

本文中的 `<运行目录>` 按[本机运行记录](writing-and-changes.md#本机运行记录)解析，默认 `.system/.workbench-runtime/`；自定义位置从所属实例的 `.system/workbench/runtime.jsonc` 读取。

## 适用范围

本规则适用于 Agent 在本库 `3.资源/飞书知识库/` 下新建、修改、重命名、移动或删除知识库内容，包括正文、附件和目录结构。目录迁移期间旧 `04.资料/飞书知识库/` 及已明确移位的同步单元同样适用，不能通过路径变化绕过同步规则。每个知识库子目录对应一个飞书知识空间；涉及多个知识库时，分别核对账号、拉取并报告结果。

只读操作和仅修改知识库同步配置文件，不触发本规则的编辑前拉取及编辑后回传询问。配置例外仅指明确承担知识空间与 CLI 账号绑定的配置文件，不能按文件后缀把正文或附件排除。一次操作同时修改配置和内容时，内容部分仍执行完整流程；配置文件不作为知识库内容拉取或上传。

仅拉取并保存远端内容不产生新的待回传修改；此时报告拉取结果。仅调整本地节点的存放路径、本地链接或已确认的共享正文嵌入表示，未改变远端正文、标题或节点关系时，也不产生待回传修改；此时报告本地映射调整结果。本地文件移动不自动代表飞书节点移动。会话收尾的回传询问针对 Agent 编辑后尚未回传的内容。

本规则约束 Agent 的操作，不代表 Obsidian、FNS 或其他编辑器会自动执行这些步骤。本地文件写入同时遵守[写入与变更](writing-and-changes.md)，附件与恢复材料遵守[附件规则](attachments.md)。

## 每个知识库一份配置

每个知识库目录只维护一份手工配置，已有配置沿用原位置，新建时使用 `同步配置.yaml`。由本人或获授权的 Agent 维护，执行同步的 Agent 在访问该知识库前读取。多个知识库可以绑定同一账号，也可以分别绑定不同账号；绑定关系随各自配置保留，直到明确修改或移除。

配置应能明确提供：

- 飞书知识空间 ID，以及它对应的本地知识库目录。
- Lark CLI 使用的 profile；如采用独立 CLI 配置目录，也须明确该目录的来源。
- 期望应用的 app ID，以及该应用下期望用户的 open_id。

profile 选择的是 CLI 应用配置，不能单独证明当前登录用户。Agent 必须读取 CLI 实际生效的应用与登录用户信息，与配置中的期望身份比较。缺项或不匹配时停止该库内容的编辑，报告具体缺项或差异，不自动切换登录用户。

登录凭证由 Lark CLI 管理，不写入知识库配置或正文。不另增第二份需要本人维护的账号映射配置。上述配置约定不会使 CLI 自动发现或读取此文件，读取与核对由执行同步的 Agent 或后续实现负责。

## 本地节点与同步记录

每个飞书节点保留一份 Markdown 节点文件；其内容按下文保存为正文或正文嵌入。节点有子节点时，创建该节点的同名目录，将自身节点文件保存为目录内的 `_节点名.md`，子节点也放在该目录内。各层递归使用同一规则，例如 `大模型使用/_大模型使用.md` 保存父节点，`大模型使用/API接入大模型/_API接入大模型.md` 保存同样有子节点的下一级节点。无子节点的笔记直接使用 `节点名.md`，不单独建目录、不加下划线。下划线只用于本地文件名，不加入笔记原始标题或飞书标题。

标题中的 `/` 等文件名不安全字符替换为对应全角字符；同层重名或替换后冲突时先明确区分方式，不能覆盖现有文件。调整本地存放规则时，同时更新受影响的本地链接、同步清单与本地比较基准，保留节点身份和远端对应关系；不能把文件移位误判为远端文档删除或新建。

笔记属性保存原始标题、来源链接、`lark_space_id`、`lark_node_token`、`lark_obj_token`、`lark_obj_type`、`lark_parent_node_token`、`lark_revision_id` 与 `lark_pulled_at`。现有文件以节点标识和同步清单中的实际路径定位，不能在标题变化后仅按新标题重新生成另一份笔记。正文中的文档引用和子页面列表，在目标已随本次拉取保存时转换为本地链接；范围外目标保留远端链接，不据此扩大拉取范围。

### 共享正文与 Obsidian 嵌入

经来源账号与实际对象核对，不同节点的 `lark_obj_type`、`lark_obj_token` 相同时，只维护一份可编辑正文，其余节点通过 Obsidian 的 `![[库根相对路径，不含 .md]]` 显示它。标题相同但对象不同的文档仍各自保存。每个节点保留自己的标题、来源、空间 ID、节点 ID、父节点和远端版本，不能用正文节点的身份覆盖其他节点的身份。

已有正文归属时沿用；首次选择时，优先使用本次已接入节点中唯一的 `node_type: origin` 所在路径。没有唯一可用原节点且归属尚未确认时，先保留现状并确认，不根据遍历顺序任意选择。正文路径一旦确定就记入同步清单，不因后续拉取顺序改变而切换。

共享组内的节点属性显式保存 `lark_content_role`（`body` 或 `embed`）和 `lark_body_path`（含 `.md` 的库根相对正文路径）。正文文件的 `lark_body_path` 指向自身；嵌入文件除自身属性外，正文部分只保留一行嵌入，直接指向正文文件，不形成嵌入链或循环。例如，社群库的《ChatGPT/Codex安装与配置》使用：

```markdown
![[3.资源/飞书知识库/AI超级个体/工具/ChatGPT／Codex安装与配置]]
```

首次将已有副本改为嵌入前，比较各副本、各自的本地基准与最新远端正文，区分属性和相对链接差异。存在不同的待同步正文修改时，先保留版本并按冲突规则处理，不能用嵌入替换来丢弃改动。保存恢复记录并核验唯一正文和嵌入目标后，再替换副本。

拉取时按实际对象读取正文，每组只更新正文文件；其他节点更新自身元数据并保持嵌入，不重新生成完整正文副本。同步清单为每个节点记录 `content_role`、`body_path` 和实际文件路径；`shared_with` 表示同一远端对象的其他节点路径，不表示存在其他正文副本。各节点的本地基准保留各自的实际表示，远端 XML、Markdown 响应仍配套保存，不能把嵌入语法当成远端正文比较。

从嵌入节点开始编辑时，先解析并核对正文路径、对象标识及关联节点，再按各库配置完成相关知识库的身份核对、完整拉取和冲突检查，最终修改正文文件。检测到嵌入文件中另有手工正文或目标缺失时，先保留并报告，不能直接覆盖。回传针对唯一正文对应的实际对象，每批只回传一次；本地属性和嵌入语法不上传成飞书正文。回传验证成功后更新正文基准及所有关联节点的版本与嵌入基准，报告受影响的知识库。

正文文件移动或改名时，同步更新全部嵌入、`lark_body_path`、清单和基准。删除一个快捷节点不等于删除正文；其他节点仍引用的正文须保留。原节点删除或失去访问权限、跨账号无法核对来源时，保留已有正文，停止依赖它的编辑和回传，先明确新的正文归属。

### 自动生成的同步记录

Agent 将自动生成的同步记录保存在库根相对路径 `<运行目录>/lark-wiki-sync/<space_id>/runs/<run_id>/`：`nodes.json` 保存节点树，`documents/` 保存配套的 XML、Markdown 完整响应，`local-baseline/` 保存转换后的本地基准，`install-manifest.json` 保存文件路径、节点标识、远端版本、文件哈希及完成阶段。正文与 `reference_map` 配套保留，不能只保留 Markdown 而丢弃原始引用信息。

全部核验成功后，才更新同一 `<space_id>/` 下自动生成的 `latest.json`，指向本次清单。后续 Agent 先读取该指针与清单，再比较本地文件和基准；中断或部分成功的记录须先检查实际完成阶段。这些是运行记录，不是另一份手工配置，也不作为可编辑业务内容。

后续自动生成的同步记录使用实例 `<运行目录>/` 运行目录，使用前按[写入与变更](writing-and-changes.md#本机运行记录)核验 Git/FNS 排除。已有 `config/workbench-migration/` 中的实例历史说明继续原位保存，不作为运行数据迁移。运行记录缺失时不能假定本地没有改动，也不能声称另一台设备已经拥有比较基准。

## 开始编辑之前

1. 确认获授权的内容操作及所属知识库，读取其配置并完成身份核对。使用当前可用的 `lark-shared`、`lark-wiki` 及相关文档类型 Skill 核实命令能力，不能把普通云盘文件同步命令当作知识库在线文档同步工具。
2. 先检查本地是否存在尚未回传的修改，以及是否保留了上次成功拉取或回传时的远端原文、版本和节点对应关系。以知识空间 ID、节点 ID 和实际文档标识识别对象，不能只靠标题或路径判断同一文档。
3. 拉取所属知识库的最新节点结构与内容，核对完整结果后再开始内容编辑。范围是该知识库，不能默默缩成只读取本次目标文档。分页、附件或文档类型有遗漏，以及权限不足、网络失败等情况，都须明确报告；拉取未完成时停止该库内容的编辑，不能用旧副本继续并声称已取得最新内容。
4. 将取得的远端内容与本地内容安全比较，按下文处理差异。只在能够保留本地待同步改动、确认目标文件未被其他写入方改变后，才更新本地文件并读回核验。配置文件保持在拉取范围之外。

同一会话继续编辑或开始下一轮编辑时，再检查远端是否变化；重新拉取仍须保留本轮尚未回传的内容，不能用远端副本直接覆盖。首次接入或缺少可靠比较基准时，保留现有本地内容，先核对来源与差异，不能把现有文件直接视为已同步版本。

### 本地与飞书都有修改时

比较三份内容：上次成功同步时保存的原文、本地当前内容、此次取得的飞书内容。远端版本与原文由执行同步的 Agent 或实现保留为恢复和比较记录，不另设一份手工配置；具体保存位置须遵守本库运行记录与附件规则。

| 比较结果 | 操作 |
| --- | --- |
| 本地与基准相同，仅飞书发生变化 | 用最新远端内容更新本地，读回核验 |
| 飞书与基准相同，仅本地发生变化 | 保留本地修改，记录仍待回传 |
| 两端均已修改，但当前内容相同 | 核对后记录相同结果，不重复写入 |
| 两端均已修改，改动互不冲突 | 合并两端改动，核验结果并保留合并依据；合并后的本地内容仍须确认后才回传 |
| 同一内容发生不同修改，或无法判断是否冲突 | 保留两端版本与比较基准，停止相关编辑或回传，列出冲突位置及可选结果，由本人决定 |

节点删除、移动、重命名和附件变化也要比较。远端删除而本地仍有待同步修改时，不能自动删除本地内容；本地删除也不能自动转成远端删除。不能按修改时间较晚的一方直接覆盖另一方，也不能通过更新比较基准绕过未解决的差异。

## 编辑完成与会话收尾

完成获授权的编辑后，读回所有改动文件，核对正文、属性、引用和附件。保留待同步内容及其对应的远端版本，供后续确认回传时重新比较；未取得针对这批具体改动的回传确认时，不写入飞书。

在本次会话的最终回复中列出修改的知识库与文件、未完成项或冲突，并明确告知：

> 文件已编辑，尚未同步到飞书。是否将上述修改同步到飞书？

本人未确认时，保留本地待同步修改，不能把无回复当作同意。部分文件编辑失败时，分别列出已编辑与未完成的文件，只询问已完成部分的回传。配置文件不列入待回传内容。

## 确认回传之后

1. 根据本人确认的文件和操作确定回传范围。确认后又发生的本地修改，须重新列明并取得对应确认；不能顺带上传其他待同步文件。
2. 再次核对 CLI 身份，并读取飞书当前内容与版本，与编辑所依据的远端版本比较。若协作者在此期间修改了文档，先保留两端修改并按冲突规则比较；需要合并而改变了待回传结果时，将新结果交本人确认。
3. 使用相应文档类型支持的写入接口执行已确认修改。优先局部修改，保留图片、评论、附件和未修改内容；无法确认能保留时先说明具体影响，不默认全文重写。版本条件参数是否能够阻止并发覆盖，必须按实际接口能力验证，不能仅凭参数名称承诺。
4. 写入后重新读取飞书内容，核对已确认修改及需要保留的内容。只有读回验证成功的文件才报告“已同步”，并更新供下次比较使用的原文与版本。部分失败、写入状态不明或验证未完成时分别报告，重试前先读实际结果。

已针对这批具体改动取得确认且完成回传验证的，最终回复报告已同步文件及仍待同步项，无需对已完成部分重复询问。编辑前拉取、回传前检查与本机写入协调均不能保证其他设备或协作者在检查后不再修改；无法可靠防止覆盖时，停止回传并说明限制。

## 协作者查询

需要查询某篇文档的协作者时，使用绑定账号和实际文档标识，按 `lark-drive` 的成员与权限查询能力执行。直接列出的成员、群组或部门授权，不等于所有可访问人员；继承权限、链接分享及群组成员需要分别核实。协作者列表也不表示谁正在编辑，不能以列表为空为由跳过版本比较。

## 验收边界

当前由 Agent 调用 CLI 操作，尚无可复用的全自动同步程序。实例的历史拉取证据由实例保留；接入新库时分别验证身份、文档类型、增量比较、回传和恢复，不能用别的知识库的结果替代本库验收。
