# 附件、原文件与临时材料

## 附件保存

任务专属附件必须保存到所属任务目录内。本人指定的任务内位置优先；否则使用 Obsidian 附件设置在任务内解析出的目录，设置指向任务外时改用该任务的 `attachments/`。其他笔记默认使用目标库当时已保存的 Obsidian 附件设置。Agent 直接读取该库配置，不要求打开 Obsidian。本人明确指定目录时只影响本次保存；不因此修改默认设置或迁移既有附件。设置缺失或无法确认时说明缺少什么，不猜测目录。

库根、笔记同目录、笔记下子目录和指定库内目录按实际设置解释。目录属于目标库，不能扩展到私人库、隐藏项、程序、规则、临时或运行数据目录，也不沿符号链接越出库。

保存实际取得的文件，保留原名、扩展名与字节。文件名无法在目标文件系统安全保存时说明具体问题；不把 JSONL 等原文件改成其他扩展名伪装接口支持。同名同内容可以核验后复用，不同内容使用可读序号；不覆盖旧文件。

主笔记保存实际可回查链接，并在 `attachments` 属性登记库内路径。多个材料可以放入用户指定的资料子目录；没有指定时遵循附件设置。辅助 Markdown 不成为另一条 Inbox 输入。保存文件与预览格式是两项能力，预览不支持不能阻止原文件保存。

本机文件复制不受旧 HTTP 请求的大小或扩展名限制。大文件保留方式按下节判断，不把传输接口限制当作全库规则。附件与笔记链接分别核验；附件成功、链接失败时明确报告部分结果与位置，重试先检查已写文件。

## 网盘托管文件

目标库明确采用网盘托管时，纳入格式和同步排除以该库规则为准；安装软件不自动选择百度网盘或纳入 MP3、MP4、MOV、WAV、ZIP。当前支持的替代文件为同目录 `<原文件完整名称>.yaml`，原文件允许在库内保留或按需下载。上传、下载、移动、改名、清理及核验前，先读目标库相应规则，再按[软件网盘契约](cloud-files.md)核对能力并使用 `tt-cloud-files`。

长期引用和主笔记 `attachments` 属性登记替代文件路径，原文件存在时可以附加播放链接。原文件暂未下载不表示附件丢失；YAML 不计作另一条 Inbox 输入。托管附件所在目录移动时同样适用网盘路径联动规则。

## 库外长期资料

未采用逐文件网盘托管的课程视频、采集视频等大文件，仍存放在本人选择的库外目录、外置硬盘或网盘，不进入本库 `tmp/`，不通过本库 FNS 传输。没有真实原文件的设备仍可阅读位置说明、转写与分析。逐文件托管采用上节规则，不能以本节要求阻止其原文件恢复到库内。

在对应课程或 Task 中使用普通 Markdown 登记源文件位置，可使用 `源文件位置.md` 模板。写清设备、硬盘或云盘名称和实际路径/链接；只记录本人提供或已核验的位置。多个位置暂视为同一套源文件的替代入口，不引入版本或完整度管理。位置登记不等于下载、复制、备份、同步或播放已实现。

视频解析已经生成的完整转写及实际用于引用分析的关键截图随 Task 长期保留，可按需设 `关键截图/`。不要求为尚未启动的任务预先生成材料；其他材料是否保留完整原文或逐字稿按具体类型决定。

## 临时文件与保留

仅用于执行步骤、完成后无需保留的辅助文件才归为临时文件；无法判断时先保留。保留要求与 FNS 同步范围分别确定，不能因为体积大、由下载产生或不参加同步就归入 `tmp/`。

单个业务 Task 的临时文件放在该 Task 的 `tmp/<用途>/`；多个 Task 共用时放所属 Project 的 `tmp/<用途>/`。不在库根集中保存业务任务临时文件。这些目录不参加 FNS，写入前按当前设备核验排除配置，其他设备分别核验。

任务结束后不自动清理临时文件。本人提出清理时，先列具体文件并取得确认；位于 `tmp/` 不等于已有删除授权。功能实现的运行锁、重试记录和恢复文件按[写入规则](writing-and-changes.md)的生命周期管理，不当作业务 Task 材料。

归档项目、领域记录或资源时，专属附件和长期证据随对象整包保留，已有临时文件也不因归档自动删除。移动到 `4.存档/` 或恢复时，重新核对本机 FNS 对新路径的临时目录排除；托管文件按网盘规则联动，其他仍在独立使用的资源保持主要位置并更新引用。
