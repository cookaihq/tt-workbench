# 收件箱

一条 Inbox 记录对应一次围绕同一件事保存的内容，可包含多个链接、摘录和想法。未定归属的问题、想法、资料和已有研究记录可以进入收件箱，不要求先分类或填写保存理由。明确补充原记录时追加，无关内容另建，不按会话或消息条数机械划分。

## 目录与身份

收件箱使用 `0.收件箱/`，整理后按实际去向分流。原输入的身份、正文和创建时间随材料保留；历史记录按明确范围迁移，不因读取或修改规则自动处理。

- 手动录入：在 `0.收件箱/` 新建 Markdown，应用模板后书写；不要求条目文件夹或 UUID。
- 程序录入：`0.收件箱/YYYY-MM/<可读标题>/记录.md`。标识放在属性中，不放进新目录名前缀。不同记录同名时增加可读序号，如 `标题 (2)`；同一请求重试先核对已经写入的结果。
- 标题保留原值用于显示；目录名去除路径保留字符，最多取 40 个字符。未提供标题时可用正文首行前 60 个字符，原正文不改写。
- 旧 UUID 目录、手动单文件与新目录共同可读，不批量重命名或迁移。记录身份由 `type: inbox` 表达，不由目录深度或固定文件名决定。
- 已登记在主笔记 `attachments` 中的辅助 Markdown、当前附件设置对应的文件、`源文件位置.md` 和其他明确类型的笔记不计为独立输入。直属缺类型记录提示补模板；嵌套身份不明文件提示核对，不自动改类型。重复 ID 指出路径，不合并。

## 属性与正文

| 属性 | 规则 |
| --- | --- |
| `type` | `inbox` |
| `inbox_status` | 新建 `pending`（待整理）；明确整理后 `reviewed`（已整理） |
| `created` | `YYYY-MM-DD HH:mm:ss` 字符串，记录本次创建时刻 |
| `created_timezone` | 同一时刻的 UTC 偏移，如 `-07:00`，不写死北京时间 |
| `title` | 显示标题；手动笔记可省略 |
| `id` | 程序生成 UUID，手动笔记可省略；追加、读取和同步不重生成 |
| `capture_entry` | 实际录入方式，不当作来源出处 |
| `source_urls` | 可选 http/https 字符串数组，只保存实际提供的链接，不自动抓取网页 |
| `attachments` | 可选的库内附件路径数组，用于回查和区分辅助资料；保留原附件内容 |

实现可以增加不可作为用户业务状态编辑的重试标识或请求摘要。具体字段由实现文档说明。

正文允许只有一句话或 URL；原始输入的空行、缩进和结尾换行保留。没有取得的信息不补造；AI 归纳与本人判断遵守[来源规则](content-and-sources.md)。重复 URL 不自动合并。

读取将创建时间与原 UTC 偏移组合成实际时刻，再按阅读设备时区显示并标明时区，按实际时刻排序。详情保留原值。缺少或无效时间、偏移时提示，不猜测、不补造；读取、同步和补充不重算创建时间。

## 整理与推进

收件箱只保留尚待澄清处理方式的输入。整理后，已决定推进的工作进入项目或项目内任务；持续责任的标准与运行记录进入领域；仅需保存的知识、来源、对象信息和未投入想法进入资源。不设独立待考虑集合。决定保留为资源即可完成澄清，不要求建立任务、开展研究或产生成果。

整理成功须核对材料已到达目标、附件与链接完整，不能只修改 `reviewed` 或隐藏原条目冒充分流。旧记录的 `reviewed` 继续保留为原整理状态，不能据此推断已完成迁移；实际入口支持和历史清单见[重构实施记录](../../.scratch/information-architecture-workflow/spec.md)。

整理状态由本人或明确获授权的 Agent 更新，允许明确范围的批量授权。保存、AI 摘要、来源补充、视频解析或添加附件均不自动改状态。

本人明确将记录转为或归入 Task 时，按[任务资料归属](projects-and-tasks.md#任务资料归属)将原始输入与任务专属附件一起迁入任务目录。迁移成功后收件箱不保留同一套资料副本；原输入、身份、创建时间、来源和整理状态随材料保留，任务有自己的说明与进度。单纯保存、标为已整理或添加引用不触发迁移或启动 Agent。

已有独立归属、供多项工作共用的资料可以只建立引用。界面与 Agent 必须区分“迁入任务”和“仅添加引用”；不能用添加链接代替获授权的资料迁移。

一条输入支持多个工作时，完整原文保留一个主要位置，各项工作分别引用；不能复制多份可编辑原文。迁入项目、领域或资源同样遵守原文版本核对、身份保留、专属附件联动和可恢复迁移规则，不扩大为全库自动整理。
