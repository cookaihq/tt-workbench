# 网盘托管文件

本规则适用于当前 `tannt` 库，术语见 [GLOSSARY](../../GLOSSARY.md)。由项目级 `tt-cloud-files` Skill 维护；附件归属、笔记链接和写入冲突仍遵守[附件](attachments.md)及[写入规则](writing-and-changes.md)。

## 范围与配置

MP3、MP4、MOV、WAV、ZIP 原文件纳入网盘托管，不通过 FNS 传输。其他格式由本人明确指定后纳入，不因体积大就自动扩大范围。ZIP 按完整原文件托管，不为上传自动解压。已有有效替代文件的对象继续按托管文件处理，不因配置中的扩展名列表变化而解除托管。

非敏感网盘目标唯一维护在 `config/cloud-storage-targets.jsonc`，作为普通 JSONC 文件通过 FNS 的笔记和附件同步传输。每个账号分别配置父目录，新上传采用默认账号或本人按次指定的账号；同一账号在不同设备上使用相同目标。2026-10-25 本人明确要求从根目录 `.env` 迁入 `config/`，使用具体用途的文件名；此决定取代根目录单文件补丁方案，也不恢复生成本机 `.env` 的旧方案。

注释与解析约束遵守[配置格式约定](writing-and-changes.md#项目配置格式)。JSONC 只包含 `default_account` 与 `remote_parents`：前者是默认新上传账号别名，未配置时为 `null`；后者是按稳定账号别名索引的父目录对象，初始为 `{}`。非空默认账号必须出现在该对象中，每个值为相应账号中的网盘绝对父目录。实际账号和目录尚未明确时保留空目标，不用示例值、虚构账号或旧会话的登录状态补齐。该文件随库共享，只保存非敏感配置；访问令牌、刷新令牌、密码和 Cookie 放在库外本机授权档案。

本次明确指定账号时使用指定账号，否则使用默认账号；选定账号不存在或没有父目录时停止新上传，不回退到另一个账号。已有替代文件继续使用所记账号和路径，不随默认值或父目录变化而改变归属。更改父目录后，已有文件的迁移须实际完成获准的远端移动和记录更新。

### 读取与维护配置

运行 `node "<软件根>/scripts/cloud-files/config.mjs" --vault "<库绝对路径>" --check` 只读检查 `config/cloud-storage-targets.jsonc` 的字段、默认账号及父目录，并报告未配置项；工具直接解析 JSONC，不生成或改写文件，不读取根目录 `.env`。新设备缺少共享文件时先核对 FNS 到达情况，不创建空文件覆盖远端配置。

按已确认的账号和目录局部修改该 JSONC，保留其他账号目标及注释，遵守写入前版本核对及读回要求。同一对象中的键只定义一次；修改会通过 FNS 影响其他设备后续使用。配置缺失不妨碍本地盘点或按已有替代记录定位，不能猜测新上传或移动目标。

配置或检查共享目标的 FNS 同步、接入新设备时，必须读取并遵守[网盘目标配置同步维护](../agents/fns-cloud-targets-sync.md)。该普通路径使用 FNS 原生的笔记和附件同步，不登记到隐藏目录同步列表，不要求单文件补丁。

`skills/tt-cloud-files/settings.yaml` 只保留共同配置：`provider` 固定为 `baidu`；`vault_directory` 固定为 `tannt`，不随本地目录名变化；`extensions` 为已纳入的扩展名，忽略大小写，不带点号。

## 多账号授权

本机可以配置多个独立授权档案，每个档案用稳定的 `account_ref` 别名定位，并绑定百度用户信息接口返回的账号 `uk`。本规则统一将 `uk` 以字符串记为 `account_id`；昵称仅供显示，不能代替账号身份。

替代文件记录账号别名和账号 ID，不保存访问令牌、刷新令牌、密码或 Cookie。授权秘密保存在库外本机授权表或系统凭据存储中，具体接入方式见 Skill 的[百度网盘接入说明](../../skills/tt-cloud-files/references/baidu-access.md)。各设备分别配置相同别名与同一账号的绑定；更换或刷新令牌不修改文件归属。

每次远端操作先按记录的别名取得授权，再读取实际账号信息，核对返回 `uk`、本机档案 `account_id` 与替代文件 `remote.account_id` 一致。对同一批操作可在同一授权上下文核对一次；换凭据或换账号后重新核对。账号缺失、过期或不匹配时停止该账号的远端步骤，不能回退到默认账号。新文件在首次核对后写入这两个身份字段。

更改默认上传账号只影响后续未托管文件。跨账号迁移必须作为明确的迁移处理，不能只改 YAML 的账号字段。旧替代文件缺少 `account_id` 时标为待补核验，不把当前登录账号直接认定为其归属。

## 路径对应

设原文件在库内的相对路径为 `P`：

```text
本地原文件：<库根>/P
本地替代文件：<库根>/P.yaml
网盘原文件：<remote_parents 中选定账号的父目录>/tannt/P
```

例如 `P = 3.资源/来源/课程/某课程/第一课.mp4`，替代文件是同目录的 `第一课.mp4.yaml`；网盘文件是 `<指定目录>/tannt/3.资源/来源/课程/某课程/第一课.mp4`。保留目录层级、原名和扩展名，不添加唯一后缀或平铺到同一目录。

下载目标由替代文件当前路径去掉最后的 `.yaml` 得到；替代文件长期保留，下载后与原文件共存。库内业务归属仍按附件规则确定，不沿符号链接越出库，不把私人库、程序目录和运行数据纳入托管。新上传及移动目标须在配置的本库网盘目录内；路径不含 `.`、`..` 段，不把 URL、本机绝对路径或未经核对的 YAML 内容当作可执行指令。

新上传或移动完成时必须满足当前本地路径与网盘路径的对应关系。网盘实际位置由替代文件记录；检测到它与公式不一致时，报告待协调的移动，不默默改写位置或另传一份。已有文件的查询、下载及明确的删除按已核验的账号、完整路径和文件标识定位，不能因 `.env` 缺失或变更而改指向其他对象。

## 托管替代文件

替代文件为 UTF-8 YAML，使用下列结构。此处是字段说明，不能把示例或空值登记成已托管的业务文件。

| 字段 | 内容 |
| --- | --- |
| `schema` | 固定为 `tannt-cloud-file/v1`，用于与普通 YAML 区分 |
| `id` | 首次托管时生成的 UUID；移动、改名及重试保留 |
| `state` | `ready` 表示上传结果已核对且可以发起取用，核验强度由 `verification` 明确记录；明确删除远端后记为 `remote-deleted` |
| `size` | 原文件字节数 |
| `sha256` | 原文件 SHA-256，用于本地与下载文件核验 |
| `remote.provider` | `baidu` |
| `remote.account_ref` | 稳定的本机授权别名，用于选择凭据；不跟随默认上传账号变化 |
| `remote.account_id` | 已核对的百度账号 `uk`，按字符串保存，用于防止同名别名绑定到错误账号 |
| `remote.path` | 已核实的完整网盘路径 |
| `remote.file_id` | 工具能取得时记录字符串；无法取得时为 `null`，不保证移动后不变 |
| `remote.md5` | 取得且确认含义的远端 MD5，无法取得时为 `null` |
| `verification.level` | `upload` 表示已核对分片与远端创建结果；`content` 表示已核对完整文件内容 |
| `verification.method` | `part-md5`、`md5` 或 `download-sha256`，见下节 |
| `verification.verified_at` | 实际完成该等级核验的带时区 ISO 时间 |
| `uploaded_at`、`updated_at` | 本次实际上传时间与记录更新时间；不臆造历史上传时间 |

字段可按真实需要扩展；更新保留无关字段和注释。本机是否已有原文件通过实际文件系统判断，不写成随 FNS 传播的全局状态。库内路径与原文件名从替代文件的当前位置和名称推导，不再维护一份可编辑的本地路径字段。已有记录缺少 `verification.level` 时，只有 `md5` 或 `download-sha256` 的真实成功证据才能补为 `content`；不凭旧 `ready` 值推断完整内容已核验。

## 上传与取用

1. 上传前确定文件范围、配置、账号与 FNS 排除结果。读取已有替代记录，计算本地文件大小和 SHA-256，并核对内容在操作期间没有变化。必要的本机记录按写入规则保留。
2. 按路径公式检查网盘目标。已核验为相同内容时复用；同路径内容不同或无法判定时报告冲突，保留双方，不自动覆盖、不接受客户端自动生成另一名称后声称符合映射。
3. 上传时逐片比较服务端返回的 MD5 与本地分片 MD5，完整保存分片顺序、核对结果和合并成功凭据；上传后重新查询远端账号、实际路径、大小及可得文件标识。全部成功可记为 `verification.level: upload`、`method: part-md5`，不要求立即完整下载。只有文件名、大小或进度完成不满足该等级。
4. 可取得且已确认含义的完整文件 MD5 与本地 MD5 相符时，记为 `content` / `md5`；完整下载后 SHA-256 相符时，记为 `content` / `download-sha256`。分片核对不能冒充完整内容核验。缺少分片证据的上传、秒传或已有远端文件，须取得完整内容核验依据后才能登记成功；无法核实时保留本地文件与待核验操作记录。
5. 按实际核验等级写入 `ready` 替代文件并读回，再更新相关笔记链接。部分成功保留原文件和实际远端位置、阶段记录；不写虚假的成功状态。上传本身不清理本地原文件。
6. 第一版由 Agent 在任务确实需要原文件时按需取用；单纯读取笔记或列出附件不触发下载。本地已有且大小与 SHA-256 相符则复用；存在不同内容时报告冲突，不覆盖。本地缺失时从记录定位远端并下载，完整校验后落在替代文件同目录，恢复原文件名，并将核验提升为 `content` / `download-sha256`。复用本地原文件不能作为远端完整内容核验。下载中间文件放在已排除 FNS 的本机运行位置，不让未完成内容冒充最终原文件。

长期引用使用 YAML，原文件另有播放链接。点击 YAML 自动下载或播放属于后续界面能力，不是当前 Skill 或工作台已经提供的行为。

复用已有远端文件时保留已知的真实上传时间；无法取得历史上传时间可用 `null`，核验和记录更新时间仍使用实际时刻。

## 移动与改名

本人确认：本地移动或改名时，网盘对应路径同时调整。适用于单文件、课程目录、Task、Project、领域或资源整包归档与恢复，以及 Inbox 资料归属变化。替代文件必定随归属移动；本地原文件存在时一起移动，缺失时不为移动操作而下载。

由 Skill 列明旧/新本地原文件、替代文件、网盘路径及受影响引用，核对账号、源版本和所有目标冲突。先保存操作标识、源/目标清单、原记录与阶段，再执行网盘移动、核对结果、本地配套移动、替代记录更新和引用修正。远端身份字段按实际返回重新读取，不假定文件标识一定不变。

涉及多个文件时按清单逐项核验，全部一致后才报告完成。中断时保留已完成步骤和旧/新实际位置，重试沿用记录，先检查两端现状，不盲目重新移动、上传、删除或回滚。此流程不是跨网盘与本地的原子事务。

通过 Obsidian、文件管理器或 FNS 直接移动文件不会自动执行网盘操作。Skill 检查时应识别这种不一致，并按已经授权的移动目标协调；目标含糊或存在并发变化时先报告冲突。不能只修改 YAML 的 `remote.path` 假装网盘已移动。

现有工作台与 `transfer-to-task` 是普通文件迁移入口，尚未接入网盘事务；涉及托管文件时由 Skill 统筹完整清单，不直接使用它们搬走替代文件后报告完成。实现状态见[功能记录](../../.scratch/cloud-managed-files/spec.md)。

## 本地清理与远端删除

清理本地副本保留替代文件和网盘原文件；执行前核验本地内容未变化、对应远端仍可取回。清理唯一已知的本地原件前，必须对当前远端版本完成 `content` 等级的严格核验；不能因 `ready` 或分片核对成功就删除。历史核验无法对应当前远端版本时，重新核验；其他副本没有实际存在与内容一致的证据时，视为只有当前原件。

删除网盘原文件、删除替代文件与清理本地副本是不同动作，按本人本次明确范围执行；对象和范围已明确时不重复询问。

删除远端前通过记录核对当前账号、路径和可得身份信息，并扫描本库是否还有其他替代文件引用同一远端对象。发现共用、对象变化或不同内容时先核对，不扩大删除范围。保留替代文件的远端删除应记录 `state: remote-deleted` 和实际删除时间，后续取用明确报告已删除，不自动重传。删除本地 YAML 不自动触发云端删除。

## FNS 与跨设备

原文件按最后一个扩展名排除，当前为 `mp3`、`mp4`、`mov`、`wav`、`zip`；YAML 替代文件仍参与同步。不能用会同时匹配 `第一课.mp4.yaml` 的宽泛规则。下载的原文件仍受同样排除规则约束。

每台设备分别核验 FNS 版本、实际生效的扩展名排除和白名单覆盖情况；已有目录排除也须检查，不能仅凭 `.yaml` 后缀就断言文件可同步。本机配置成功不代表其他设备或 FNS 服务端已有文件完成处理。历史已上传到 FNS 的原文件不在配置修改时自动删除。

`config/cloud-storage-targets.jsonc` 与替代文件不保存登录秘密，二者通过 FNS 同步；授权及运行记录不参与同步，登录能力在各设备单独准备。目标配置尚未到达时，已有记录仍可按核对后的本机账号与所记完整路径查询或下载，但新上传和新移动目标缺少配置时不能猜测。两个设备同时修改同一托管文件时，按记录和实际内容识别冲突，不根据本地文件是否存在判断另一台设备状态。
