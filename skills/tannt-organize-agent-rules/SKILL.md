先读取 `<软件根>/docs/agents/package-layout.md`。从本 Skill 的真实路径（解析发现链接后）向上两级得到 `<软件根>`；下文 `docs/`、`scripts/` 等指软件资源，业务路径和 `config/` 指用户明确的目标知识库。读取目标库实际 Agent 入口，命令显式传 `--vault "<库绝对路径>"`，不以软件目录推断目标库。

## 确认目标与事实

1. 确认实际目标库、可写的正式规则源、当前宿主及版本、系统、用户目录、实际配置目录和本次授权阶段。读取目标库的 `AGENTS.md` 及软件根的 `GLOSSARY.md`、`docs/rules/scope-and-directories.md`，以及 `<规则源>/README.md` 和 `<规则源>/scenarios-agent-instructions/maintaining-agent-instructions-and-project-rules.md`。后两者来自本人确认的知识库或规则仓库；工作台软件包不含个人正文。缺少已确认源或维护说明时先定位或确认，保留现有入口。
2. 按全局说明的“已有全局指令的评估与迁移”逐项检查主入口、共用场景入口、覆盖文件、真实源、内容版本和必要引用。页面提示词中的项目、宿主、路径与状态均重新核查；明确选择的宿主作为范围，页面观察不作为当前事实或变更批准。
3. 分别记录文件类型、原链接文字目标、直接目标、最终真实目标和可读性。以文件系统事实区分普通文件（即使同文）、直接链接、间接链接、其他目标、断链、缺失及未知。检查失败只阻止依赖该项的动作，其他独立结果保留。

从实际进程及宿主配置核对 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`；默认目录只是未自定义时的候选。安装器不支持自定义位置时，报告该限制，继续检查真实位置；依据具体获准方案使用原生文件工具处理已确认入口，再人工核验直接目标和加载，不能清空变量或检查默认目录冒充成功。

## 选择分支

| 事实 | 下一步 |
| --- | --- |
| 主入口未直接链接正式源 | 读取旧正文及必要场景，进入条款分析与方案 |
| 主入口正确，场景入口缺失、断链、目标不符或被旧目录占用 | 保持主文件正文和链接，核查场景旧内容与依赖，提出仅修复场景入口的方案；发现确需合并的具体条款时再追加内容方案 |
| 两项入口正确但被覆盖或无法读取 | 只处理对应遮蔽、权限或读取问题 |
| 来源或入口状态未知 | 列明已知事实、原因和待核查项，保留未知内容 |
| 入口正确且内容清楚完整 | 报告事实，无需重新拆分或迁移 |

## 澄清与审阅

按正式迁移流程逐条记录原文来源、适用对象、条件、动作和结果。事实先核查；含糊条款给出原文、不同解释、推荐及行为影响，按依赖分轮确认，沿用本会话已经确认且未变化的解释。

以是否需要所有会话加载划分全局主指令与场景指令。复用已有适用正文；冲突展示双方，设备／系统／宿主条件随条款保留；项目专属条款标明归属和待处理位置，跨项目写入依具体授权。

按全局说明的“只读核对与条款去向”形成可审阅方案，并执行其中的授权与部分批准要求。进入写入阶段的完成条件：本次动作有具体授权，受入口切换影响的每条要求都有获准去向；否则保留原入口，继续独立的获准部分。

## 获准后执行

先读取 `docs/rules/writing-and-changes.md`，依全局说明的“获准后的迁移与恢复”执行版本复核、恢复材料核验、正式源写入、旧入口处置和直接建链；逐步记下前后版本、已完成动作与恢复依据。已有具体授权继续有效，只有新增动作或变化的差异需要补充确认。

复用安装器时，显式指定已确认的正式规则源与宿主，安装与复查范围一致：

```text
node "<软件根>/scripts/global-agent-instructions/install.mjs" --source "<正式规则目录>" --agent codex
node "<软件根>/scripts/global-agent-instructions/install.mjs" --source "<正式规则目录>" --agent codex --check
```

Claude Code 将参数值改为 `claude`。明确同时处理两个宿主才使用 `--agent all`。安装器只安装、检查和有限回滚链接；普通文件归档、语义合并和实际加载由本流程负责。入口只需部分修复且安装器被其他未决项阻止时，按已批准的独立动作使用原生工具并逐项核验，保留正确入口和原链接目标文件。单宿主操作保留另一宿主可能依赖的旧共享中间入口。

Windows 链接类型、权限失败、中断及重试，执行“获准后的迁移与恢复”对应要求。每步以现场读回结果及恢复记录为依据，再决定继续、保留或安全恢复。

## 验证与交付

执行全局说明“获准后的迁移与恢复”末尾的文本、路径、库外新会话与场景行为验证，按其中列明的阶段逐项交付证据、备份位置和剩余范围。只有相应证据齐全才报告该阶段完成。

页面用户操作后可刷新事实；页面不会执行 Skill 或保存审批状态。
