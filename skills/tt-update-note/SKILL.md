---

从本 Skill 的真实路径（解析发现链接后）向上两级得到 `<软件根>`。先读取并执行 `<软件根>/docs/agents/package-layout.md` 的“目标库规则读取”：确认用户指定的库，沿该库实际 Agent 入口读取本次主题规则。下列业务规则均指该入口选定的正文；软件说明仅提供工具契约。命令显式传 `--vault "<库绝对路径>"`。

1. 确定目标笔记和本次获授权的变化，读取该库范围与目录、写入与变更规则。从实际文件读取完整原文；目标不唯一时先搜索与辨认，不猜测路径，不要求打开 Obsidian。
2. 按操作补读该库规则：收件箱分流与状态、项目任务属性、内容来源与判断、附件、存档与恢复。涉及网盘托管文件、YAML 替代文件或其所在目录的移动、改名时，另读该库网盘规则，由 `tt-cloud-files` 维护远端与本地对应关系；飞书同步单元先执行该库飞书编辑与同步场景。各主题路径由实际入口决定，不固定为软件 `docs/rules/`。
3. 只修改已授权内容。可用 `node "<软件根>/scripts/vault/write.mjs" --vault "<库绝对路径>"` 的 `update` 或 `attach`；调用字段、支持格式、正文替换与重试流程见 `<软件根>/docs/agents/vault-file-operations.md`。先核对工具与目标规则相容，缺项或冲突按前述读取流程处理。提交刚读取的完整原文作为 `expected`，不要在命令行拼接正文。
4. 更新后直接读回文件，核对指定变化、未涉及属性、创建时间及正文。附件还需核对原字节与链接。多记录操作分别报告结果，不联动其他记录状态。
5. 检测到原文变化时保留拟写内容并指出冲突位置，不替换原文快照强制重试。没有成功更新原笔记就报告未完成；另存副本、附件已复制或工作台能显示，都不能替代原操作结果。

用户明确要求从收件箱创建或归入任务时，另读该库任务资料归属和附件规则。规则与工具相容时，使用 `<软件根>/docs/agents/vault-file-operations.md` 的 `create-task`（确需新建时）与 `transfer-to-task` 流程，将原记录和专属资料一并迁入，核对附件字节、来源身份与时间、任务中的实际链接及源文件移除结果。共享资料引用与资料迁移分别报告。迁移失败时沿用恢复记录及已建任务；不能用普通 `update` 改类型、只加链接或保留分散副本来代替迁移。本 Skill 不自行决定创建任务或启动研究。

分流到项目、领域或资源，以及归档或恢复整包内容时，先按文件操作说明核对实际可用入口和字段；未覆盖的操作使用符合该库规则的迁移工具，不猜测命令。当前软件创建任务要求指定项目，完成或暂停不自动归档；目标规则若不同，先说明能力冲突。保留源/目标清单、原版本和恢复位置，读回文件并核对附件与引用后才报告完成；普通迁移不能绕过网盘、飞书同步或共享附件检查。
