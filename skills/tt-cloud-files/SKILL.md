从本 Skill 的真实路径（解析发现链接后）向上两级得到 `<软件根>`。先读取并执行 `<软件根>/docs/agents/package-layout.md` 的“目标库规则读取”：确认用户指定的库，沿该库实际 Agent 入口读取本次主题规则。下列业务规则均指该入口选定的正文；软件说明仅提供工具契约。命令显式传 `--vault "<库绝对路径>"`，工具的 `scripts/`、`lib/` 路径相对于软件根。

## 入口

先读目标库入口指明的范围与目录、附件、网盘托管、写入与变更规则。由这些规则确定纳入格式、路径映射、生命周期和同步要求；从软件 `<软件根>/docs/rules/cloud-files.md` 核对支持的替代文件格式及工具限制，差异按前述读取流程处理。读取本 Skill 同目录的 `settings.yaml` 了解服务支持，它不提供实例网盘目录或纳入格式。新上传／移动所用的库网盘目录由目标库规则或本次明确选择确定，不使用固定 `tannt` 或本地库名推断；已有记录沿用经核验的身份与完整路径。

通过 `node "<软件根>/scripts/cloud-files/config.mjs" --vault "<库绝对路径>" --check` 只读核对该库 `config/cloud-storage-targets.jsonc` 中的共享目标；直接解析 JSONC，不执行文件内容。该文件不含凭据，采用 FNS 的库按自己的规则同步；不读取或生成根目录 `.env`。配置或必要规则缺失不妨碍独立的只读盘点，但不能猜测新上传或移动目标，也不以软件规则补齐实例选择。

涉及目标库的飞书同步单元（含其规则覆盖的迁移旧位置）时，先执行该库飞书编辑与同步规则。涉及 Inbox 分流、整包归档或恢复时，联合 `tt-update-note`，由本 Skill 统筹托管部分的源/目标清单；不要直接使用普通迁移入口移动 YAML 后宣称网盘也已调整。

## 先检查实际能力

识别本次需要的操作及文件范围。复用会话中已经明确的账号、路径、授权与取舍；仅询问缺少且会改变结果的信息。

配置授权或执行远端操作前，读取[百度网盘接入说明](references/baidu-access.md)。本机授权使用 `scripts/cloud-files/accounts.mjs` 的保存与检查流程；优先复用已经实测的官方 MCP 查询与官方 API 传输方式。其他本机工具先读其帮助或对应技能，逐项核对当前账号及本次所需能力。按共同规则选择授权档案并校验账号身份，每个操作上下文固定自己的凭据，不用共享的临时默认账号切换承载多账号并行操作。

新上传使用本次指定账号或共享默认账号，并取该账号自己的父目录；已有文件沿用替代记录的账号与路径。显式选择失败时不回退默认账号。实际账号、父目录或默认选择缺失时，仅补充本次必需的信息；账号 ID 通过授权后的接口核验，不让用户手填，也不从旧会话猜测。

缺少工具、登录或新上传目标时继续本地盘点与计划，将不能执行的步骤明确留待补齐；不臆造工具命令、不从无关配置或旧会话中提取令牌、不把链接可打开当作传输已成功。前次传输成功不表示本机已保存可复用授权。

本 Skill 是 Agent 执行流程，不提供后台监听或自带网盘登录。目录变化由使用本 Skill 的操作处理；人工或 FNS 变化在检查时发现。

## 按请求执行

| 请求 | 动作 |
| --- | --- |
| 列出、检查 | 在授权的库内业务范围找已纳入扩展名原文件和 YAML，解析 `schema: tannt-cloud-file/v1`，区分未托管、本地缺失、内容变化、路径不一致、远端待核验、已删除。普通 YAML 不当作替代文件。只读请求不写入、不上传、不补下载。 |
| 上传、纳入托管 | 检查该库同步要求、选定账号及其父目录；计算映射和流式哈希；核对远端重名；上传并按规则记录分片或完整内容核验等级；创建或更新替代记录并读回；维护长期引用。 |
| 使用、下载 | 对照替代记录检查本地原文件；匹配则复用，缺失则下载并校验后恢复到同目录，冲突则保留现场。 |
| 移动、改名 | 扫描完整受影响范围及引用，记录旧/新路径清单；核对并移动网盘文件，再配套处理本地原文件（若有）、YAML 和引用；逐项核验两端一致。 |
| 释放本地空间 | 按已明确范围核验云端与本地内容；清理唯一已知本地原件须满足当前远端版本的完整内容核验；保留 YAML 和远端。 |
| 删除托管文件 | 先根据本次指令辨认删除范围；按 YAML 核对实际远端对象及其他引用，再执行明确的本地/云端删除和记录更新。 |

其他格式仅在用户明确指定后纳入，并核验该库适用的同步排除；不把扫描到的全部二进制文件都上传。未登录或未查询的远端状态标为“待核验”，不能凭 YAML 断言文件仍在网盘。

## 文件写入与恢复

使用仓库已有的 `lib/vault/vendor/yaml/dist/index.js` 或环境中可靠的 YAML 解析器；读完整原文后局部更新，保留注释、未知字段、身份和原时间。`scripts/vault/write.mjs` 的业务笔记更新入口只支持 Markdown，不用它改写 YAML。

先用 `node "<软件根>/scripts/workbench/runtime-storage.mjs" --vault "<库绝对路径>" --check` 读取本实例 `current` 作为 `<运行目录>`。本机操作记录放 `<运行目录>/vault-io/cloud-files/<操作标识>/`，软件约束见 `<软件根>/docs/rules/writing-and-changes.md` 的“本机运行记录”，同时遵守目标库适用要求；使用 FNS 时核验该设备排除。上传、下载、移动和删除按实际阶段记录目标、源版本、结果及恢复所需信息，不写入登录秘密。新建不覆盖已有不同内容；写入前复核版本，完成后读回。优先复用 `VaultFiles.safe`、`withLock`、`exclusiveFile`，但它们不替代业务范围、YAML 格式及远端身份检查，也不提供跨设备事务。

本地原文件与恢复材料依照用户已有授权处理。重试首先读取同一操作记录和两端现状；保留有冲突的文件，报告明确的已完成阶段与未完成阶段，不用换操作标识掩盖未完成事务。

## 完成依据

报告实际原文件、替代文件、所属账号及网盘位置，所做动作与核验等级。路径移动必须核对网盘新位置、YAML 记录、存在的本地原文件以及相关引用；上传完成必须有符合规则的分片或完整内容核验和 YAML 读回。区分本机配置、实际远端操作和跨设备同步的验证范围。
