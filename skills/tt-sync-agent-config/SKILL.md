name: tt-sync-agent-config
description: 按目标知识库的配置清单核对当前 Agent，检查本机 FNS 普通配置，差异经用户允许后应用并复查。首次或更新清单后直接发送名称即可。
---

先读取 `<软件根>/docs/agents/package-layout.md`。从本 Skill 的真实路径（解析发现链接后）向上两级得到 `<软件根>`；下文 `docs/`、`scripts/` 等指软件资源，业务路径和 `config/` 指用户明确的目标知识库。读取目标库实际 Agent 入口，命令显式传 `--vault "<库绝对路径>"`，不以软件目录推断目标库。

FNS 完整运行配置保留在本机插件目录的普通 `data.json`，不自动外移或建链。完整配置（含各设备自己的 Token）只在明确发布时生成 Git 快照；应用仍只替换四组共享规则，不借用另一设备身份。旧链接按 `docs/agents/fns-device-config.md` 检查，在获准后迁回。

本 Skill 管理配置清单中的运行时、项目 Skill 发现、工作台、FNS、飞书与网盘配置。正常读取并遵守适用规则；Agent 规则的检查、整理、迁移、入口修复和加载验证均不属于本流程，也不自动转交或调用其他规则 Skill。网盘非敏感目标唯一维护于 `config/cloud-storage-targets.jsonc`，通过 FNS 普通文件同步；凭据各设备独立准备。

1. 读取目标库的 `AGENTS.md`、`docs/rules/scope-and-directories.md`、目标库 `config/agent-config-checklist.md`（尚无清单时先按 `docs/agents/agent-config-checklist.md` 确定目标） 和 `docs/agents/agent-config-sync.md`。每次重新读取本机已收到的目标清单及相关源，按执行流程做简易文件检查；缺失、冲突或检查后变化时停止相关修改。不沿用上次会话的清单或另一台电脑的通过结果，也不以本机检查证明远端最新版本或整批同步完整。
2. 每次执行先读取并遵守 `docs/agents/fns-device-config.md`，运行设备配置检查。普通 `data.json` 留在本机插件目录；旧链接报告待迁回，缺文件则提示安装 FNS，不生成或借用配置；断链、错设备和目标冲突分别报告。单独名称只启动只读检查，不修改其他设置或发现入口，不为检查写测试文件。逐条报告当前 Agent、目标、结果及依据，区分符合、不符合、无法验证、不适用；不因本次没使用某功能跳过已纳入项，不改清单迎合本机现状。
3. 对差异先给出具体修改项、影响范围与验收方式，再取得用户允许；允许部分时只应用那部分。已有明确覆盖当前环境和动作的授权继续沿用，不重复确认。清单更新或另一台设备的许可不自动等于本次修改许可。
4. 应用前重读本次依据的清单、旧配置和自身配置工作所需资料；若目标或原文变化，更新差异，新增动作取得对应许可。复用项目 Skill 安装器时显式指定当前宿主 `--agent codex` 或 `--agent claude`。工作台安装器的 `--check` 与 `--help` 只读；插件安装和 Skill 注册分别执行。 首次未注册时由项目指令读取本文件，发现入口也在用户允许后建立。
5. 复查保持同一宿主范围，核对配置文件、项目 Skill 实际发现及适用功能，报告完成项、未通过项和必要的登录／重载操作。不把配置文件一致或本机通过称为另一台已同步完成。
