开始执行时，从本次加载的 SKILL.md 元数据读取 `name` 和 `metadata.version`，向用户提示“正在使用 <name> v<version>”。版本只取本文件；已有会话保留的旧内容不能冒称已加载磁盘新版。

解析发现链接得到本 Skill 真实目录。存在同目录 `skill-package.json` 时，`<软件根>` 为同目录的 `runtime/`；源码开发时才向上两级取软件根。先读取并执行 `<软件根>/docs/agents/package-layout.md` 的“目标库规则读取”：确认用户指定的库，沿该库实际 Agent 入口读取本次主题规则和配置场景。下文软件流程均显式标明 `<软件根>`；目标库的清单、规则及场景按其入口解析。命令显式传 `--vault "<库绝对路径>"`。

FNS 完整运行配置保留在本机插件目录的普通 `data.json`，不自动外移或建链。完整配置（含各设备自己的 Token）只在明确发布时生成 Git 快照；应用仍只替换四组共享规则，不借用另一设备身份。旧链接按 `<软件根>/docs/agents/fns-device-config.md` 核对工具能力，同时遵守目标库场景，在获准后迁回。

本机文件排除通过 `<软件根>/scripts/fns/sync-request.cjs` 的 `local-check` 检查，按上述设备配置规则在获准后使用 `configure-local`。本机检查不依赖发布历史或 Git 远端；读取到旧权威版本不代表它符合当前设备的应用条件。

本 Skill 管理配置清单中的运行时、项目 Skill 发现、工作台、FNS、飞书与网盘配置。正常读取并遵守适用规则；Agent 规则的检查、整理、迁移、入口修复和加载验证均不属于本流程，也不自动转交或调用其他规则 Skill。网盘非敏感目标维护于目标库 `config/cloud-storage-targets.jsonc`，同步方式按该库选择；凭据各设备独立准备。

1. 读取目标库入口要求的范围及配置场景、该库 `config/agent-config-checklist.md`，再读 `<软件根>/docs/agents/agent-config-sync.md` 核对执行能力。尚无清单时用 `<软件根>/docs/agents/agent-config-checklist.md` 的结构帮助用户确定目标，不直接采用软件或其他实例的选值。每次重新读取本机已收到的目标清单及相关源；缺失、冲突或检查后变化时停止相关修改。不沿用上次会话的清单或另一台电脑的通过结果，也不以本机检查证明远端最新版本或整批同步完整。
2. 对清单已纳入的 FNS，读取目标库适用场景及 `<软件根>/docs/agents/fns-device-config.md`，运行设备配置检查；未纳入项不由软件默认开启。普通 `data.json` 留在本机插件目录；旧链接报告待迁回，缺文件则提示所缺条件，不生成或借用配置；断链、错设备和目标冲突分别报告。单独名称只启动只读检查，不修改其他设置或发现入口，不为检查写测试文件。逐条报告当前 Agent、目标、结果及依据，区分符合、不符合、无法验证、不适用；不因本次没使用某功能跳过已纳入项，不改清单迎合本机现状。
3. 对差异先给出具体修改项、影响范围与验收方式，再取得用户允许；允许部分时只应用那部分。已有明确覆盖当前环境和动作的授权继续沿用，不重复确认。清单更新或另一台设备的许可不自动等于本次修改许可。
4. 应用前重读本次依据的清单、旧配置和自身配置工作所需资料；若目标或原文变化，更新差异，新增动作取得对应许可。复用项目 Skill 安装器时显式指定当前宿主 `--agent codex` 或 `--agent claude`。工作台安装器的 `--check` 与 `--help` 只读；插件安装和 Skill 注册分别执行。 首次未注册时由项目指令读取本文件，发现入口也在用户允许后建立。
5. 复查保持同一宿主范围，核对配置文件、项目 Skill 实际发现及适用功能，报告完成项、未通过项和必要的登录／重载操作。不把配置文件一致或本机通过称为另一台已同步完成。
