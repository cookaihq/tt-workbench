开始执行时，从本次加载的 SKILL.md 元数据读取 `name` 和 `metadata.version`，向用户提示“正在使用 <name> v<version>”。版本只取本文件；已有会话保留的旧内容不能冒称已加载磁盘新版。

解析发现链接得到本 Skill 真实目录。存在同目录 `skill-package.json` 时，`<软件根>` 为同目录的 `runtime/`；源码开发时才向上两级取软件根。先读取并执行 `<软件根>/docs/agents/package-layout.md` 的“目标库规则读取”：确认用户指定的库，沿该库实际 Agent 入口读取本次主题规则。下列业务规则均指该入口选定的正文；软件说明仅提供工具契约。命令显式传 `--vault "<库绝对路径>"`。

1. 核对实际目标库与本次保存范围，读取其范围与目录、内容与来源、写入与变更规则。Obsidian 是否运行不影响文件保存；按已获授权的文件访问条件继续。
2. 未定归属时读取该库收件箱规则，按其规定保存；归属明确则就地保存。目录、分类和是否建立工作记录由该库规则及本次授权确定。输入已明确时直接处理；只有会改变保存对象或内容的缺失信息才询问。普通保存不自动创建工作或改变状态。
3. 有附件或原会话文件时读取该库附件规则，核实实际来源文件。按该库网盘托管规则已纳入的格式及已有替代记录的文件交由 `tt-cloud-files`；普通附件复制不代表网盘托管已经完成。按用户要求保存原文件及链接；未取得的材料明确列出，不用摘要代替。多份材料与主笔记的关系按规则表达；涉及飞书同步内容时先执行该库相应场景。
4. 根据场景选择工具。可复用入口为 `node "<软件根>/scripts/vault/write.mjs" --vault "<库绝对路径>"`，完整字段与部分失败处理见 `<软件根>/docs/agents/vault-file-operations.md`；先核对其五目录、格式等能力与目标规则相容，也可用符合规则的文件操作。命令直接读写本库文件，不需要工作台接口；规则缺项或能力冲突按前述读取流程处理。
5. 读回主笔记，核对附件字节及实际链接，逐项报告保存位置和缺少的材料。失败重试先核对已有结果；部分完成须指出具体文件和未完成步骤。完成依据是实际文件结果，不等待工作台打开。

已有任务的专属新资料按该库项目任务与附件规则保存。用户要求把已有 Inbox 记录归入任务时使用 `tt-update-note` 的迁移流程，不另存一份输入。
