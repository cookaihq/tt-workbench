开始执行时，从本次加载的 SKILL.md 元数据读取 `name` 和 `metadata.version`，向用户提示“正在使用 <name> v<version>”。版本只取本文件；已有会话保留的旧内容不能冒称已加载磁盘新版。

解析发现链接得到本 Skill 真实目录。存在同目录 `skill-package.json` 时，`<软件根>` 为同目录的 `runtime/`；源码开发时才向上两级取软件根。先读取并执行 `<软件根>/docs/agents/package-layout.md` 的“目标库规则读取”：确认用户指定的库，沿该库实际 Agent 入口读取本次适用的范围、规则维护场景及概念。软件根用于工具，个人全局正文来自明确选择的 `<规则源>`；两者均不能代替目标库自己的规则。

## 确认目标与事实

1. 确认实际目标库、可写的正式规则源、当前宿主及版本、系统、用户目录、实际配置目录和本次授权阶段。读取目标库实际入口指明的规则和所需概念，以及 `<规则源>/README.md` 和 `<规则源>/scenarios-agent-instructions/maintaining-agent-instructions-and-project-rules.md`。后两者来自用户确认的知识库或规则仓库；工作台软件包不含个人正文。缺少已确认源或维护说明时先定位或确认，保留现有入口。项目规则与全局规则的适用范围冲突时先指出具体条款，沿用已有明确决定，不用软件术语表替换目标库概念。
2. 按全局说明的“已有全局指令的评估与迁移”逐项检查主入口、共用场景入口、覆盖文件、真实源、内容版本和必要引用，识别主文件通过链接、导入或文字路径引用的外部规则文件。页面提示词中的项目、宿主、路径与状态均重新核查；明确选择的宿主作为范围，页面观察不作为当前事实或变更批准。
3. 分别记录文件类型、原链接文字目标、直接目标、最终真实目标和可读性。以文件系统事实区分普通文件（即使同文）、直接链接、间接链接、其他目标、断链、缺失及未知。检查失败只阻止依赖该项的动作，其他独立结果保留。

从实际进程及宿主配置核对 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`；默认目录只是未自定义时的候选。安装器不支持自定义位置时，报告该限制，继续检查真实位置；依据具体获准方案使用原生文件工具处理已确认入口，再人工核验直接目标和加载，不能清空变量或检查默认目录冒充成功。

## 选择分支

| 事实 | 下一步 |
| --- | --- |
| 主入口未直接链接正式源 | 读取旧正文及必要场景，进入条款分析与方案 |
| 主入口正确，场景入口缺失、断链、目标不符或被旧目录占用 | 保持主文件正文和链接，核查场景旧内容与依赖，提出仅修复场景入口的方案；发现确需合并的具体条款时再追加内容方案 |
| 两项入口正确但被覆盖或无法读取 | 只处理对应遮蔽、权限或读取问题 |
| 来源或入口状态未知 | 列明已知事实、原因和待核查项，保留未知内容 |
| 入口正确且内容清楚完整 | 报告事实，无需重新拆分或迁移 |

## 评估旧条款与外部引用

本机既有的 `AGENTS.md`、其他主文件和外部引用都是待评估来源，不默认其中所有规则合理或应继续保留。按条款记录原文来源、适用对象、条件、动作和结果，与用户当前要求、实际环境及正式规则逐项比较，提出有依据的取舍：

| 建议 | 判断与说明 |
| --- | --- |
| 保留 | 仍有实际用途、含义明确且适用范围合理；说明价值及对应正式正文，已有同义条款时复用 |
| 丢弃 | 已失效、被有效规则取代、无实际用途或造成不合理约束；说明依据及退出后的行为影响，去重须指出仍承载有效要求的正文 |
| 更新 | 目标仍有必要，但表述含糊、条件失准、内容冲突或做法过时；给出原文、拟写正文及理由，区分结构调整与行为变化 |
| 待澄清 | 来源不可读、事实不足或取舍依赖用户决定；列出缺口与可判断部分，不默认为保留或丢弃 |

发现外部规则引用时，解析并读取实际源文件及理解条款所需的下级规则引用，记录来源、版本和读取关系；未知项按待澄清处理。把外部正文拆成可分别判断的条款，纳入同一评估，再按下节组织主指令与场景指令。不能把外部文件整份复制、改名搬入或原样接成链接当作整理完成；原文件边界不决定最终场景边界。

事实先核查；含糊条款给出原文、不同解释、推荐及行为影响，冲突展示双方，按依赖分轮澄清，沿用本会话已经确认且未变化的决定。保留尚未获准改动的现场，不等于建议永久保留其规则；提出丢弃或更新建议，也不等于已获准停用或改写。

## 组织正文与汇总方案

按评估结果组织拟保留及更新的内容：

- **全局主指令**：需要所有会话加载的跨项目共同要求写入 `<规则源>/AGENTS.md`；主文件同时保留简短的场景读取入口。
- **全局场景指令**：仅在特定条件下适用的详细规则，全部统一维护在已确认规则仓库的 `<规则源>/scenarios-agent-instructions/`，包括从外部引用重组的正文。优先合并到已有适用场景，无适用场景才新建；按实际主题命名，允许将一个外部文件拆入多个场景，或将多个来源合并。主文件写明触发条件、读取时机、`~/.agents/scenarios-agent-instructions/<主题>.md` 路径与执行要求。
- **范围与依赖**：设备／系统／宿主条件随有效条款保留；项目专属条款标明归属与待处理位置，跨项目写入依具体授权。场景仍需调用外部 Skill、脚本或工具时，保留必要的实现引用，规则正文集中维护；工作台软件目录、用户配置目录或原外部文件不充当另一份场景正文源。

向用户先给出以下汇总；每项写明具体文件或条款及原因，没有建议的类别明确写“无”，未能判断的部分另列待澄清：

| 汇总项 | 必须说明的内容 |
| --- | --- |
| 建议新建的场景规则文件 | `<规则源>/scenarios-agent-instructions/` 下的具体文件名、来源条款、触发条件、拟写内容，以及为何需要新建而非复用已有场景 |
| 建议丢弃的原有规则 | 来源及原文、丢弃理由、退出后的行为影响；明确是取消要求，还是去除已有正式正文覆盖的重复内容 |
| 建议更新的原有规则 | 来源及原文、拟写正文或具体差异、目标主文件／已有场景、更新原因及适用范围变化；拆入新场景时关联对应新建项 |
| 建议保留的原有规则 | 来源及原文、保留原因、最终位置或复用的正式条款；保留有效要求不等于保留原文件布局 |

在汇总后按全局说明的“只读核对与条款去向”补齐受影响的主文件入口、场景引用、旧外部文件及链接的具体处置、影响范围、恢复办法和验收方式。旧路径兼容入口仅在仍有具体使用方需要时提出并说明原因，不能代替正文重组。进入写入阶段的完成条件：本次动作有具体授权，受入口切换影响的每条要求都有获准去向，包括明确获准丢弃；否则保留原入口，继续独立的获准部分。

## 获准后执行

先读取规则源所属项目及目标库本次适用的写入与变更要求，依全局说明的“获准后的迁移与恢复”执行版本复核、恢复材料核验、正式源写入、旧入口处置和直接建链；逐步记下前后版本、已完成动作与恢复依据。已有具体授权继续有效，只有新增动作或变化的差异需要补充确认。

复用安装器时，显式指定已确认的正式规则源与宿主，安装与复查范围一致：

```text
node "<软件根>/scripts/global-agent-instructions/install.mjs" --source "<正式规则目录>" --agent codex
node "<软件根>/scripts/global-agent-instructions/install.mjs" --source "<正式规则目录>" --agent codex --check
```

Claude Code 将参数值改为 `claude`。明确同时处理两个宿主才使用 `--agent all`。安装器只安装、检查和有限回滚链接；普通文件归档、语义合并和实际加载由本流程负责。入口只需部分修复且安装器被其他未决项阻止时，按已批准的独立动作使用原生工具并逐项核验，保留正确入口和原链接目标文件。单宿主操作保留另一宿主可能依赖的旧共享中间入口。

Windows 链接类型、权限失败、中断及重试，执行“获准后的迁移与恢复”对应要求。每步以现场读回结果及恢复记录为依据，再决定继续、保留或安全恢复。

## 验证与交付

执行全局说明“获准后的迁移与恢复”末尾的文本、路径、库外新会话与场景行为验证，按其中列明的阶段逐项交付证据、备份位置和剩余范围。只有相应证据齐全才报告该阶段完成。

逐项回查汇总中的条款去向、拟写正文和实际结果，确认纳入本次整理的全局场景正文均位于 `<规则源>/scenarios-agent-instructions/`，有效读取入口指向统一场景，获准丢弃的内容未从旧引用继续加载。最终回复保留上述四类汇总及理由，并标明各项是建议、已执行还是未完成；仅出方案时不报告迁移或加载完成。
