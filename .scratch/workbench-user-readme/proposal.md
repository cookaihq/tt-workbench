# 面向用户的 README 改写提案

- 日期：2026-10-29。
- 状态：用户已确认本方案；实施结果见[实施记录](implementation.md)。下文保留评审时的拟稿与当时安装包缺项，不作为最新安装指引；当前用户入口为根 README。
- 参考：[插件仓库调研](research.md)。

## 已理解的需求

1. 根 README 面向使用工作台的人，先说明用途、安装与第一次使用。
2. 普通用户使用维护者准备好的成品，安装流程不要求克隆源码、安装构建环境、运行测试或构建。
3. 安装提供两个并列入口：手动下载并解压完整包；复制提示词让有本机文件访问能力的 Agent 帮忙安装。
4. 测试、构建、发布与内部实现说明放入开发文档，根 README 保留简短链接。

## 推荐首页结构

1. **一句话介绍**：在 Obsidian 中收集笔记、管理项目与任务，并为 Agent 提供配套 Skill。
2. **能做什么**：收集与整理、项目与任务、笔记阅读与编辑、Agent 协作；使用真实界面截图展示核心流程。
3. **安装**：支持的 Obsidian 版本与桌面端范围；手动安装与 Agent 安装提示词。
4. **开始使用**：启用插件 → 打开工作台 → 保存一条随手记或查看已有笔记；Skill 按需单独安装。
5. **更新**：点击工作台版本号、设置公开软件仓库、检查更新并按提示重启。
6. **帮助与反馈**：按用户问题链接使用说明和 GitHub Issues。
7. **开发与贡献**：链接开发文档，不在用户安装章节放 npm 命令。

功能介绍保持现有能力边界：内容写回 Markdown；业务组织遵循收件箱、项目、领域、资源与存档约定。不能把“任意知识库位置”写成“支持任意目录结构”，也不能宣称会自动启动、监控 Agent。

## 安装章节拟稿

以下拟稿以维护者已经发布完整 `tt-workbench.zip` 为前提。当前构建脚本尚未生成该 ZIP，正式 README 采用这些步骤前要补齐并验证发布附件。文件名是本提案建议，最终需与实际产物一致。

### 安装前

需要桌面版 Obsidian 1.8.7 或更新版本，以及一个已经创建的知识库。安装插件无需单独安装 Node.js；通过外部 Agent 使用命令行工具时，相关运行要求在各工具说明中列出。

### 方式一：下载并解压

适用于首次安装；已经安装过工作台，请使用“更新”章节。

1. 打开 [Releases](https://github.com/cookaihq/tt-workbench/releases)，在最新正式版本的附件中下载 `tt-workbench.zip`。页面自动生成的 `Source code` 是源码压缩包，不能用于本安装流程。
2. 退出 Obsidian，将压缩包中的整个 `tt-workbench` 文件夹放入知识库的 `.obsidian/plugins/` 目录。没有 `plugins` 文件夹时创建它。
3. 确认文件直接位于 `.obsidian/plugins/tt-workbench/manifest.json`、`.obsidian/plugins/tt-workbench/main.js`，并保留包内其余文件与子目录。
4. 重新打开 Obsidian，在“设置 → 第三方插件”中允许使用第三方插件，然后启用“tt 工作台”。
5. 点击左侧工作台图标，或在命令面板中搜索“tt 工作台”并执行“打开工作台”。

如果使用了自定义 Obsidian 配置目录，将上面的 `.obsidian` 换成自己的目录名。`.obsidian` 通常是隐藏文件夹，可在系统文件管理器中开启显示隐藏文件。

安装只添加插件及其内置资源。开始使用 Agent Skill、同步服务或个人规则时，再按相应说明设置。

### 方式二：让 Agent 帮忙安装

将下面的提示词复制给能够操作本机文件的 Agent，例如 Codex 或 Claude Code，并填写知识库的绝对路径。

```text
请帮我安装 Obsidian 插件 tt-workbench：
https://github.com/cookaihq/tt-workbench

知识库绝对路径：<填写我的知识库路径>
Obsidian 配置目录：.obsidian（如有自定义，请替换）

请先阅读仓库当前 README，按用户安装说明下载最新正式 Release 的完整插件包，并核验发布清单和包内文件。安装不需要克隆源码或构建；如果没有可用的完整发布包，请说明情况。

先核对上述知识库与配置目录；缺少必要信息时询问我，不要把当前工作目录当作知识库。首次安装只写入该配置目录下的 plugins/tt-workbench。若已有插件，按仓库的更新说明处理，保留设置与本机文件；遇到冲突先报告。

这次仅安装插件。不要修改业务笔记、同步配置、Skill 注册入口或个人 Agent 规则。完成后报告安装版本、位置和校验结果，并告诉我如何在 Obsidian 中启用和打开工作台。
```

这段提示词是本项目新增的安装入口设计，参考样本未提供同样的 Agent 提示词；不把它写成其他插件的既有做法。

## 更新章节拟稿

在工作台右上角点击版本号。首次使用时，将更新来源设为 `cookaihq/tt-workbench`，然后检查更新。有新版本时点击安装，完成后按提示重启 Obsidian。

使用内置更新保留插件设置。若提示安装文件已被修改或存在冲突，请查看[更新与恢复说明](../../docs/workbench/updates.md)，先处理报告的问题。

## 正式落地时需要补齐的事项

- **完整 ZIP**：当前 [build.mjs](../../scripts/workbench/build.mjs) 只生成 `dist/plugin/`、`dist/release.json` 与 `dist/tt-workbench.bundle.json.gz`。新增 ZIP 应包含顶层 `tt-workbench/` 文件夹、完整资源及 `release.json`，与现有更新包使用相同的文件清单，验证首次解压安装后仍可由内置更新器管理。
- **真实下载入口**：2026-10-29 实际访问公开 [Releases 页面](https://github.com/cookaihq/tt-workbench/releases)，页面显示 “There aren’t any releases here”。当前不能引导用户下载不存在的附件。ZIP 与现有两个更新附件应属于同一个版本；发布依据任务授权另行执行。
- **首次安装与更新**：手工解压指引限定首次安装。已有插件通过现有更新流程处理，避免直接覆盖造成文件混用或设置丢失。
- **文档分层**：把根 README 中的构建、发布、内部目录和迁仓记录整理到合适的开发文档，保留有用信息；同步修正 `apps/workbench/README.md` 中“当前开发检出没有远端”等过时文字。
- **截图**：采用真实界面，示例库中不出现个人笔记、账号、绝对私有路径或历史本机验收材料；截图不是本轮交付。
- **验证范围**：本轮只核对仓库文档和实现入口，不代表 ZIP 安装、线上 Release、跨设备或 Agent 实际安装已经验证。
