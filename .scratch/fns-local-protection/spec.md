# FNS 发布与本机文件排除解耦

2026-10-29 用户确认实施。目标是拆仓后的工作台能独立管理本机文件排除，并能读取旧规则、发布修正版。

- 保留知识库自己的 Git 传输分支、完整配置快照和历史格式。接收验证结构、指纹与历史；当前设备的路径要求只用于本机发布与应用检查。
- Git 对象中的 `config/fns-config/` 不构成本机目录要求。实际存在的旧设备目录继续保护，旧链接仍须显式迁回。保留已有排除，不自动清理其他设备可能仍使用的规则。
- 版本弹窗只提供软件版本与更新。FNS 页的本机检查提供文件排除状态、补齐入口；损坏发布记录不能阻止本机检查和修复。
- 保护清单覆盖当前运行目录、位置配置、插件及恢复目录、安装锁和插件启用列表；旧插件按实际存在情况展示。采用实例实际配置目录与运行位置。
- 补齐只修改本机排除规则，使用共同本机锁、暂停 FNS、备份、核对原文、写入和加载核验。不要求配置 Git 远端；已有 Git 仓库中的恢复材料仍须忽略。安装不隐式修改 FNS。
- 软件更新、运行位置、Skill 和 Agent 连接服务使用同一基础排除校验。没有 FNS 时本机检查显示不适用；启用但未加载时不能当作安全状态。

验收覆盖旧发布修复、真实损坏仍阻断、首次补齐、并发与失败恢复、Git 缺失/无远端、自定义目录、旧实例、无 FNS 和界面入口。软件测试与隔离安装不代表真实知识库或其他设备已更新。

实现与验收结果见[实施记录](implementation.md)。
