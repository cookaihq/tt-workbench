## Problem Statement

本人在一台电脑上调整 FNS 的同步目录、排除目录、排除文件类型或白名单后，希望将这些规则明确指定为权威版本，让其他电脑采用同一套规则，同时保留各自的账号、连接和设备设置。

现有每设备完整配置及本机符号链接只解决配置归属与保存位置；修改 A 的配置不会自动更新 B。完整配置通过 Git 传递，但尚无程序负责发布身份、差异比较、冲突处理及本机应用。FNS 对自身配置存在默认排除和白名单覆盖机制，不能笼统断言插件绝对无法同步自己的配置；本库已明确将设备配置目录排除出 FNS，使用 Git 传递。

设备接入、检查与配置应用流程可以由程序重复执行。本人希望在工作台完成这些操作，并准确知道“本机生成”“已推送”“已接收”“已写入”和“已应用”的区别。

## Solution

工作台左侧新增「系统」分组，入口为「FNS 配置同步」，采用已选定的 C「差异工作区」布局。页面顶部显示本机身份、最近核验的权威版本、本机应用记录及当前状态；按四组规则切换，主体并排显示本机与权威版本，标出新增、修改和删除。

正常流程：在 A 的 FNS 设置中修改规则 → 在工作台预览并发布本机规则 → 程序通过 Git 传递本机完整配置和发布记录 → 在 B 检查并接收 → 比较差异 → 明确应用到 B 自己的配置 → 程序恢复 FNS 并核验加载结果。A 不代写 B 的设备配置，B 的应用也不会自动成为一次新发布。

页面提供设备检查、本机接入、检查更新、发布和应用。首次缺少 FNS 或本机配置时说明应完成的安装和配置步骤；程序入口同时支持独立检查与设备归位，工作台不可用时也不依赖 Skill。保留 `tannt-sync-agent-config`，其整体去留待当前功能完成后另议。

## User Stories

1. 作为工作台使用者，我希望从「系统 → FNS 配置同步」进入功能，以便集中管理库的设备设置。
2. 作为当前设备使用者，我希望看到本机身份、链接归属和真实检查结果，以免改到其他设备的配置。
3. 作为首次接入者，我希望程序保留已有完整配置并完成归位、建链，以便继续使用自己的账号和设置。
4. 作为缺少必要依赖的使用者，我希望看到具体缺项与下一步，以便补齐 FNS、Git、授权或链接权限后继续。
5. 作为使用自定义 Obsidian 配置目录的人，我希望检查和写入使用实际目录，以免误读默认位置。
6. 作为规则维护者，我希望继续在 FNS 设置中修改规则，并在工作台确认发布，以便明确决定哪些内容成为权威版本。
7. 作为发布者，我希望四组规则的新增、修改和删除都参与发布，以便另一台设备完整采用这次规则变化。
8. 作为发布者，我希望发布记录明确来源和版本，以便追溯采用依据。
9. 作为发布者，我希望操作只传递本功能的配置和记录，以免夹带库中其他未提交或未推送内容。
10. 作为断网时的发布者，我希望保留待推送版本并重试同一次发布，以免重复生成版本或误以为已经传出。
11. 作为接收者，我希望检查更新先取得相互对应的来源配置和发布记录，以便比较实际收到的内容。
12. 作为接收者，我希望接收更新后仍由自己决定应用时机，以便先查看同步范围变化。
13. 作为接收者，我希望按四组规则并排查看增删差异，以便理解应用后的结果。
14. 作为有本机未发布修改的人，我希望先选择保留本机或采用权威版本，以免自己的修改被静默覆盖。
15. 作为两台设备都改过规则的人，我希望看到各自修改及待发布内容，以便明确选择一次新的发布。
16. 作为与另一设备同时发布的人，我希望较晚的操作重新核对远端版本，以免用过期依据覆盖新发布。
17. 作为应用者，我希望仅更新本机的四组共享规则，以便账号、连接信息和其他设置继续属于本机。
18. 作为应用者，我希望程序保存恢复材料、暂停 FNS、更新真实目标并恢复原启用状态，以便避免旧运行时覆盖新配置。
19. 作为应用者，我希望看到已写入、待加载、加载失败或已应用的实际状态，以便判断是否还需处理。
20. 作为使用者，我希望 FNS 配置同步开关关闭或只读模式等条件被明确提示，以免把规则写入误认为文件已经开始同步。
21. 作为使用者，我希望来源内容与发布指纹不符时停止应用，以免采用尚未发布的内容。
22. 作为使用者，我希望必要的设备配置和运行数据排除规则得到检查，以免配置应用破坏本库既定同步边界。
23. 作为重开工作台的使用者，我希望页面重新核验本机内容和应用记录，以免继续显示已过期的成功状态。
24. 作为没有历史应用记录的人，我希望内容相同时显示“内容一致”，以免程序捏造已经应用某版的历史。
25. 作为 macOS 和 Windows 使用者，我希望设备接入与配置应用分别在实际环境验收，以便了解每台机器已经验证的能力。
26. 作为工作台暂不可用时的使用者，我希望通过程序入口完成独立检查和恢复准备，以便排障不依赖专用 Skill。

## Implementation Decisions

以下包含已确认的产品行为，以及根据现有规则与代码核查落实的工程约束；未验证能力不作为现成实现引用。

### 界面与范围

- 固定采用 C 布局。保留现有业务导航，增加系统分组与新入口；真实页面不带示例设备切换、演示场景或伪造的版本、时间和检查结果。
- 本版负责检查、接入、比较、发布、接收与应用。规则编辑继续使用 FNS 设置；比较页面不新增通用设置编辑器。
- 每次发布和应用以约定的四字段为一个整体，传播删除，不做集合求并、不静默合并，也不逐条勾选形成另一个未标识版本。

| FNS 字段 | 共享内容 | 解析与比较要求 |
| --- | --- | --- |
| `configSyncOtherDirs` | 额外纳入的库内目录 | 遵守 FNS 的目录前缀语义，不作为任意正则或任意单文件规则 |
| `syncExcludeFolders` | 路径及目录排除规则 | 保留模式与大小写选项，按 FNS 实际匹配语义比较 |
| `syncExcludeExtensions` | 排除的文件类型 | 按 FNS 的扩展名匹配语义处理前导点号与大小写 |
| `syncExcludeWhitelist` | 排除白名单 | 保留其优先于排除规则的作用，显示覆盖后果 |

### 设备接入与本机运行

- 沿用 macOS、Windows 原生的稳定设备身份方案及每设备完整配置模型。插件入口为本机相对符号链接；按实际 Obsidian 配置目录定位，不能依主机名猜选配置。
- 复用现有设备检查、归位和建链能力。缺少本机配置时引导安装并完成本机设置；不制造空配置，不用另一台设备的配置或凭据初始化。
- 对目标已有不同内容、错设备或库外链接、断链、身份不可识别、未知目录链接及 Windows 权限失败保留现场。可重复执行已完成步骤，不以复制文件或硬链接替代约定的符号链接。
- 接入和写入的工作台适配层负责实际卸载运行中的 FNS、等待并核验状态，随后恢复原启用状态。现有迁移器只检查磁盘启用列表，不能将其单独作为运行时已停止的证明。
- 独立程序入口复用同一业务逻辑。不能控制或核验运行中的 FNS 时，仅执行无依赖的检查，并给出暂停步骤；不得绕过运行时前提写入。

### 发布、传输与权威记录

- 发布输入为本机完整设备配置，权威管理范围仅为四字段。完整配置允许进入 Git 的既有约定继续有效；应用不会复制来源设备的其他字段。页面、错误和日志不输出完整配置或凭据。
- 权威记录包含格式版本、不可混淆的发布身份、前序发布身份、展示版本、来源设备、发布时间、固定字段范围和规则指纹；值仍取自来源设备配置，不新增可独立编辑的共享规则正文。
- 展示版本便于阅读，真正的争用与重试判断使用发布身份及前序关系。时间戳或较大数字不能单独证明某次发布可覆盖另一版。
- 发布前重新读取本机内容、核对预览依据并检查远端版本。无权威版本时允许首次明确发布；已有版本时先取得并比较当前权威内容，再决定是否发布本机状态。
- Git 模块只发布本机完整配置与权威记录，只接收所需的 FNS 对象。当前分支、暂存区、无关工作区文件及其他未推送提交必须保持原状；不能用整库提交、自动 stash、整库 pull 或推送当前分支来实现本按钮。
- 实现采用与用户工作分支隔离的 FNS 传输引用，使用独立暂存上下文构建所需对象，按预期远端前序追加发布；不得将用户工作分支的祖先提交一并带入传输。接收读取发布对象，不把另一设备完整配置直接覆盖到本机入口。
- 独立传输引用解决“只传 FNS、不夹带其他库改动”；普通分支直接推送会携带其所有待推送提交，整库拉取还可能改写本机正在使用的配置，故不作为本功能传输方式。具体引用名由实现统一管理，缺少远端、授权或所需 Git 能力时报告缺项，不新建远端或修改鉴权方案。
- 发布前后核验来源与记录属于同一发布。实际读到的四字段与发布指纹不符时阻止应用并提示来源重新发布，不能静默采用未发布值或另找旧值绕过校验；不可获知的离线设备改动不冒充已检测。
- 本机生成、提交和推送各有结果。推送失败保留同一待推送发布；重试先核对远端是否已接受。远端已被其他发布推进时停止原推送，重新展示差异和选择，不强推、不按版本号自动抢占。
- 接收成功只证明取得了可核验内容，不应用规则。联网检查失败时显示最近收到的版本和检查时间，不能声明它是当前远端最新。

### 比较、应用与恢复

- 四字段在 FNS 中是字符串，可能保存 JSON 规则数组，也可能是旧换行格式。比较和指纹使用经校验的规范表示，写入保留 FNS 支持的字段类型；原型中的数组不是生产存储格式。
- 规范化覆盖空字符串与空数组等确定等价形式，保留有语义的模式、选项与顺序；非法格式、无效规则或不能解释的版本拒绝应用，不丢弃未知内容来强行解析。
- FNS 会把自身插件目录的内部排除项分存在本机存储，并在加载、保存时规范化设置。共享规则取自磁盘设备配置；运行时核验使用同一语义模型并保留本机内部项，不能把完整运行时对象直接发布或仅按序列化文本判定失败。
- 设备配置目录与本机运行数据必须继续被 FNS 排除，白名单不能覆盖这些边界。发布或应用的候选内容不满足既有规则时，展示具体问题并阻止操作；不能应用后悄悄补回规则却声称与权威版本一致。
- 本机未发布修改通过本机基线和当前规则判断。应用前展示替换后果，允许稍后处理、保留本机并准备发布、明确使用权威版本；保留本机不等于自动发布，选择权威也不覆盖其他字段。
- 应用固定到本次预览的发布身份和本机原文。提交前重读；任一依据变化即停止并更新比较。页面不能用旧确认套用新收到的版本。
- 保存修改前内容与恢复记录，暂停 FNS，通过符号链接解析并写入本机真实目标，只替换四字段，读回文件、核对链接归属、恢复原启用状态并核验 FNS 实际加载。其他设备配置保持原样。
- `configSyncEnabled` 等开关、只读模式和连接状态属于设备自身设置，不随四字段应用改变。显示这些条件对实际同步的影响；必要条件未满足时，已写入或已加载记录仍须明确标出未生效条件，不能宣布实际文件同步通过。
- 操作失败、中断、恢复原启用状态失败与核验失败分别保留进度和恢复材料。恢复只针对本次本机变更且先核对后续修改，不自动覆盖后来产生的新内容；此操作不是跨文件、跨进程或跨设备事务。
- 本机回执记录设备身份、发布身份、基线指纹、写入与加载结果。重开页面重新核验；只有内容相同但没有回执时显示“内容一致”，应用后再修改时显示“本机有修改”。本机不能推断另一设备已经应用，也不增加远程应用监控。

### 模块与交付

- 建立一个供工作台与独立程序共同使用的配置同步服务，暴露检查、预览、发布、接收、应用和重试等完整业务操作；UI 负责展示与用户选择，不另写一份同步逻辑。
- 复用现有设备配置模块、配置解析与文件核对能力。Git 传输和 Obsidian 运行时控制作为服务的边界适配，不把命令执行与插件内部对象散落到视图代码。
- 运行回执、恢复材料与缓存沿用本机运行数据位置，保持 Git 忽略与 FNS 排除，不作为另一份可编辑规则源。
- 正式实现需同步维护相关 FNS 规则、接入说明、工作台安装模块清单和使用说明，并从正式源码安装验证。安装副本不是编辑源；Skill 保留且不能成为新功能运行前提。

## Testing Decisions

- 主要测试边界是配置同步服务的公开业务操作：用两套设备环境、本地 Git 测试远端、真实文件与符号链接运行发布到应用的流程，检查可观察结果；不以私有函数调用次数、视图内部状态或原型演示通过替代功能验收。
- 沿用现有设备配置测试的真实文件夹具、独立设备身份、字段保留及链接检查方式；参考工作台 Issue 测试的版本核对、可重试操作和冲突保留方式。复用已有边界，只为 Git 与运行时控制提供必要适配。
- 自动化验收覆盖如下行为，测试凭据只使用明确的合成值：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 首次发布与两台设备顺序操作 | 来源和发布记录一致；B 接收后未应用，确认应用后只变更自己的四字段 |
| 各组新增、修改、删除与清空 | B 获得发布的完整结果，不以集合求并复活删除内容 |
| 其他本机设置和设备配置 | 非受管字段、凭据与其他设备文件保持原值，链接继续指向本机 |
| 无关未提交、已暂存、已提交但未推送内容 | 发布与接收不改当前分支、索引及无关文件，也不把无关提交传出 |
| 网络失败与结果不明后重试 | 发布身份不变；远端已接收时识别成功，不重复创建版本 |
| 两台设备基于同一前序发布 | 仅一个推进远端；另一个重新比较，无强推或静默覆盖 |
| 发布内容缺失、来源变化、指纹不符 | 阻止应用并说明实际不一致项，不采用未发布内容 |
| 本机未发布修改与远端新版本并存 | 展示选择；无确认不覆盖，保留本机不自动发布 |
| 预览后本机文件或发布依据变化 | 陈旧操作停止，原内容和恢复输入可核对 |
| 缺少配置、错误链接、身份或权限失败 | 不借用别机配置，不覆盖不同目标，报告可接续步骤 |
| 原来禁用 FNS、加载失败、配置同步开关关闭 | 保持原启用意图，分别报告文件、运行时与生效条件，不伪造成功 |
| FNS 自身保存规范化与内部排除项 | 四字段语义一致、内部项保留、链接未被普通文件替换 |
| 排除目录保护被删除或白名单覆盖 | 发布及应用被阻断，未静默改变待应用版本 |
| 重开页面、回执缺失或应用后再修改 | 分别显示已核验状态、内容一致或本机有修改，不编造历史 |
| 写入/重载中断与恢复 | 已完成步骤、未完成步骤和恢复依据明确，不覆盖后续外部修改 |

- 界面验收从「系统 → FNS 配置同步」真实入口进行，检查 C 布局、四组差异、键盘操作、窄窗口、确认与失败反馈；按钮状态依据真实检查结果。
- 运行时验收分别核对磁盘文件、相对链接、FNS 重载后的实际值以及再次从 FNS 设置保存后的链接。文件写入通过不能代替加载通过。
- macOS、Windows 原生及真实双机验收分别记录环境与结果。用受控测试内容验证规则变化对应的实际纳入/排除效果；单机夹具和内存演示不能代替真实跨机结果，未到场的环境明确记为待验收。
- 原 to-spec 阶段仅收敛规格与术语；后续 implement 阶段分别执行隔离夹具和 macOS 实机验证。原型证据只证明显示与演示交互，不能替代实现证据。

## Out of Scope

- 退役整个 `tannt-sync-agent-config`、重做其他 Agent 配置同步或系统菜单中的其他功能。
- 自动安装 Obsidian、FNS、Git、自动登录、复制其他设备凭据，或代替用户修改系统链接权限。
- 额外共享 FNS 的账号、连接、开关、只读模式等字段，以及把完整来源配置覆盖到本机。
- 自动发布本机修改、后台自动应用、定时推送、按时间自动选胜者、自动合并冲突或跨机代写配置。
- 通用 Git 客户端、整库提交/拉取/推送、调整远端或凭证政策。
- 任意历史版本切换界面、远程设备在线监控与应用回执汇总、移动端和 Linux/WSL 支持。
- 将四组规则拆成第二份可独立编辑的共享配置，或把本版比较页扩展为 FNS 设置编辑器。
