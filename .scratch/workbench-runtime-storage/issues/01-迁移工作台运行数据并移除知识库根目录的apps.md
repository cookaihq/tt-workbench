# 迁移工作台运行数据并移除知识库根目录的apps

## 用户要求与目标

2026-10-29，用户要求将“需要工作台项目调整运行数据路径”的需求登记到工作台项目，并另开会话处理。前提是工作台源码已经独立迁仓，目标知识库不应继续留下沿用源码布局的 apps/workbench/data/。

完成后，工作台、独立 CLI 和 Skill 配套命令统一使用明确的实例运行目录；已有记录可恢复地迁移；实际知识库根目录的 apps 在确认只剩本功能旧数据且已经清空后移除，后续受影响操作不再重新创建它。

## 已确认边界

- 运行数据属于各知识库或开发记录所在项目的实例，不能移进公共软件仓库作为共享状态。
- 新路径尚未由用户指定。接收会话先检查现有路径解析、安装更新和隔离机制，再确定一致的新位置；支持自定义 Obsidian 配置目录及无 Obsidian 进程的独立命令。
- 保留锁、请求回执、失败恢复及历史记录的必要职责，不能用删除全部记录代替路径迁移。历史记录与正在使用的状态分别处理，发现未知文件或并发修改时保留并报告。
- 个人全局规则仍归用户选择的正式源管理；云盘目标、Agent 配置清单和飞书同步历史不属于本次运行目录迁移。
- 插件安装与后续配置操作继续分离；安装或只读检查不能隐式修改 FNS 配置、迁移数据或注册 Skill。
- 按设备规则备份，先核验目标与文件内容，再清理旧位置；迁移失败和重试不能覆盖新数据。

## 调查与实施范围

1. 找全生产代码中的旧路径使用方：笔记文件操作与 Skill 配套 CLI、开发 Issue、FNS 本机配置迁移、FNS 规则同步及排除范围调整、Agent bridge；另检查最新 Skill 安装管理状态、插件安装更新和测试夹具。
2. 建立共用的运行目录解析方式，明确目标知识库与 developmentRoot 不同的情况下各类状态归属，避免在软件工作目录或用户目录间混用。
3. 为旧实例提供受控迁移：区分运行锁与历史记录；核对源/目标冲突、链接、失败中断和重复执行，记录前后版本与恢复位置。
4. 配套维护 Git 忽略、FNS 排除检查、配置提示、Skill/CLI 文档和适用规则。具体设备配置变更保持在本次迁移必要范围内，不扩大为整体同步设置重写。
5. 实施与验证在工作台项目推进；针对已授权目标知识库完成安装、迁移与实际入口验收。不要在知识库重新创建开发脚本或测试环境。
