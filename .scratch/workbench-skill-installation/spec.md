## 已确认的首版范围

在工作台左侧“系统”下新增 **Skill 安装**，管理当前知识库、当前电脑的内置 Skill。选择 Codex 或 Claude Code 后，可安装单项或全部未安装项。首版管理随工作台分发的五项，不扩展到第三方市场、用户级全局安装、远程设备或任意 GitHub Skill。

| 展示名称 | Skill 标识 | 主要用途与安装后事项 |
| --- | --- | --- |
| 保存新内容 | `tannt-capture` | 在 Agent 中保存新输入，明确内容与来源 |
| 更新已有笔记 | `tannt-update-note` | 明确目标笔记，进行追加、整理或授权归档 |
| 管理网盘文件 | `tannt-cloud-files` | 在需要使用时，按 Skill 流程单独配置网盘账号 |
| 检查 Agent 配置 | `tannt-sync-agent-config` | 按当前库自己的配置清单检查，差异确认后应用 |
| 整理 Agent 规则 | `tannt-organize-agent-rules` | 在 Agent 规则页核对来源和入口，整理及接入另行确认 |

清单以 `skills/manifest.jsonc` 为准。界面展示中文用途和实际 Skill 名称；原型中的五条示例不作为正式实现硬编码清单的依据。

### 安装到哪里

- 页面显示当前库名和绝对路径，目标来自正在使用的 Obsidian 库。
- Codex 的项目发现入口在 `<库>/.agents/skills/<名称>`；Claude Code 在 `<库>/.claude/skills/<名称>`。
- 入口引用当前库已安装插件的 `skills/<名称>`，支持自定义 Obsidian 配置目录；默认 `.obsidian` 仅为原型示例。
- 页面中的“已安装”指本机发现入口正确且资源可读，不推断宿主已加载、正在运行或外部服务已配置。
- 页面不安装或启动 Agent 宿主。用户在库根新开宿主会话，核对宿主列出的 Skill，再进行实际调用。

### 状态和动作

| 状态 | 判断依据 | 页面动作 |
| --- | --- | --- |
| 未安装 | 发现入口不存在，内置资源有效 | 安装 |
| 已安装 | 入口指向本插件的对应资源且可读取 | 查看使用说明；移除安装 |
| 入口损坏 | 已证实属于工作台的入口失效，正确资源仍可用 | 单独修复；不能按名称相同猜测归属 |
| 同名冲突 | 普通文件、目录，或不属于本工作台的链接占用入口 | 展示位置与已知来源，保留原内容；处理后重新检查 |
| 检查失败 | 权限、父目录、资源缺失或其他原因导致无法判断 | 展示原因并重新检查，禁用依赖该结果的写操作 |

首次打开和重新检查只读取。安装前重新核对资源和入口，避免用陈旧检查结果覆盖他人改动。实际错误按受影响范围展示；无法判断不等同于未安装。

单项安装不触发配置或调用 Skill。安装全部针对当前所选宿主的未安装项；已有项保留。若存在损坏、冲突或不可读取项，先列出可安装项及跳过原因，用户可选择安装其余项。损坏入口通过明确的“修复入口”处理，不隐含在普通批量安装中。

安装结果逐项显示成功、失败、跳过及具体原因。操作失败后重新检查实际状态，不把整个批次显示为成功；并发修改时保留新内容，不自动覆盖。原型重点演示部分冲突，不模拟操作系统写权限或所有中途错误。

移除安装前显示宿主、Skill 和入口位置；只删除仍被确认属于工作台的所选入口。内置资源、笔记、账号配置、其他宿主入口及全局规则保留。移除失败或入口归属变化时停止并显示原因。

### 安装后与更新

成功后提供“使用说明”：从库根新开宿主会话、核对 Skill、明确目标和内容后调用。网盘账号、共享配置和全局规则接入分别指引到已有流程或页面，不自动执行。

Skill 资源版本随工作台插件版本更新，首版不单独选择或升级某个 Skill。普通插件更新保持已有入口，更新后重新检查；新增加的 Skill 仍由用户在页面中选择安装。插件卸载导致入口失效时，应显示资源缺失的实际原因，不能声称修复成功；重新安装插件后可再次检查。

注册入口属于设备本地接入，需遵守现有 Git/FNS 排除及每设备注册约定；正式实现验收须覆盖新建隐藏发现目录时的适用规则。原型没有创建真实发现目录。

## 现有能力与实施缺口

原型确认时的 `scripts/agent-skills/install.mjs` 支持显式库路径、所选宿主全清单注册、只读检查、已核实旧源迁移；会预检整批并拒绝同名冲突。当时没有逐项状态 API、按 Skill 选择、部分冲突时安装其余项、一般入口修复或卸载 API。本原型提出的这些行为由确认后的正式实现设计共享安装模块，不能直接把 CLI 的整批结果包装成页面逐项结果。

正式实施还需将入口检查、预检和写入共用到 CLI/UI；验证所有权、真实路径、并发变更、失败恢复及自定义配置目录。不以直接读取 SKILL.md 代替新宿主会话的标准发现验收。

原型页面、静态资源与本地预览服务留在 `prototype/skill-installation` 分支；`docs/prototypes/` 不进入插件分发包。正式实现使用独立分支，验证通过后更新已安装工作台。

## 后续验收重点

- 新库安装插件后，Skill 入口仍为空；只有点击 Skill 安装后才建立对应入口。
- 单项／批量安装的宿主、知识库和结果准确；另一个宿主和其他库不受影响。
- 已安装、缺失、损坏、冲突和无法检查分别展示；普通内容、陌生链接及并发改动保留。
- 修复及移除只操作可验证归属的入口，失败展示与实际状态一致。
- 插件更新后可继续发现已有 Skill；新 Skill 不自动安装；移除入口不删除内容和规则。
- 两宿主的新会话能标准发现并进行适用的真实调用；文件可读、注册成功与实际行为分别留证。
- 检查 Windows 原生与实际支持的平台行为；未经验证的平台明确标记，不扩大承诺。
