## 目标与改动

用户要求修正根 `AGENTS.md` 未完整列出 `docs/agents/` 文档及其使用场景的问题。

- `AGENTS.md`：保留常驻要求，按开发协作、目标库与配置操作、历史回查列出全部 13 份文档；写明工作开始前的读取要求、各场景条件、路径基准和索引维护要求。12 份现行文档与 1 份已退役文档分别接入。
- `CLAUDE.md`：保留 `@AGENTS.md` 导入。原有 Issue、分诊与代码探索的领域文档入口已移入共同索引；正文仍由原文档维护。
- `docs/agents/fns-hidden-item-check.md`：补充目标库规则读取入口，区分采用该流程的目标库与软件开发仓库；创建前读流程并保存基线，自动检查仍以实际新建隐藏项为条件。

沿用 ADR 0001、ADR 0005 的项目内正文归属与目标库自治要求。原有 Skill 的工具引用和目标库规则读取流程继续使用；未改变业务模型、字段、CLI、模板、安装器或程序读写行为。本次无需修改目标库正文或迁移笔记，未指定或操作真实目标库。

保留本轮开始前及并发会话的修改，包括 Skill 安装 UI 已实施说明、FNS 隐藏项命令中 `check --vault` 的顺序修正；本记录仅描述上述入口改动。

## 静态核对

- 枚举 `docs/agents/*.md` 与根索引比较：13/13 均有直接引用，无遗漏、失效条目或重复条目。
- 根 `AGENTS.md` 的 15 个 Markdown 文件链接均能在本机解析；隐藏项说明新增的 `package-layout.md#目标库规则读取` 文件及标题锚点存在。
- `CLAUDE.md` 的有效内容为 `@AGENTS.md`，共同触发条件不再分别维护。
- `git diff --check -- AGENTS.md CLAUDE.md docs/agents/fns-hidden-item-check.md` 通过。

以下为入口与正文的人工场景核对，不是宿主行为测试：

| 场景 | 核对结果 |
| --- | --- |
| 只读检查本仓 Git | 先读 Git 说明；目标库操作条件未触发 |
| 探索代码 | 共同入口要求读取领域文档，保留原 Claude 入口的读取时机 |
| 跟踪或关闭开发 Issue | Issue 流程与分诊／关闭规则可从共同入口发现；凭证要求继续沿 Issue 正文读取 Git 说明 |
| 执行配置检查 Skill | 先取目标库规则，再按配置检查流程读取实例清单及适用软件说明；未自动启用可选集成 |

| 修改已有隐藏项、在已有隐藏目录中新建普通文件，或仅在源码仓库工作 | 保留原跳过条件；源码目录不被推断为目标库 |
| 回查旧 `.env` 同步方案 | 读取退役文档了解历史；当前设置、迁移及旧补丁退役进入现行网盘目标同步流程 |

## 验证边界与路径

本轮验证覆盖本机正文、索引覆盖、文件路径、所新增锚点及静态场景关系。未运行新宿主会话加载或实际 Agent 行为验证，未核对其他设备同步到达。仅修改指令及说明，未运行应用测试、构建或插件安装。

项目入口以工作台根为基准：`AGENTS.md`、`CLAUDE.md`、`docs/agents/` 和 `docs/rules/` 保持相对位置；场景文档中的相对 Markdown 链接以该文档所在目录解析。其他设备也须保持这些相对路径与目录关系，绝对项目根可以不同。目标库仍使用自身实际入口及其声明的路径基准。
