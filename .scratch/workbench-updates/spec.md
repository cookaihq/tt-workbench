# 工作台代码改由 Git 更新

Status: ready-for-agent

用户要求工作台代码不随 FNS 同步，由 Git 管理；希望在工作台右上角看到版本号，并收到新版本提示。当前仓库为私有 CNB 仓库，两台设备分别使用自身 Git 凭证。

## 实施范围

- 正式源码 `apps/workbench/`，安装副本 `.obsidian/plugins/tannt-workbench/`。首次实现为 `0.19.0`；最终与逐条 FNS 规则说明合并交付 `0.20.0`，安装脚本产生完整安装包校验清单。
- 右上角运行版本、启动/六小时/手动 Git 检查、新版本提示、明确点击后安装、重启生效。
- 使用现有 `origin/main` 中已提交推送的完整安装包；沿用本机 Git 凭证，不要求公开仓库，不引入发布服务器。不自动 pull 整库，不写笔记、索引或开发源码。
- 固定检查得到的提交，完整下载并校验后替换目录。保留旧版与本机数据，拒绝覆盖本机代码修改。进程中断留下恢复记录；不宣称目录切换是跨进程事务。
- 工作台源码、依赖、相关脚本与插件目录加入本机 FNS 排除。每台分别配置或明确发布/接收 FNS 规则；应用旧规则不能静默撤销既有代码排除。

## 当前证据

实施前本机为 `0.18.0`，源码与插件副本均已被 Git 跟踪；FNS 仅排除工作台运行数据及整个 `.obsidian`，尚未排除源码和共享模块。当前分支 `main`、上游 `origin/main`，现有 Git 凭证成功读取真实私有远端。实现、本机安装及 macOS 初验见[验收记录](../../local-evidence/.scratch/workbench-updates/verification/README.md)，当时远端仍是 `0.18.0`。随后与逐条 FNS 规则说明合并为 `0.20.0`；用户已授权将全部待提交内容一同提交推送，发布前联合检查见[发布验收](../../local-evidence/.scratch/workbench-updates/verification/release.md)。另一台设备及 Windows 的未验收范围保持独立。
