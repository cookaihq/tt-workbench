# 既有规则取舍与外部引用重组

2026-10-29 用户要求：处理电脑上已有的 `AGENTS.md` 及其外部引用时，先评估规则是否合理，提出保留、丢弃和更新建议；外部文件按主指令与场景指令重组，场景正文统一进入规则仓库的指定目录。向用户汇总建议新建的场景文件、建议丢弃和更新的规则及各自原因。

## 实施范围

规则整理由 [tt-organize-agent-rules](../../skills/tt-organize-agent-rules/SKILL.md) 承担，与用户截图一致；`tt-sync-agent-config` 继续负责配置检查与同步。用户首条消息中的 Skill 名称与截图、现有职责不同，已向用户说明并询问，按截图及现有分工实施。

- 把本机主文件和外部引用视为待评估来源，按条款比较当前要求、实际环境及正式规则；保留现场与建议保留规则分别表达。
- 外部引用先解析实际来源并读取，再按条款评估和重组；文件边界不决定场景边界，避免整份复制或只换路径。
- 主指令放在 `<规则源>/AGENTS.md`，全局场景正文统一在 `<规则源>/scenarios-agent-instructions/`。优先复用已有场景，必要外部工具实现引用仍可保留，个人正文不进入工作台软件仓库。
- 方案及最终交付均覆盖新增场景、丢弃、更新、保留四类及理由，空类别明确写“无”，证据不足另列待澄清；执行结果与建议分别标记。
- 原有授权、局部入口修复及加载验证边界继续适用；本次仅改 Skill 源码及说明，不迁移真实个人规则或安装插件。

## 静态流程审阅

下列是本次文档审阅采用的输入与预期行为，不是新宿主会话执行或真实迁移证据：

| 输入情形 | 对照修改后的流程 |
| --- | --- |
| 一个外部文件混有常驻要求及两个不同触发的流程 | 逐条评估；有效常驻内容进入主文件，按场景分别组织，不保留原文件边界作为分类依据 |
| 不同外部文件包含同主题要求，正式源已有对应场景 | 合并到已有场景，作为更新说明原文、差异和理由；无需新建时新增类别写“无” |
| 本机规则含有效要求、重复条款及有证据表明失效的旧做法 | 分别提出保留、去重／丢弃或更新，解释行为影响；既有文件存在本身不作为保留理由 |
| 外部规则路径不可读，其他来源可读 | 不可读部分列待澄清，继续独立分析；未知内容不自动保留到新源或丢弃 |
| 用户只批准部分建议，入口切换仍会停用未决条款 | 保留原入口，执行独立获准部分；不会以备份代替继续加载 |
| 主入口已正确，仅场景目录入口失效 | 只进入场景入口修复分支；没有具体内容问题时不重新拆分正文 |
| 仅要求整理方案 | 交付四类汇总及理由、具体文件和条款去向；执行和加载阶段不报告完成 |
