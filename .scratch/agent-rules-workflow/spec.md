# 本机全局 Agent 规则整理 Skill：tannt-organize-agent-rules

本规格承接已确认的需求和已完成的工作台页面，供后续实现独立 Skill 及剥离原配置同步职责。2026-10-28 按 `mattpocock-skills:to-spec` 整理并发布至本库本地 Markdown issue tracker；同日用户回复“按推荐验收”，确认本文的测试边界。`ready-for-agent` 表示规格可进入实施，不表示 Skill 已实现或本机规则已迁移。

## Problem Statement

当前电脑的全局 Agent 规则可能以普通文件、旧链接或分散场景保存，混合常驻要求、按需流程、设备条件和含糊表述。用户需要先弄清每条规则的含义及去向，再按 tannt 约定整理并接入；仅运行链接安装器不能完成这些判断。

主规则入口与场景目录入口相互独立，因此主文件已接入、场景目录仍缺失或指向错误位置的情况确实可能发生。用户需要只修复有问题的部分，保留已正确接入的主文件。

原 `tannt-sync-agent-config` 仍承担规则检查与迁移，混合了整机配置和规则整理职责。工作台已提供只读浏览、入口状态与调用提示词，但提示的新 Skill 尚未实现，整个流程缺少可实际执行的独立入口。

## Solution

提供项目级 Skill `tannt-organize-agent-rules`，在 Agent 会话中完成当前电脑已有全局规则的来源识别、歧义澄清、拆分方案和用户确认。沿用术语表中的“全局主指令”和“全局场景指令”：按是否需要在所有会话中加载划分，不按篇幅划分。

用户确认具体方案后，Skill 继续写入正式源，建立或修复本机符号链接，并分别核验文件、路径和实际宿主加载。默认只处理执行 Skill 的当前 Agent；用户明确指定时才扩展宿主范围。单次请求仅允许检查或方案时，停在该范围。

| 本机事实 | 用户得到的流程 |
| --- | --- |
| 主文件未直接链接到当前项目正式源 | 读取已有规则及必要场景，澄清含义，确认整理及入口方案后落地 |
| 主文件已正确链接，场景入口缺失、失效或目标不符 | 保留正确的主文件正文与链接，核查旧场景及依赖，确认后仅补齐或修复相关入口并验证按需读取 |
| 两项入口正确，但存在覆盖文件或读取问题 | 核查具体遮蔽或读取问题，按实际需要提出处置方案 |
| 无法确定来源或入口状态 | 报告未知及原因，先核查，保留已有内容 |
| 入口符合约定且内容清楚完整 | 如实报告，无需制造新的拆分或迁移 |

工作台继续承担既有只读职责；用户复制提示词进入 Agent 会话，操作后回页面刷新。原配置同步 Skill 完全退出 Agent 规则管理，不再保留“检查后转交”流程。

## Implementation Decisions

1. **范围与结构。** 新建独立项目级 Skill，支持目标为 Windows 原生、macOS 上的 Codex 和 Claude Code。Skill 编排会话和获准操作，引用当前项目的正式规则及维护流程，不复制另一套规则正文。项目路径与用户配置目录按实际环境解析；当前执行宿主不明时先查明。读取范围限于相关规则、引用和必要加载依赖。

2. **发现与调用。** 将新 Skill 纳入活动清单和既有项目级安装、发现机制，维护对应根入口和接入说明。支持按名称调用及页面提供的两类提示词。提示词携带的项目、目标宿主、入口及观察结果是待核查输入；用户明确选择其他宿主时按该选择确定范围。安装与检查始终显式限定宿主，不能依赖工具默认处理所有宿主。复制提示词不构成内容或入口变更批准。

3. **来源与接入判断。** 分别记录主入口、共用场景入口、覆盖文件、真实源、内容版本与引用关系。普通文件即使同文也不是符号链接接入；直接链接、间接链接、错误目标、断链、缺失和不可读分别处理。核对实际自定义配置目录，工具不支持时报告限制，不改用默认目录得出成功。单项失败保留其他独立检查结果；未知来源保持原状。

4. **条款分析与澄清。** 按原条款保留来源，分析适用对象、条件、动作与结果；重点处理指代不明、冲突、重复、旧例外和设备条件。能查明的事实先自行核实；确需用户决定时给出原文、歧义、可选解释、推荐及影响，按依赖分轮确认并记录已确认解释。未回复不算批准。未获准改变的要求保留原义。

5. **拆分与去向。** 全局主指令保留跨项目常驻要求和明确的场景读取触发；其他全局条款进入适用场景。场景入口写明条件、读取时机、可解析路径和执行要求，验证可从库外使用。优先复用已有适用正文；同义条款不重复追加，冲突不按时间或文件位置自动裁决。项目专属内容标注归属，跨项目写入须有对应授权，项目规则部署不成为本 Skill 的通用职责。

6. **可审阅方案与授权。** 在改动前展示每条原文及拟写正文、保留或退出行为、目标主文件或场景、触发及引用、拟新增或替换的文件和链接、影响范围、备份与恢复办法、验证方式。区分结构拆分和行为变化、共享正文修改和本机入口动作。共享正文可能随同步影响其他设备，共用场景入口可能影响另一宿主；按必要依赖核查，不扩大成另一宿主的完整审计。用户可部分确认；若切换整份入口会停用未决条款，保留旧入口及必要场景，继续无此依赖的已批准动作。既有授权沿用，新增或变化的动作另行确认。

7. **场景入口修复分支。** 主文件已正确直连时，保留其正文和链接，仅核查场景目录、必要旧内容及读取依赖；确认处置方案后补齐或修复场景链接。只有发现确需合并或澄清的具体条款时才追加内容方案，不能以修复入口为由重新拆分主文件。两项入口正确但被覆盖或无法读取时，转向对应问题；全部符合时报告事实而不生成无必要改动。
8. **获准后的写入。** 执行前重读旧文件、链接及目标正式源，与获准版本核对；变化只阻止受影响动作，保留拟写方案并重新澄清相关差异。先核验恢复材料，再写正式源并验证条款去向与引用；确认入口切换不会停用未决要求后，按方案处理旧入口和覆盖文件，再建立直接链接。处理链接时保留其原目标文件；单宿主操作保留另一宿主可能依赖的旧共享中间入口。复用既有安装器的适用能力，语义合并、普通文件归档和加载验证由 Skill 流程负责。Windows 使用原生符号链接，权限失败如实报告，不改用复制、硬链接或 WSL 冒充目标接入。

9. **备份、失败与重试。** 按当前本机规则选择不参与同步、不会被宿主加载的备份位置，保存受影响原文件、必要引用、原路径、类型、目标及版本，读回验证并告知用户。记录跨文件操作的已完成步骤和恢复依据，不宣称全体原子迁移。失败时核查现场；仅恢复本次可安全恢复的内容，外部已有修改时保留并报告。安装器自身的链接回滚不能代替正文和普通文件恢复；本机恢复不等于跨设备撤销。重试先核对结果，避免重复合并和归档。

10. **结果与完成条件。** 分别报告来源已读取、含义待澄清、方案待确认、候选已生成、正式源已写入、入口已接入和实际加载已验证；未执行或无法验证的阶段明确列出。候选文件不等于正式生效，备份不等于旧规则仍在加载。从源库之外，用目标宿主新会话或加载诊断验证主指令，并核验场景触发后实际读取正确正文、适用要求可用、退出条款未从旧入口重新加载。记录宿主版本、系统、工作目录、证据及限制；链接正确不能证明旧会话已刷新，也不能证明其他设备已同步或加载。

11. **完整剥离旧流程。** 从原配置同步 Skill、执行流程及配置检查清单 A02／A03／A04 移除以 Agent 规则为管理对象的检查、分析、迁移、入口修复和加载验证；不保留检查后转交或隐式调用新 Skill。清单的共享源可用性检查只覆盖执行自身配置工作所需资料，不借此恢复全局规则或项目规则的管理。正常读取、遵守适用规则继续保留。同步更新根入口、全局说明、活动 Skill 清单、安装接入说明和页面的能力说明；只将旧规则整理职责指向新入口，通用规则维护场景仍承接日常新增与编辑。

12. **保留关联功能边界。** 原 Skill 的 FNS、工作台、飞书、网盘、运行时和 Skill 发现职责及其当前授权继续生效。实施时按最新正式规则核对；现行 FNS 使用插件目录内的普通运行配置，旧自动外移建链流程已经退出，不能随本次拆分恢复。工作台沿用已确认的系统分组、A 布局、只读浏览、状态、提示词和刷新；Skill 过程记录不成为页面的数据源，不新增分析结果数据库或审批状态，也不扩展业务笔记读写接口。

## Testing Decisions

2026-10-28 用户已确认推荐边界：以**在真实 Agent 会话中调用已安装 Skill，并针对隔离的样例规则完成流程**为主要验收入口。核对可观察的会话行为、批准范围、文件与符号链接结果及实际加载证据；同一边界下回归调用原 Skill，验证规则管理已退出。直接读取源码或仅检查文件存在，不代替标准发现与真实调用。

好的测试使用真实文件系统和符号链接，断言用户能观察的结果与未获准内容保持情况，不固定模型措辞、内部函数调用顺序或条款数量。可用含义明确的样例要求核对拆分后仍保留条件与动作，再用含糊、冲突样例检验确认边界。测试对话中的预设答复只用于隔离样例，不作为真实规则迁移授权。

优先复用现有 Skill 发现、链接安装／检查和文件系统测试入口；只在既有边界补充必要的确定性验证，不新建语义分析服务或另一套测试数据存储。测试宿主通过其支持的隔离配置或独立测试环境运行；临时用户目录、正式源样例和故障目标均位于隔离范围。无法可靠隔离或无法启动相应宿主时，记录该项未验证，不改动真实全局入口来制造测试状态。

现有工作台规则读取测试已采用隔离用户目录、真实链接和权限失败模拟，可复用其夹具方式；业务阅读边界测试提供规则目录与库外文件不进入业务接口的回归依据。页面两种提示词作为调用输入验证，页面不会因此增加分析、写入或执行 Skill 的能力。

| T09 | 正文或链接在批准后被外部修改 | 执行前发现版本变化，停止受影响动作并保留外部修改，不用旧方案覆盖 |
| T10 | 备份失败、写入失败、建链权限不足、中断及部分完成 | 逐项报告；备份未核验不替换旧入口，恢复不覆盖外部新内容，不宣称整项成功 |
| T11 | 部分完成后重试；完成后再次调用 | 从实际状态接续，无重复合并或归档；完整且清楚的既有结构无无必要改动 |
| T12 | 从源库外启动新会话并触发场景 | 实际加载正式主指令，按触发读取目标场景；tannt 项目专属指令不进入其他项目；文本、路径和行为证据分开记录 |
| T13 | 只有链接检查成功、旧会话未刷新或另一设备不可验证 | 明确加载／同步未验证，不将入口成功推广为所有会话和设备成功 |
| T14 | 页面两类提示词及已过期的状态描述 | Skill 重新核查后选择对应流程；场景修复不强制重拆主文件；复制和刷新不批准操作 |
| T15 | 改造后调用原配置同步 Skill | 不出现规则检查、整理、迁移、加载验证或自动转交；仍正常读取适用规则并检查原有其他配置 |
| T16 | 原配置职责与文档引用回归 | FNS 等功能保持现行规则和授权；新 Skill 名称、清单、根入口、安装说明一致；生效说明不再把规则管理交给旧 Skill |

按实际变化测试新 Skill、受影响的发现与安装接口，以及旧 Skill 的职责边界。若共享安装器或页面接口实际发生修改，再运行对应已有测试；不为纯说明修改重跑整套应用测试。

Windows 原生／macOS × Codex／Claude Code 的发现、调用、链接及加载证据分别记录；某一组合通过不代表其他组合通过。实施记录必须区分源码完成、标准发现、真实执行和各设备验证，缺项保留为明确后续工作，不能据 Skill 已创建关闭尚未完成的实机验收。

## Out of Scope

- 新 Skill 不承担一般性的日常新增、任意改写规则、项目规则部署、整机配置同步、凭据或命令执行权限设置。
- 默认不检查或迁移另一宿主，不替其他设备创建入口，不扩大到私人库或无关用户资料。
- 不重做已确认的页面原型及布局，不在页面加入编辑、差异、整理建议、澄清问答、审批、自动修复或 Agent 启动功能。
- 不建立另一份规则正文、分析结果数据库或配置状态服务；不因文件同步就宣称其他设备已加载。
